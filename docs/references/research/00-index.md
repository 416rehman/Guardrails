## h01-conference-talks-agents: 2026 conference work on securing AI agents (DEF CON 34, Black Hat USA 2026, RSAC, USENIX Security, and others)

Full brief: [h01-conference-talks-agents.md](h01-conference-talks-agents.md)

The 2026 programmes are now in hand: DEF CON 34 (6-9 Aug, about 150 agent-related sessions, read through a schedule export because defcon.org still resets), Black Hat USA (briefings 5-6 Aug, via a slide index and a vendor round-up because blackhat.com returns 403), AI Village (34 posters), BSides Las Vegas, [un]prompted I, OBTS v9 and four academic venues. Six results matter most. (1) Novee broke the Claude Code, Gemini CLI and Codex CLI sandboxes through design seams, not kernel bugs: allow rules evaluated after safety checks, an allowlist enforced at registration only, a Landlock backend that dropped read-only exceptions, shared /proc and /tmp, and a trusted parent process. The Gemini issue (GHSA-wpqr-6v78-jr5g, CVSS 10.0, fixed 24 Apr 2026) fired before any prompt in headless CI. (2) Tenet's GhostJacking made WAF logs and unauthenticated Sentry events into instructions that agents later read through vendor MCP servers, with one agent infecting another; there is no single fix. (3) Wiz's OffGuard chained a LiteLLM MCP auth bypass (CVE-2026-59822, in KEV) with root execution through custom-code guardrails (CVE-2026-59821); 9.6% of exposed instances accepted the default key. (4) LLM guards leak: BeyondTrust used Copilot Studio's guard as an oracle, and "Block Means Yes" shows a correct guard leaks through its verdict pattern. (5) Propagation is measured: MCParasite spread across shared channels in 21 of 26 tests; Pillar showed one CI agent waking a privileged one. (6) Zenity's PleaseFix hit all five agentic browsers, with vendors split between patching and "intended". Skills supply-chain work (MalSkill, Promptware EOD) shows composition and memory persistence defeat per-file scanning. Open-source defensive tools appeared at the same events: AgentsLeak (MIT), GolemHalt/Sondera Cedar hooks (MIT), HoneyMCP, Praxis, MCP X-Ray and AgentHound (all Apache-2.0), which narrows some whitespace claimed in brief 22. Two named leads were corrected: "Agentic ProbLLMs" is a 39C3 talk from December 2025, and the worm poster is "MCParasite". Not obtained: Black Hat Asia and Europe session lists, LABScon, BlueHat, CAMLIS, fwd:cloudsec, RSAC session content, and fix status for several items. The brief runs to about 5,500 words, over the 3,500 target, because of the per-item tables.

**Design implications**

- Ship a sandbox conformance suite: for every declared boundary on every backend (Landlock, bubblewrap, Seatbelt, Windows), prove enforcement at execution time, including pre-task inputs, headless runs, shared /proc and /tmp, and parent-trusts-child paths.
- MCP gateway must label tool results by source trust; telemetry-class connectors (WAF logs, error trackers, tickets, issues) are untrusted and cannot drive state-changing calls without step-up.
- Harden our own LLM consumers first: console assistant, triage agents and detonation workers read attacker-written fields. Quote fields, isolate workers per tenant, no credentials, no egress.
- Treat our LLM/MCP gateway as Tier-1: no default keys, fail closed without auth, never execute user-supplied guardrail code in-process, bind each credential to its destination, validate egress targets.
- Judge hygiene: return a verdict code only (no reasoning), rate-limit feedback, detect verdict probing, keep deterministic policy beneath, and refuse when the judge cannot see everything the action depends on.
- Build a defensive cross-agent graph (configs, credentials, MCP servers, instruction files, shared channels) and detect new attack paths, bot-to-bot triggers, and content written by one agent then acted on by another.
- Skills and MCP supply chain: baseline and diff tool descriptions after approval, analyse skill composition rather than single files, flag run-time remote fetches, detonate at install.
- Browser sensor should mark agent-driven sessions and gate purchases, password-manager access and repository collaborator changes across the five agentic browsers.
- Offer credential-layer enforcement for cloud identities (out-of-process token broker with blast-radius policy) and detect role-assignment writes made by agent identities.
- Make approval quality measurable: show argument provenance in approval prompts, track approval latency, and use predict-then-approve for irreversible actions.

## h02-conference-talks-sensors: 2025-2026 conference and practitioner work on endpoint sensor technology, read for defensive sensor design

Full brief: [h02-conference-talks-sensors.md](h02-conference-talks-sensors.md)

WESP is still an undocumented preview on 10 November 2026: binaries in Insider builds, no SDK, no date. Elastic's 26 October teardown finds no path for a user-mode client to return a block verdict, and no network coverage. About a dozen of roughly 100 MVI members take part under NDA (Bitdefender, CrowdStrike, ESET, SentinelOne, Sophos, Trellix, Trend Micro, WithSecure). Plan Windows as driverless plus optional driver through 2027.

The most consequential new fact: Windows Dev Drive detaches every minifilter outside the antivirus altitude range by default, including Defender for Endpoint's own EDR filter, unless an administrator allow-lists it. Microsoft tells developers to put repositories and package caches there, so a file sensor is blind where coding agents work.

User-mode ETW can be spoofed and flooded by low-privileged processes (Black Hat USA 2025), and call stacks can reportedly be fabricated (LACUNA Chain, June 2026, unvalidated). ESET counted almost 90 EDR killers in March 2026, with a growing driverless class that blocks sensor traffic or freezes sensor processes.

Apple now documents the macOS 27 descendants client: AUTH and NOTIFY over the caller's subtree, no root, no TCC, entitlement still required. Descendants cannot exec setuid binaries unless the caller is root, and a denied exec emits no EXEC event. macOS 27 also adds Apple-native execution allow/deny through declarative device management. No dedicated WWDC26 Endpoint Security session was found. Objective by the Sea v9 runs 18-20 November, so only abstracts exist; several concern AI agents, including an inline local judge fed by hooks plus Endpoint Security.

On Linux, LSFMM+BPF 2026 established that BPF LSM programs unload when the loader's descriptors close and that their maps are writable from user space; no fix was agreed. Signed BPF programs are in mainline since 6.18. fanotify gained a permission-event watchdog, but the mmap page-fault pre-content hook was reverted.

CrowdStrike's post-outage baseline is crash-loop detection into a safe mode, ring-based content distribution, host-group schedules and content pinning.

No credible public measurement of sensor overhead on coding-agent or build workloads exists; Tetragon's 1.68% on a kernel build is the only primary figure. That gap is ours to fill.

**Design implications**

- Report enforcement state as a measured fact: every heartbeat states per hook whether we are attached, enforcing or monitor-only, plus event-loss counters. Tetragon shipped a bug that silently downgraded enforcement to monitoring.
- Treat policy and detection content as code: ring-based rollout, customer pinning, host-group schedules, and automatic crash-loop fallback to a safe mode that keeps discovery and audit but drops inline enforcement.
- Ship Windows driverless first and put WESP behind the same internal interface as the optional driver. No roadmap item may depend on a WESP date or on a user-mode blocking path existing.
- Detect Dev Drive volumes and their filter allow-list on day one, raise a coverage finding, and source agent file evidence from hooks and gateways instead of a minifilter.
- Define evidence tiers: kernel-origin and gateway facts outrank user-mode ETW, call stacks and agent-reported hook data. No verdict may rest only on a spoofable source.
- Make Linux enforcement survive loader death: pin links and programs, deny map and program access to other tasks, keep an in-kernel default, and use signed light skeletons on 6.18 and later.
- Build the macOS supervisor on the descendants client with an explicit deadline-miss mode per policy, synthesize denied-exec audit records, document the setuid limitation, and test alongside declarative execution rules and XProtect.
- Model lineage as a graph with IPC edges (XPC, Apple Events, launchd, COM, D-Bus) and artifact edges (package, extension, project revision that selected the code), not only fork and exec.
- Publish and release-gate our own overhead benchmark: kernel build, npm ci, cargo build and a scripted agent loop with thousands of short processes, sensor on and off.
- Add out-of-band tamper detection: server-side heartbeat-gap alerts, detection of local rules that block sensor egress, and a local spool that proves the gap afterwards.

## h03-incumbent-vendor-docs: Search-backed teardown of incumbent EDR, XDR, SASE and identity vendors' agent-security products (the ones the first round could not read)

Full brief: [h03-incumbent-vendor-docs.md](h03-incumbent-vendor-docs.md)

Incumbents moved fast between June and November 2026, but almost none publish mechanisms. Palo Alto's Cortex XDR 6.x release notes (November 2026) confirm Agentic Endpoint Security with hook capture for coding agents, OS-level prompt interception through the XDR sensor for apps without hooks, and a Cortex Targeted Sensor that runs AES beside a third-party EDR. That directly contests our "enhance the EDR you already run" position. SentinelOne launched Singularity Agentic Detection and Response on 2026-10-21 in early access; there is no public technical documentation and its site blocked fetches. Netskope has the clearest endpoint discovery doc: a periodic signature scan, Windows x64 and macOS only, eight named agents, nothing in VMs or containers, nothing outside its signature file. Zscaler ships AI Endpoint Security (mechanism and OS unstated) plus an MIT repo of AI Guard hooks for Claude Code, Codex, Cursor, Cline and Windsurf whose install guide overwrites the user's existing hooks and uses a 30-second cloud timeout. Check Point Workforce AI Security combines a browser extension, desktop proxy, IDE integrations and a script-based discovery, Windows and macOS only (read from an unofficial copy of the guide). Identity vendors do not build sensors: Okta discovers local agents and MCP servers through CrowdStrike Falcon; Jamf pushes vendor-native managed configuration by DDM; 1Password brokers credentials outside the model context. Trend Micro opened a draft portable hook specification (agent-hook-unity) with a cross-handler deny guarantee; it is unaccepted and has no adoption. Datadog is the only incumbent documenting limits and overload behaviour (fails open at 700 requests per minute). Koi, Noma, Knostic and Operant gate their docs behind sign-in; Cisco, Wiz and Zenity docs were unreadable. No agent product surfaced for Sophos, Bitdefender, ESET, Tanium, Fortinet, Orca or Iru, which is weak evidence of absence. Table stakes: Windows and macOS inventory of agents, MCP servers and extensions; hook verdicts for Claude Code, Cursor and Codex; an MCP gateway; Allow, Ask, Block; SaaS agent connectors; session audit. Undocumented by anyone: behaviour-based discovery of bespoke agents, WSL and container coverage, local offline verdicts, hook coexistence, published fail modes, public pricing. All 18 searches were used.

**Design implications**

- Build the hook installer as a broker that preserves foreign hook entries, never replaces the hooks key, and alerts when our entries are removed. Zscaler's published installer clobbers existing hooks, so this will happen in the field.
- Offer an explicit targeted-sensor build that does only agent discovery and enforcement beside any EDR, with tested coexistence notes for CrowdStrike, SentinelOne, Defender and Cortex. Palo Alto now sells this mode.
- Map our hook event model to Trend Micro's agent-hook-unity draft (18 events; gate, observe, partial, unavailable claims) and publish per-agent capability claims in that vocabulary, without taking a dependency on the unaccepted spec.
- Make discovery list-independent: combine signatures with behaviour (LLM API egress, tool-loop process trees, MCP handshakes) and surface unknown agents. Cover WSL, VMs and containers, which Netskope's documentation explicitly excludes.
- Decide hook verdicts locally with a budget of tens of milliseconds and no cloud call on the hot path. Publish a per-connector fail-mode table that includes rate-limit and timeout behaviour, which only Datadog and DefenseClaw document.
- Export local-agent and MCP inventory in a form identity platforms can ingest, modelled on Okta's CrowdStrike Falcon integration, so we become the endpoint source for Okta-style agent registries.
- Deliver policy through MDM-managed configuration (Jamf Blueprints and DDM, Intune, plain files) and read back settings Jamf AI Governance already enforces, so two writers do not fight over one managed-settings location.
- Do not require a local TLS proxy. If network inspection is enabled, detect existing Netskope, Zscaler, Prompt Security and Check Point interceptors and chain or stand down, because proxy variables and PAC settings are single-valued.
- Match the buyer-facing vocabulary incumbents share: Allow, Ask, Block, Detect, Redact; per-MCP-server and per-tool rules; session-centric audit with agent-run reconstruction; MITRE ATLAS mapping on shipped policy templates.
- Keep documentation, limits and prices public and ungated. Four specialists gate their docs and no incumbent publishes a price, so openness is a cheap, visible differentiator.

## 06-market-runtime: Commercial market map: runtime security for AI agents

Full brief: [06-market-runtime.md](06-market-runtime.md)

By November 2026 the commercial market has converged on three mechanisms: native agent hooks (pre-tool allow/deny/ask), MCP or LLM gateways, and endpoint config-file discovery pushed through an existing EDR or MDM. Hooks are the shared weak foundation: per-agent, opt-in, usually fail-open by the vendors' own docs, limited to Claude Code, Cursor and Codex, and themselves an attack vector. The high end is now kernel sensor plus hook correlation, held only by EDR-class vendors (CrowdStrike, Microsoft, Palo Alto Cortex XDR One from 19 Oct, Sysdig AI Defense from 4 Nov). Proxy-based endpoint inspection is fragile: a hands-on review of SentinelOne's Prompt Security agent found a local mitmproxy bypassed by unsetting an environment variable, broken signed Bedrock requests, and full prompts stored in clear. Network gateways cannot see stdio MCP or a harness's built-in tools; Cloudflare says this itself. Runtime blocking is OS-skewed (Microsoft Windows-only preview, Jamf macOS-only, Linux desktop rare, WSL uncovered). Bespoke in-house agents and agent-versus-human attribution under shared credentials are essentially unserved; discovery is a named-product list. Platform-native checkpoints (Anthropic inference hooks, Claude Code Compliance API) remove the endpoint agent but only for one vendor's enterprise plan. At least 17 relevant acquisitions in 2025-2026 make vendor continuity the buyer's main structural risk; Pillar was acquired by Vanta today and Astrix standalone sales ended in June. Public pricing is nearly absent (Knostic at $15 per user per month is the only list price found) and no independent efficacy testing exists. Analysts use Gartner's "guardian agents" and Forrester's "agent control plane"; CSA's AARM spec (R1-R9, five verdicts) is the emerging conformance checklist. Open-source hook layers (Numbat, Prempti, Sage, all Apache-2.0) lack a console, multi-tenancy, kernel correlation and tamper protection, which is the whitespace. Caveat: the shared search budget ran out, so Wiz, Orca, Datadog, Trend, Sophos, Fortinet, MDR vendors and several startups were not verified.

**Design implications**

- Never rely on hooks alone: pair hook semantics with an OS sensor, correlate by process tree and time, and alert when a hook goes silent while the agent process keeps acting.
- Make failure mode an explicit per-policy setting (fail open, fail closed, fail to ask) and report hook and sensor health centrally, including missing or stopped agents in a device inventory.
- Adopt AARM R1-R9 as the conformance target and use its five decisions (ALLOW, DENY, MODIFY, STEP_UP, DEFER) as the verdict enum, with tamper-evident identity-bound receipts.
- Default to local decisions and metadata-only export with opt-in, on-device-redacted content capture; full-prompt logging is a liability competitors have created for themselves.
- Build generic agent discovery from behaviour (process calling an inference endpoint or local model runtime and spawning shells or writing files), not only config-path signatures, to cover bespoke agents.
- Ship a local MCP proxy for stdio servers and hook coverage for harness built-in tools, since network and remote gateways are blind to both.
- Treat Linux desktop, WSL, signed binaries and tamper protection on all three operating systems as launch requirements; these are documented gaps in shipping commercial products.
- Evaluate reusing Numbat's NDJSON event schema and CEL sequence rules, Falco rule syntax and Elastic's open detection rules, and expose a headless embeddable sensor and policy engine for EDR vendors.

**Surprises**

- Sysdig, a cloud-workload vendor, shipped a desktop kernel sensor for AI agents on macOS and Windows on 4 Nov 2026, and donated an Apache-2.0 hook layer (Prempti) to the Falco project.
- Perplexity publishes an Apache-2.0 endpoint agent-visibility tool (Numbat) covering 26 agent surfaces with forensic reconstruction of sessions that predate its install.
- Anthropic now offers server-side tool-call validation (inference hooks) and Compliance API endpoints for local Claude Code sessions, so some enforcement needs no endpoint software at all.
- The only public list price found in the whole category is Knostic at $15 per user per month; no MDR vendor offering for agent activity was found.
- Pillar, author of the most detailed endpoint comparison, was acquired by compliance vendor Vanta on the research date, with runtime enforcement deferred to summer 2027.

**Verifier's corrections**

Web search budget was exhausted; checks used direct primary fetches and gh. Do not assume hooks always fail open: Prempti is fail-closed by default, Claude Code has onFailure "block" (2.1.295, SDK in 2.1.317), Anthropic inference hooks can block on failure. Blocking is not limited to three agents (Numbat, Sage, Microsoft cover more). Cloudflare MCP detection is not header-only, and portals can disable individual tools. The "single choke point" warning is vendor commentary, not Gartner. Vanta/Pillar is a signed agreement, not closed. Sage rules are DRL 1.1, not Apache-2.0. ## 07-market-identity: Commercial market map: agent identity, access and secrets

Full brief: [07-market-identity.md](07-market-identity.md)

The agent identity market has converged on one architecture: register the agent in a directory with a human sponsor, give it no long-lived secret, broker short-lived audience-scoped tokens through token exchange, and enforce at an MCP gateway. Okta, Microsoft, AWS, Google, HashiCorp, Descope, Keycard and Aembit all ship variants.

ID-JAG (Cross App Access) is the winning cross-vendor standard. MCP made it a stable extension dated 2026-07-28; the IETF draft is still at -06. It governs the connection, not individual tool calls, so a gateway or in-agent hook is still required.

Every commercial product assumes the agent is a registered OAuth client. None gives an identity to an unregistered local process. Entra Agent ID does not support interactive or public-client flows, and BeyondTrust's endpoint product says agents run as the signed-in user with no identity of their own. That is our main whitespace, along with Linux endpoints (BeyondTrust is Windows and macOS only) and stdio MCP servers (gateways cover remote HTTP only).

Coding agents still keep credentials in plaintext files, and Claude Code can mint a one-year token. Anthropic and OpenAI now offer workload identity federation, and Claude Code managed settings can block static keys, so a local broker can remove model API keys entirely.

Credential-injecting egress proxies (Infisical Agent Vault is open source) are the practical way to keep secrets out of the model, but they rely on bearer session tokens and unenforced network isolation.

Delegation semantics differ by vendor. Vault's rule, the intersection of user policy and an agent ceiling, is the cleanest but is Enterprise-only.

Consolidation is nearly complete: Astrix to Cisco, SGNL to CrowdStrike, CyberArk to Palo Alto, Entro to SailPoint. Agent controls at Microsoft, Okta and Vault sit behind top-tier licences.

The search budget ran out, so Akeyless, Doppler, Veza, Saviynt, Ping, SailPoint, Silverfort, Oso and Clutch are not verified from primary sources.

**Design implications**

- Derive agent identity from attested process facts (binary signer, parent chain, user, device, repo, session) and emit SPIFFE-style IDs, so unregistered agents get an identity no commercial product provides.
- Build a Rust endpoint credential broker that acts as apiKeyHelper, git credential helper, AWS credential_process and SSH agent shim, releasing short-lived scoped credentials only to attested agent processes.
- Ship an egress injection proxy bound to OS-sensor process identity or DPoP, not bearer session tokens, with enforced network isolation and placeholder substitution for stdio MCP server environments.
- Implement on-behalf-of as the intersection of the human's policy and an agent ceiling, attenuating per sub-agent hop, encoded as nested act claims plus RAR-style authorization_details.
- Act as an ID-JAG requesting client and accept ID-JAGs at our gateway; correlate Entra, Okta, AWS and Google agent objects to observed processes instead of building another IdP.
- Reuse SPIRE, OpenBao, agentgateway, Cedar or Cerbos and SpiceDB behind stable interfaces; keep secrets in the customer's store so our broker holds leases, not a hosted token vault.
- Configure Anthropic and OpenAI workload identity federation against our issuer and push Claude Code managed settings (forceLoginMethod, allowedProviders) to remove static model keys from endpoints.
- Make policies fail closed on missing attributes, require a principal as sponsor, and add policy replay against recorded activity plus CAEP events for revocation.

**Surprises**

- AWS's own documentation describes AgentCore Identity's delegation as an "impersonation flow", not true on-behalf-of delegation with a distinct actor.
- CyberArk is now "Idira" under Palo Alto Networks; cyberark.com redirects there and the old Secure AI Agents docs URL returns 404.
- Teleport's Agentic Identity Framework docs mark most identity, access and security components "in-progress" and the scheduling layer "not started".
- Cloudflare MCP portals do not enforce Access features such as independent MFA and purpose justification for portal-authorised servers, and do not support stdio servers.
- 1Password's runtime scoped credential issuance for agents was still "later this year" at the March 2026 Unified Access launch; its Cursor hook is a no-op on Windows.

**Verifier's corrections**

Eight of ten claims held; two need correcting. (8) Google mints a new agent principal only on delete-and-replace, not every redeploy; DPoP applies only across Agent Gateway. (10) Do not treat Infisical Agent Vault as an open-source base: the MIT standalone repo is marked no longer recommended, and the platform version's server code is under the Infisical Enterprise License. Also: Entra agent Conditional Access needs Agent 365 plus Entra P1/M365 E3 (or E7). Claude Code blocks apiKeyHelper when forceLoginMethod/forceLoginOrgUUID is set, so the broker-as-apiKeyHelper and managed-login-policy recommendations conflict. agentgateway and ToolHive do handle stdio MCP servers. ## 08-oss-agent-security: Open-source landscape: agent security, sandboxes, firewalls and MCP gateways

Full brief: [08-oss-agent-security.md](08-oss-agent-security.md)

Surveyed about 85 open-source agent-security repos via the GitHub API (READMEs and architecture docs read directly) plus Claude Code, BeyondTrust and Agent 365 docs. Web search was unavailable (shared budget exhausted), so there is no news or blog corroboration.

The field splits into five layers that no open project spans: hook policy engines, OS sandboxes, egress/MCP/LLM proxies, observe-only telemetry, and scanners. The nearest open AIDR analogues are uber/ADR (discovery, sensor, benchmark and detector; prevention withheld) and perplexityai/numbat (hooks, OTLP and transcripts into one CEL engine; blocking opt-in). Neither has a console, fleet, identity or kernel sensor.

Fleet management, per-agent identity and team consoles are consistently paywalled or source-available (Pipelock ELv2, HOL Guard Cloud, Snyk Evo, AgentWard and Cordum BSL, Archestra dual licence). A fully open multi-tenant console is unoccupied.

No project delivers kernel enforcement on all three OSes. agentsh is closest, but macOS is alpha and its Windows minifilter is unsigned. Every sandbox only confines processes it launches; none attaches to an already-running or unregistered agent.

Windows options improved in 2026: microsoft/mxc (MIT, Rust SDK) exposes a native Windows 11 process container with learning mode, and Anthropic's srt and Codex sandbox on Windows using a dedicated user or restricted tokens, ACLs and WFP.

OWASP's Agent Control Standard v0.1.x is a JSON-RPC wire format for hooks; Microsoft's governance toolkit now uses it. Its reference Guardian is unauthenticated and fails open. Claude Code hooks also fail open unless `onFailure: "block"` is set.

Policy languages are fragmented across Rego, Cedar, CEL, Falco YAML, Starlark and TOML. Useful Rust components: cedar, Dogwood, OpenAPPA, nono, mxc-sdk, Sondera hook adapters, Prempti, httpjail, agentgateway and Codex sandbox crates.

Dead or stale seeds: Daytona (closed June 2026), Invariant, Lasso, Leash, cupcake, mcp-guardian, mcp-context-protector, MCP Defender.

**Design implications**

- Build one Rust endpoint daemon fusing hooks, proxy and OS telemetry, plus a fully open multi-tenant console. Each source alone is commoditised; the combination and the console are the unoccupied ground.
- Adopt OWASP ACS as the hook wire format, but ship HMAC-authenticated, fail-closed Guardian behaviour. Keep per-agent shims thin, using Sondera's and numbat's per-agent capability matrices as the truth table.
- Use Cedar in Rust as the core policy language and compile outward to native controls: Claude managed settings and hooks, Codex execpolicy rules, Gemini TOML. Enforcement then survives when our hook is skipped.
- Delegate sandboxing: mxc-sdk on Windows, the nono crate on Linux and macOS, and drive srt or Codex's built-in sandbox where present. Do not write another Seatbelt or Landlock profile generator.
- Reconcile hook events against OS telemetry by process ancestry and timing. Agent-descended activity with no matching tool call is both a detection and a hook-tamper signal, and gives agent-versus-human attribution.
- Do discovery in three passes: catalog fingerprints and config parsing (port uber/ADR Discovery), transcript parsers (ADR Sensor, numbat), then behavioural classification of arbitrary processes by LLM-API traffic, which no open project does.
- Emit signed, hash-chained decision receipts that state what the boundary could not see, and export OCSF and OTLP. Add sequence rules using Dogwood-style temporal operators and OpenAPPA-style taint labels.
- Publish hook shims, event schema and policy evaluator as separately versioned crates with a C ABI so EDR vendors can embed them without our daemon. Vendor small dependencies; project churn is high.

**Surprises**

- Uber and Perplexity both open-sourced endpoint agent detection tooling in 2026 (uber/ADR, perplexityai/numbat), yet neither includes a console, fleet management or default-on prevention.
- Windows now has an OS-native agent containment path: microsoft/mxc's processcontainer, already wired into Codex (mxc-sandbox crate) and NVIDIA OpenShell. Anthropic's srt also gained Windows support via a local user plus WFP.
- A hook wire standard exists (OWASP ACS) and Microsoft's governance toolkit adopted it, but its own reference implementation is unauthenticated and fails open by default.
- Daytona, at 71k stars, went closed-source in June 2026, and six of the listed seed projects are stale, archived or acquired within roughly a year.
- Hook-based guards openly describe themselves as cooperative rather than security boundaries (Prempti, Rampart, Obot Sentry), and Claude Code's own hooks proceed on hook error or timeout unless configured otherwise.

**Verifier's corrections**

Eight of ten claims held; web search was unavailable, so checks used GitHub API and vendor docs only. Do not get these wrong: (1) Microsoft AGT's "ACS" is Agent Control Specification (responsibleai/agent-control-spec), not the OWASP Agent Control Standard; AGT does not speak the OWASP wire protocol. (2) OWASP ACS has two reference stacks: the AGT Guardian is unauthenticated and fail-open, but adapters/ already has HMAC and default-deny. (3) MXC telemetry is opt-in on the published 1.0.0 contract; Required only on 1.1.0-alpha, Windows only. ## 09-oss-detectors: Open detection components: injection classifiers, safety models, secrets and PII, command analysis

Full brief: [09-oss-detectors.md](09-oss-detectors.md)

No small prompt-injection classifier is both strong and cleanly licensed. Prompt Guard 2 is the best small model, but its Llama 4 licence is not OSI and the download is manually gated. The Apache-2.0 alternative, Protect AI's DeBERTa v2, was archived as unmaintained in July 2026 along with LLM Guard. PIGuard (MIT) is the best permissive interim choice. Independent scores sit far below model cards: about 79% on PINT, and 72-82% recall at roughly 1% false positives. No authoritative CPU latency figures exist for any of them.

Adaptive attackers beat every detector. "The Attacker Moves Second" reports over 90% attack success against Protect AI, PromptGuard and Model Armor, and 71% against PIGuard; stacking detectors did not help. Anthropic's October 2026 red-team found Claude Code Auto Mode and Codex Guardian missed over 55% of attacks. GuardFall bypassed the shell guards in 10 of 11 open-source coding agents, and tree-sitter parsing alone did not help.

Reusable parts with clean licences:
- Secrets: Kingfisher (Apache-2.0, Rust crates) with the Betterleaks rule catalog (MIT).
- PII: Presidio patterns (MIT), small GLiNER-PII ONNX models (Apache-2.0), OpenAI privacy-filter (Apache-2.0).
- Gateway judges: gpt-oss-safeguard-20b and Granite Guardian 4.1 8B (both Apache-2.0).
- Runtime: ort for Rust, with candle as a pure-Rust fallback.

Licence traps to keep out of the default bundle: Llama 4, Gemma, Elastic (Sentinel), NVIDIA Open Model, Semgrep Rules License, AGPL (TruffleHog, tirith), and destructive_command_guard's rider excluding OpenAI and Anthropic.

We must build ourselves: a shell and PowerShell canonicalising risk analyser, an Apache-licensed multilingual tool-output injection classifier, provenance and taint tracking with keyed transcript framing, and signed detector packs. ML verdicts should feed risk scoring; blocking should rest on deterministic policy.

Web search quota ran out mid-run, so Semgrep, CyberSecEval and promptfoo facts come from repository contents only.

**Design implications**

- Treat ML classifier verdicts as risk-score signals, not sole block decisions; put hard guarantees in deterministic layers (command policy, taint and provenance, egress and capability control).
- Build our own Rust shell and PowerShell analyser that canonicalises before matching (quote removal, $IFS and variable expansion, recursive substitution, pipe-to-interpreter, heredocs) and fails closed; publish the GuardFall A-E corpus as a conformance suite.
- Train and ship our own Apache-2.0 injection classifier on MIT/Apache bases, aimed at coding-agent tool outputs, multilingual, calibrated, with NotInject-style hard negatives. Use PIGuard (MIT) as the interim default.
- Define a detector plug-in ABI with licence metadata so non-OSI weights (Prompt Guard 2, Llama Guard 4, Sentinel, ShieldGemma) are operator-installed opt-ins, never bundled or silently downloaded.
- Embed Kingfisher crates with the Betterleaks rule catalog for secrets, offline only on endpoints with live validation disabled; avoid TruffleHog (AGPL) and write our own Opengrep-compatible rules, since Semgrep's rules cannot be redistributed.
- Standardise inference on ort with pinned versions and per-model fp32-versus-int8 accuracy gates; DeBERTa int8 can lose substantial accuracy. Keep candle as the pure-Rust and WASM fallback.
- Monitor tool results and in-workspace file writes, and wrap transcript turns in keyed, unguessable frames with escaping before any LLM judge sees them; these were the cheap fixes Anthropic validated.

## 10-oss-sensor-blocks: Open-source building blocks for the endpoint sensor

Full brief: [10-oss-sensor-blocks.md](10-oss-sensor-blocks.md)

- Ship source adapters for built-in Sysmon, Santa, osquery, Falco, Tetragon, KubeArmor and Wazuh; on hosts that have them, add attribution and policy instead of duplicate hooks.
- Write our own Rust OpAMP client from the spec protobufs using only Beta features; use opamp-go server side; deliver updates through TUF (tough) plus sigstore.
- Start the Apple Endpoint Security entitlement request and Microsoft Hardware Developer Program registration immediately; both are external lead-time items that block macOS and Windows enforcement.
- Give AI coding agents an explicit do-not-read list (GPL, Elastic License, Comodo CASL repositories) and evaluate building on Rustinel's stack before starting clean.

## 11-oss-platform-blocks: Open-source building blocks for the server platform

Full brief: [11-oss-platform-blocks.md](11-oss-platform-blocks.md)

Recommend a Rust server built as one binary with role flags behind five ports (relational, event store, bus, workflow journal, blobs), with exactly two adapters each: SQLite + DuckDB/DuckLake + in-process bus for the laptop, PostgreSQL + ClickHouse + NATS JetStream for HA and SaaS. Licence traps are widespread. Not OSI: Restate, SurrealDB, Memgraph, Redpanda, Pathway (BSL), FalkorDB and Inngest (SSPL), Flipt v2 (Fair Core), CockroachDB, TimescaleDB tsl/. ## 12-windows: Windows: observing and blocking agent activity (WESP, drivers, no-driver options)

Full brief: [12-windows.md](12-windows.md)

WESP is not a route for us in 2026. It is still preview-only and undocumented (wesp.sys minifilter plus espclient.dll, first public in Insider build 29661, Sept 2026). Production clients need a WESP://Permission token attribute and Antimalware-PPL, which needs an ELAM driver, which needs Microsoft Virus Initiative membership. MVI requires an organisation with a commercially available real-time anti-malware product, NDA, yearly test-lab certification and MVI 3.0 safe-deployment practices. WESP also shows no network events and no confirmed synchronous user-mode verdict.

Our own kernel driver is feasible but needs a legal entity: EV certificate, Entra tenant, legal signatory and Hardware Developer Program agreements. Azure Artifact Signing is user-mode only and issues no EV certs. Cross-signed driver trust ended April 2026. Microsoft now labels attestation signing "for testing scenarios", excludes it on Server per docs, and has promised more certification tests. Microsoft suspended WireGuard's and VeraCrypt's signing accounts in April 2026, so account loss is a real risk. windows-drivers-rs 0.5.0 still says not for production, though Portmaster ships a Rust WFP driver via Partner Center.

Much works with no driver: ETW kernel providers, built-in Sysmon (optional feature on Windows 11 and Server 2025, telemetry only), user-mode WFP filters keyed on app path, user SID or AppContainer SID, an AMSI provider, restricted tokens, job objects, ProjFS, and the WSL plug-in API (signed DLL plus one registry value). OpenAI Codex already ships a driverless Windows sandbox on these primitives. The gap is pre-action blocking of agents that run as the human user.

Windows-native agent features (Agent Workspace with per-agent accounts in a separate session, the on-device registry odr.exe, an MCP proxy) are all still preview, with no documented vendor hook; third-party coding agents do not use them.

Recommendation: driverless Phase 0; optional minimal attestation-signed driver in Phase 1; WHCP/HLK in Phase 2; WESP and PPL through EDR-vendor embedding in Phase 3. Web search quota ran out late, so several 2026 status points are flagged unverified in the brief.

**Design implications**

- Define one sensor abstraction with interchangeable back ends (ETW, built-in Sysmon, own driver, WESP, host EDR feed); tag every event with provenance and tamper-resistance grade so policy never depends on a specific back end.
- Ship Phase 0 driverless: Rust SYSTEM service, ETW plus Sysmon ingestion, user-mode WFP sublayer with SID-keyed filters, AMSI provider, ODR inventory; make in-agent hooks and MCP/LLM gateways the primary pre-action enforcement.
- Build a launcher that runs agents or their tool subprocesses under a dedicated sandbox user or AppContainer in a job object; that SID drives WFP rules, deny-read ACLs and agent-versus-human attribution.
- Keep the Phase 1 driver optional, tiny and HVCI-compatible on x64 and ARM64: process-create veto, minifilter on configured secret paths, WFP redirect-to-gateway, ObRegisterCallbacks; all policy in user mode, fail-open on timeout.
- Plan for a legal entity early: EV certificate and Hardware Developer Program account gate any driver; add a second account admin and a recovery plan, and budget WHCP/HLK for Server and durability.
- Reach WESP and PPL through embedding: expose the core as a C-ABI library an EDR vendor can load inside its own Antimalware-PPL process and feed from its WESP queue.
- Cover WSL2, Docker Desktop and Dev Containers with a minimal signed WSL plug-in that starts an eBPF sensor in the utility VM root namespace, including ARM64 and custom kernels.
- Copy ODR's static tool-list pinning in our MCP gateway on all platforms, and model our driver protocol on WESP's in-kernel rules plus user-mode queues so a WESP adapter stays thin.

**Surprises**

- Microsoft now documents attestation signing as for testing scenarios only; the common open-source route to a loadable driver has no stated future.
- WESP shows no network events and no confirmed synchronous user-mode verdict path, so even MVI vendors will likely keep WFP callout drivers.
- Microsoft suspended WireGuard, VeraCrypt and Windscribe driver-signing accounts in April 2026 over re-verification, blocking updates until public pressure.

## 13-macos: macOS: observing and blocking agent activity (Endpoint Security, Network Extension, sandbox)

Full brief: [13-macos.md](13-macos.md)

Blocking exec, file and IPC activity on macOS requires Endpoint Security, which is gated by an Apple-approved entitlement bound to one Team ID. Self-builds only load it with SIP disabled, so community builds get userspace controls only. Network Extension is different: Apple does not list it among entitlements needing a request, and LuLu ships an open-source Developer ID content filter. That makes NE the first kernel-enforced control we can ship without waiting on Apple.

macOS 27 added es_new_descendants_client: AUTH and NOTIFY for the caller's own process subtree, no root, no Full Disk Access, and deadline floors that let a policy prompt block an exec. It still needs the entitlement; Apple DTS said a self-add entitlement is intended. It also added selectable deadline-miss modes (kill, fail closed, fail open), AUTH for XPC connect, and launchd bootstrap events. Restrictions vanish if the client dies.

Santa is the best precedent: one system extension with several ES clients by concern, and inverted process muting plus fork/exec/exit bookkeeping to watch only chosen process trees. Santa is now open core; its network extension is closed and paid.

Claude Code, Codex, Cursor and Gemini CLI all use Seatbelt on macOS, but only for shell commands; MCP servers and built-in tools run outside. Agents in VMs are invisible to host ES. Anthropic's beta (5 Nov 2026) lets approved vendors run a detection-only sensor inside the Cowork VM.

Risks: Apple announced on 2 Oct 2026 that Full Disk Access will tighten, with no date or detail, and ES clients need it. Process lineage breaks at launchd, XPC and terminal apps.

The web-search budget ran out mid-task, so NE limits around TLS, QUIC and ECH, and whether NE sees VM guest traffic, are inferred rather than verified.

**Design implications**

- Build three macOS tiers on one policy engine: userspace (no Apple approval), Network Extension (org Developer ID), Endpoint Security (Apple entitlement). The product must be useful at the first tier, which is all self-builders get.
- Apply for the ES entitlement immediately as an organisation and develop with SIP off meanwhile; treat approval time as an unbounded external dependency in the roadmap.
- Copy Santa's client-per-concern layout: exec authoriser, agent-tree watcher using inverted process muting with fork/exec/exit bookkeeping, secrets guard using inverted target-path muting, recorder, tamper client.
- Put process tree, policy and telemetry in a Rust static library with a C ABI; keep a thin Swift shell for ES client creation, NE provider classes, extension activation and XPC.
- Make that Rust library the embedding SDK: EDR vendors link it into their own entitled extension, because hosting our extension in their app needs a separate Apple approval.
- On macOS 27, ship an agent launcher built on es_new_descendants_client with a watchdog that kills the subtree if the client exits, since restrictions drop when the client dies.
- Ship NE as content filter plus DNS proxy first, installed lazily on wake or reboot because activation drops connections; make transparent-proxy routing to the LLM/MCP gateway opt-in.
- Cover VM-hosted agents with the Linux sensor as a guest package, pursue Anthropic's approved-vendor route for Cowork, and model the host VM process as an agent container.

**Surprises**

- macOS 27 has a user-level ES client scoped to the caller's process subtree (no root, no Full Disk Access) that Apple DTS says was designed for AI-tool supervision.
- ES has had undocumented network AUTH/NOTIFY events since macOS 26.4 (RESERVED_5/6); they are still unnamed in the 27.0 SDK.
- Santa is open core as of 2026: its network extension, sandbox-profile rules and EDR signals are paid Workshop features, and the network extension source is not public.
- Anthropic now controls an approved-vendor list for running EDR sensors inside the Cowork VM; host-based tools cannot see inside it by design.
- Endpoint Security shipped in iOS 27.2 beta as observe-only and research-mode gated, per third-party reverse engineering.

**Verifier's corrections**

Santa's pattern is not a tree follower: it propagates on FORK but drops the entry on EXEC, re-watching only binaries that match policy. Our agent-tree watcher must select each exec target itself. "Shell commands only" is wrong for Gemini CLI (whole CLI re-exec under sandbox-exec) and incomplete for Codex (file operations too). A non-root descendants client blocks all setuid/setgid execs in the subtree, so sudo breaks unless the supervisor runs as root; deadline floors exclude bootstrap AUTH events. The self-add entitlement is only a DTS "probably"; plan on the full ES entitlement. Apple's docs now list RESERVED_0..18, so never hard-code ES_EVENT_TYPE_LAST. Web search budget was exhausted; claims 4, 9, 10 were re-read at source only.

## 14-linux: Linux: observing and blocking agent activity (eBPF, LSM, fanotify, seccomp, Landlock)

Full brief: [14-linux.md](14-linux.md)

BPF LSM is the only synchronous, system-wide, cgroup-scopable deny on Linux, but it is not uniformly active. Verified from configs: Debian, CentOS Stream 9/RHEL 9, Bottlerocket, Talos have bpf in the LSM list; Ubuntu 22.04/24.04/26.04 compile it but leave it inactive (Launchpad bug still open), needing a boot parameter and reboot. WSL2 only gained active BPF LSM on 2026-10-06 (kernel 6.18.54.1) and still lacks error injection and fprobe, so Tetragon-style Override does not work there. Tetragon's docs confirm SIGKILL does not reliably stop the in-flight operation; LSM return codes are the race-free path. LSM BPF programs must be GPL-compatible, but kernel docs allow packaging with non-GPL userspace; Tetragon uses GPL-2.0-only OR BSD-2-Clause for BPF beside Apache-2.0. Landlock is now at ABI 12 (7.4-rc); pathname UNIX socket control arrived only in ABI 9 (kernel 7.1), which is why Codex dropped Landlock for bubblewrap plus seccomp, as did Anthropic's sandbox-runtime. Both break under Ubuntu's AppArmor user-namespace restriction, and Claude Code's sandbox covers only Bash, not Read/Edit, hooks or MCP servers. TLS uprobes fail on Claude Code (stripped Bun, static BoringSSL; per-build offset recovery needed). fanotify permission events plus cgroup-v2 BPF give no-reboot enforcement and can hold a syscall for human approval, which BPF LSM cannot. Syscall-tracepoint sensors are blind to io_uring. BeyondTrust's AI agent security supports Windows and macOS only; open-source Linux work is research-grade or launch-time only. Recommended: capability probe, then observe/attribute with per-session cgroups, then fanotify plus cgroup BPF, then BPF LSM, plus an own Landlock/seccomp launcher, with an explicit fallback ladder. Web search budget ran out mid-run; some items (Falco io_uring status, Fedora/RHEL 10 configs, aya lsm_cgroup support) are unverified and flagged in the file.

**Design implications**

- Ship a capability probe first (BTF, bpf in active LSM list, lockdown, cgroup v2, kprobe override, fanotify, Landlock ABI, userns state, io_uring sysctl) and select the enforcement tier per host from its output.
- Make cgroup-v2 BPF network hooks plus fanotify permission events the default enforcement tier, because they need no reboot and work on stock Ubuntu and WSL2; add BPF LSM as the upgrade tier.
- Use BPF LSM return codes for static deny and fanotify or seccomp-unotify with ADDFD for hold-for-approval verdicts; never present kill-only or syscall-entry hooks as blocking.
- Attribute by one cgroup-v2 scope per agent session plus fork-copied task storage, and track IPC edges (systemd, D-Bus, tmux, Docker socket, loopback ssh, tainted file writes) to follow lineage escapes.
- Keep eBPF code in a separate crate licensed GPL-2.0-only OR BSD-2-Clause with Apache-2.0 userspace, as Tetragon does; treat Kunai (GPL-3.0) and KubeArmor's enforcer (GPL-2.0) as reference only.
- Build our own Landlock plus seccomp launcher that needs no user namespaces, gate features by ABI, and compose with Codex and sandbox-runtime sandboxes instead of replacing them.
- Get LLM content from in-agent hooks, gateways or a TLS-terminating proxy; treat TLS uprobes as optional per-build offset packs guarded by binary digest checks.
- Hook LSM, VFS and socket layers rather than syscall tracepoints, and deny io_uring in launch sandboxes, so io_uring cannot bypass the sensor.

**Surprises**

- WSL2 never had working BPF LSM until kernel 6.18.54.1 on 2026-10-06; older branches had either the config or the LSM list entry, never both.
- Landlock is already at ABI 12 in 7.4-rc, with UDP control (7.2) and capability/namespace rules; most write-ups still stop at ABI 6 or 7.
- Codex and Anthropic's sandbox-runtime both use bubblewrap plus seccomp, not Landlock; Codex explicitly rejects its Landlock path for filesystem-restricted policies.
- Falco 0.44 (2026-05) dropped its gVisor engine, legacy BPF probe and gRPC output, and its 2026 release notes show no io_uring or LSM-hook fix.
- BeyondTrust's shipping AI agent security product has no Linux support at all, despite kernel-level enforcement claims on Windows and macOS.

**Verifier's corrections**

Ubuntu 26.04 is no longer BPF-LSM-inactive: LP #2166235 added bpf to CONFIG_LSM, shipped in resolute-updates from 7.0.0-42.42 (2026-10-28); only 22.04, 24.04 GA and 25.10 still need lsm=, and cloud/HWE 7.0 flavours may lag. Probe /sys/kernel/security/lsm at runtime rather than keying on distro. fanotify gates are one release later than stated: FAN_DENY_ERRNO needs 6.14, FAN_MARK_MNTNS needs 6.15. fmod_ret on security_* does not need error injection, and Ubuntu 24.04/26.04 build BPF_KPROBE_OVERRIDE, so a no-reboot synchronous deny tier exists on Ubuntu (source-read, untested live). The fanotify watchdog (6.18+) only warns. WSL2 arm64 lacks override for a different reason than x64. Web search was unavailable; all checks are direct source reads.

Every shipping product discovers AI agents from a catalogue of known names; none documents how it finds bespoke ones. BeyondTrust comes closest, citing classifiers on process naming, signatures and LLM API traffic patterns, but gives no detail. Native Linux endpoints are uncovered: BeyondTrust and Origin are Windows and macOS only, CrowdStrike Falcon Guardian discovers on Windows and macOS, and Microsoft has WSL in preview only.

An open catalogue format already exists: arthur-ai/ai-detection-spec (Apache-2.0, 63 agents, 174 identifiers, each proven on a real install in CI). It deliberately excludes SDKs, frameworks and model runners, which are the bespoke-agent signals, so we should extend it with a second "building blocks" catalogue plus code-signing, network, hook and telemetry routes.

The evidence that separates an agent from an LLM client is the loop: model response followed by tool-like effects. AgentSight does this with lineage, a 100 to 500 ms window and argument matching, but publishes no precision or recall. TLS plaintext capture is fragile: Claude Code (Bun, static BoringSSL) and all Node.js need per-binary handling, and Microsoft's network inspection excludes pinning and HTTP/3.

For attribution, Claude Code hooks give stable join keys (session_id, prompt_id, tool_use_id, agent_id), and with tracing on, subprocesses inherit TRACEPARENT for the active tool span. Agents already self-mark child environments (CLAUDECODE, CURSOR_TRACE_ID, CODEX_THREAD_ID, AI_AGENT). Off-machine attribution is mostly forgeable convention; durable options are separate identities (Entra agent identities, AWS SourceIdentity) and injected tags such as AWS_SDK_UA_APP_ID.

Caveats: the web search budget ran out partway, so Zenity, Noma, Push, Jamf and 1Password checks were not researched. CrowdStrike's mechanism is undocumented publicly. The scoring weights and per-OS designs in the brief are my proposals, built partly on prior knowledge of OS primitives that I did not re-verify today.

**Design implications**

- Emit two distinct findings, 'LLM client' and 'agent'; require behavioural evidence (tool loop, MCP handshake, or tools array in requests) before calling a process an agent.
- Adopt and extend ai-detection-spec's catalogue and evidence schemas; add code-signing, network, env-marker, hook, telemetry, MCP-config and transcript routes, plus a separate SDK and framework catalogue.
- Capture exec-time environment on every OS: it resolves relocated config directories, reads agent self-markers and TRACEPARENT, and binds processes to specific tool calls.
- Put each agent session in a kernel-tracked container at launch (cgroup v2 on Linux, job object on Windows, audit-token lineage on macOS) so attribution survives double-fork and reparenting.
- Model brokered hops (Docker socket, SSH, schedulers, WMI, launchd) as explicit lower-confidence edges; record file-mediated execution as 'influenced by', never 'performed by'.
- Make declared-versus-observed gaps first-class detections: OS actions in a session lineage with no matching hook tool call, and sessions producing no hook events.
- Inject session identity outward at session start (AWS_SDK_UA_APP_ID, TF_APPEND_USER_AGENT, AI_AGENT, sensor-signed git notes, SourceIdentity via a credential broker) so cloud and git logs separate agent from human.
- Prefer hooks and the agent's own OpenTelemetry exporter for content; treat TLS interception and uprobes as fallbacks, and report 'could not look' separately from 'nothing found'.

## 18-identity-ietf: Internet standards for agent identity, authorisation and delegation (IETF, OAuth, WIMSE, SPIFFE)

Full brief: [18-identity-ietf.md](18-identity-ietf.md)

No agent-specific identity standard is an RFC as of 2026-11-09; the stable base is OAuth RFCs (8693, 8705, 8707, 9396, 9449, 9470, 9728), RFC 9421, SD-JWT and SCITT architecture (RFC 9943). The IETF's consensus direction is "agents are workloads": draft-ietf-wimse-aims-01 (WG document) composes WIMSE/SPIFFE identifiers, WIT or X.509 credentials, OAuth token exchange, Transaction Tokens, identity chaining and CIBA, and defines no new protocol. Three new venues exist this month: agentproto and dawn (chartered October 2026, first meeting at IETF 127) and an AUDIT WG-forming BoF; agentproto and dawn both exclude identity and defer to OAuth and WIMSE. Delegation is converging on RFC 8693 nested act plus sub_profile=ai_agent, but only in individual drafts; ID-JAG-06 still leaves actor_token processing undefined, so MCP enterprise authorisation identifies user and client app, not the agent instance. MCP 2026-07-28 deprecates Dynamic Client Registration for Client ID Metadata Documents and already pins stale drafts (ID-JAG -04 vs -06, OAuth 2.1 -13 vs -17, CIMD -00 vs -03). Near-RFC items safe to build on: identity chaining and Token Status List (RFC Editor queue), RFC 10070, WIMSE HTTP-signature profile (publication requested), Transaction Tokens (WG consensus). SPIFFE added an Incubating WIT-SVID; SPIRE is at 1.16.0. Standards do not address agents sharing a human's credentials or local stdio tool calls; endpoint attribution must be synthesised by sensors. Vendors diverge: Entra Agent ID uses proprietary xms_act_fct/xms_sub_fct claims instead of act, and BeyondTrust's docs state the agent has no identity of its own. One individual draft (draft-liu-audit-enforcement-points-00) already describes our Agent/Gateway/Host enforcement-point architecture. Caveat: web search was cut off early by a shared budget, so document status is well verified (Datatracker API) but implementer coverage is thinner.

**Design implications**

- Use a WIMSE/SPIFFE URI as the canonical, never-reused agent identifier; keep a separate key-independent agent_instance_id so identity survives key rotation and sub-agent spawning.
- Build phase 1 on RFCs only: gateways as RFC 9728 resource servers with RFC 8707 audience checks, RFC 8693 exchange adding nested act, DPoP or mTLS binding, RFC 9396 for tool permissions. Never pass tokens through.
- Put every draft-based feature (ID-JAG, CIMD, Transaction Tokens, WIT/WPT, actor profile) behind version-tagged adapters; MCP already lags the IETF by two to four draft revisions.
- Expose the policy decision point through OpenID Authorization API 1.0 (Final, January 2026) so hooks, gateways, OS sensors and third-party EDR products call one standard interface.
- Add an assurance field to agent identity (observed, self-asserted, IdP-issued, attested) because no standard covers unregistered agents discovered by sensors; let observed identities upgrade without changing identifier.
- Build a claim normaliser that maps Entra xms_* facets, standard act chains, SPIFFE IDs and Web Bot Auth Signature-Agent URLs into one delegation model.
- Treat the OS sensor as an out-of-process call authority for stdio MCP tools and as a credential broker that swaps a human's ambient credentials for agent-scoped, key-bound tokens.
- Sign audit records in a SCITT-compatible envelope and adopt the Agent/Gateway/Host enforcement-point vocabulary; engage with the AUDIT BoF as an open-source reference implementation.

## 20-policy-languages: Policy and rule languages for authorisation and detection

Full brief: [20-policy-languages.md](20-policy-languages.md)

Recommendation: Cedar is the authorisation core (Rust-native 4.14.1, WASM, schema validation, SMT analyser SymCC proving always-allow/deny, implication, equivalence with counterexamples). The big 2026 change is Dogwood, an Amazon-authored Apache-2.0 Cedar superset (v1.0 on 2026-10-13) adding session-history conditions (formerly/since/previous/count/sum within a window) and "information providers" for ML and content scores; it lowers to plain Cedar with hoisted context slots, and AWS AgentCore Policy now tells users to write it. It is four weeks old and its reference interpreter is declared not for production, so adopt its syntax and lowering model, keep lowered Cedar as the signed enforced artefact, and build our own observe-time session monitor. Stateful evaluation is the latency risk: Dogwood's durable engine measures 1.23 ms at 10 policies and 6.45 ms at 1,000; AgentCore caps temporal policies at 20 per engine. No candidate returns ask, redact or sandbox while staying analysable, so model richer decisions as attested preconditions (forbid unless evidence) and transform-then-re-evaluate, with annotations only as hints. Detections: Sigma plus correlation rules as exchange format with our own Rust matcher (existing Rust Sigma engines are AGPL/GPL), YARA-X for content, both writing session labels and risk that Cedar reads. Interop: agent-hooks/Agent Control Specification (eight interception points; allow, deny, transform, warn, escalate) locally and AuthZEN 1.0 (Final, 2026-01-11) remotely. Rego, CEL, OpenFGA/SpiceDB and agent-native rule files are rejected as the core; native formats and Tetragon/Santa are compile targets. Caveat: the shared web-search budget was exhausted before my first query, so all findings come from direct reads of primary docs and GitHub; Cedar microsecond latency and several Dogwood syntax edge cases (unless temporal) are unverified. The brief includes the layered design, six worked examples, a matrix and rejected alternatives.

**Design implications**

- Use Cedar as the single enforced authorisation artefact; accept Dogwood temporal and provider syntax as a front end that lowers to Cedar plus a slot manifest, so Dogwood can be replaced without touching enforcement.
- Build an incremental in-memory session monitor that updates temporal slots when events are observed, with asynchronous durability, so each decision is one pure Cedar evaluation; keep temporal rules few per device.
- Express ask, sandbox, step-up and just-in-time credentials as forbid-unless-evidence conditions, and redaction as transform then re-evaluate; annotations only hint the remedy, so ignoring them yields deny.
- Write security-critical normalisers (path canonicalisation, shell and SQL parsing, MCP schema generation) that emit typed facts, because Cedar has no regex, quantifiers or path type; test them harder than policies.
- Compile tiered policy (MSP to user) into one effective set per device; gate publishing with SymCC implication checks against the parent ceiling, auto-applying narrowing changes and requiring approval for expansions.
- Adopt Sigma plus correlation rules for detections with our own permissively licensed Rust streaming matcher; detections write session labels and risk that authorisation policies read.
- Expose the decision point through the agent-hooks/ACS contract locally and AuthZEN remotely, and generate native Claude, Gemini, Codex, Cursor, Tetragon and Santa rules as lossy compile targets, refusing constructs that cannot be preserved.
- Make natural-language authoring a pipeline: generate, schema-validate, SMT-check, deterministic back-translation, replay against recorded history, shadow mode, then enforce; treat slots as free booleans during analysis.

- AgentCore added a third policy effect, suppressOutput, that is absent from the open-source Dogwood repository.

## 22-research-conferences: Security research and conference work on agents: defences, AI control, offence

Full brief: [22-research-conferences.md](22-research-conferences.md)

Web search was unavailable (shared budget exhausted), so this brief rests on direct fetches of primary sources: arXiv, conference programmes, vendor docs, IETF and GitHub advisories. It lists 70 items, 20 design principles and 11 unshipped ideas. DEF CON 34 and Black Hat 2026 talk lists could not be reached.

The evidence points one way. Guardrail classifiers are not a boundary: adaptive attacks broke 12 published defences, mostly above 90%, and non-instruction payloads pass detectors as benign. Defences with real guarantees are architectural (CaMeL, FIDES, plan- or compile-then-execute), but they cannot be imposed on closed third-party agents; for those we only have hooks, gateways and the OS.

String-matching allow-lists fail structurally. Claude Code has 36 published advisories and Cursor more than 30, dominated by command-parser bypasses, execution before the trust dialog, symlink and TOCTOU races, and agents writing their own or each other's config. NVIDIA's mandatory controls are the floor: default-deny egress, OS-level write blocking outside the workspace, and no agent writes to hooks, MCP, skills or rules files.

LLM monitors miss a measurable share: 17% of real overeager actions in Claude Code auto mode, 26% evasion in BashArena, 6% in Async Control at 1% false positives. They are also attack surface: an agent can inject its monitor, and resampling amplifies that. Chain-of-thought is fragile, so ground truth must be kernel and network effects.

The daily volume is not attackers. Users accept 93% of prompts, and frontier models exceed their authorisation in 43 to 61% of benchmark tasks with no adversary.

Agent identity is converging on workload identity (IETF WIMSE draft, 2 Nov 2026). BeyondTrust already ships kernel-level agent-versus-human attribution on Windows and macOS; Microsoft Agent 365 is registry-centric. Neither doc set describes Linux endpoints, information-flow labels or control-style responses, which is our opening.

**Design implications**

- Treat every classifier and LLM judge as a signal, never a boundary; put deterministic enforcement in the OS sensor and gateway, and ship an adaptive-attack regression suite so miss rates are measured, not assumed.
- Make agent configuration protected system state: block agent-lineage writes to hooks, MCP configs, skills, rules files and IDE settings for every agent on the host, and alert when one agent edits another's config.
- Evaluate repo-supplied config before any hook, MCP start or network call, and bind file checks to inodes or descriptors rather than paths, because in-sandbox code will race path validation.
- Default-deny egress through a broker that injects short-lived secrets; keep credentials out of the sandbox and model context, and give each agent its own SPIFFE/WIMSE-style workload identity.
- Feed the action judge only user intent and tool calls, plus provenance labels from the sensor; treat agent output as hostile to the monitor and never depend on chain-of-thought.
- Replace per-action prompts with boundaries: transactional workspaces, monotonic per-task policies where narrowing is automatic, and step-up with human-presence evidence only for a few high-impact actions.
- Detect by diffing what the agent claimed against kernel and network records, track Rule-of-Two state per session, and map detections to the seven-stage promptware kill chain.
- Add control-protocol responses to the usual EDR set: deny-and-continue, resample, defer to human, asynchronous audit with a stated budget, escalate after repeated denials, kill headless runs.

**Surprises**

- Without any adversary, frontier models exceeded their authorisation in 43 to 61% of benchmark tasks, and more capable models drifted more (arXiv 2611.09113, self-reported, Nov 2026).
- A fabricated safety warning written as an ordinary review steers agents about as often as instruction injection (60.4% vs 66.0%) and injection detectors class it as benign (NeurIPS 2026).
- Injections styled as the model's own reasoning reached 50% success on reverse-shell and repo-backdoor goals where the same goals in user voice never succeeded.
- A Berkeley compile-then-execute web agent reports 0% attack success on WASP with higher task utility than ReAct (77.8% vs 55.1%), so separation no longer has to cost utility on the web.
- A Radware scan of 86 million GitHub issues, PRs, comments and READMEs found about 2.5 hidden prompt injections per 100K items aimed at coding agents.

## 23-schemas-transport: Event schema, tamper-evident audit, sensor transport and fleet management protocols

Full brief: [23-schemas-transport.md](23-schemas-transport.md)

Web search quota was exhausted before this step, so the brief rests on primary sources read directly (GitHub repos and release notes, spec and docs pages); a few items are marked unverified.

OCSF 1.9.0 (Aug 2026) is now agent-aware: an ai_agent object with stable uid and instance_uid, a delegation object, the ai_operation profile on all System, Network, Application and IAM classes, and a record_integrity profile giving a standard per-event hash chain and signatures. MCP tool metadata (ai_capability, with schema and description fingerprints) and permission results (ai_status) are merged but only in 1.10.0-dev.

OpenTelemetry GenAI conventions cover invoke_agent, execute_tool, skills, MCP and A2A, but are all "Development", moved to a new repo in May 2026 with no tagged release and about 20 pending breaking changes. ECS 9.5 and Microsoft Agent 365 reuse the gen_ai.* names, each pinned or restricted differently.

Recommendation: own a protobuf canonical model; export OCSF 1.9 plus a small extension (approval, attribution confidence); treat OTel GenAI and OpenInference as versioned ingest and export dialects.

OTLP lacks idempotency, ordering and mandated zstd, and forbids retry on partial success. OTel Arrow only wins on large streamed batches and is worse at batch size 10. Use a custom acked protobuf batch stream over gRPC/HTTP/2 with device sequence numbers, a disk spool and zstd with a trained dictionary; keep a unary POST fallback and an OTLP edge at the gateway.

Use OpAMP (v0.20.0, Beta) for config, health and package offers, and TUF for update trust, since OpAMP leaves code signing to the agent. rustls with aws-lc-rs gives hybrid X25519MLKEM768 by default; FIPS builds exist but static FIPS is Linux-only and macOS is undocumented.

For audit, combine the OCSF-shaped sensor hash chain with a tile-based Merkle log (tlog-tiles, Tessera, Rekor v2) and SCITT receipts (RFC 9943). Regulators require complete, attributable, time-stamped records, not cryptographic proofs.

**Design implications**

- Define the canonical model as our own protobuf IDL with an envelope (UUIDv7 event_id, tenant, device, boot_id, seq, trace/span ids, principal, integrity); never store OCSF or OTel names as the internal schema.
- Ship versioned, data-driven mapping files: OCSF 1.9.0 as default SIEM/lake export plus an 'aidr' extension for approval, attribution confidence and 1.10-dev objects; golden-test against the OCSF validator.
- Treat OTel GenAI and OpenInference as ingest dialects pinned to a specific commit; offer OTLP trace export and a named Agent 365-compatible export profile limited to its four accepted operation names.
- Sensor data plane: gRPC bidirectional stream of acked EventBatch messages with (device_id, boot_id, seq) idempotency, priority lanes, bounded disk spool and explicit gap events; unary HTTP/2 POST fallback for proxies.
- Compress with zstd level 3 and a dictionary trained per schema version, distributed as a managed package with dict_id in each batch; benchmark against OTAP before considering Arrow on endpoints.
- Control plane: OpAMP over WebSocket with HTTP polling fallback for config, health and package offers; verify all updates against TUF metadata with offline root and targets keys; send response actions as separately signed commands.
- Transport security: TLS 1.3 mutual auth via rustls plus aws-lc-rs, hybrid X25519MLKEM768 preferred, keys generated in TPM, Secure Enclave or CNG where available, short-lived certs, and a separate FIPS build feature.
- Audit: sign and hash-chain events at the sensor using OCSF record_integrity field shapes, append batch digests to a server-side tile log with witnessed checkpoints, and expose SCITT-style receipts for auditors.

**Surprises**

- OCSF, not OpenTelemetry, is ahead on agent security semantics: it already has agent instance identity, delegation chains, MCP tool fingerprints and a tamper-evidence profile.
- OTel GenAI conventions left the main semconv repo in 2026 and currently have no released version or schema URL to pin against.
- Microsoft deprecated its Agent 365 Observability SDK within months of GA, and its ingestion silently drops spans outside four operation names while returning 200 OK.
- OTel Arrow is larger on the wire than OTLP plus zstd for small unary batches, which is the typical endpoint sensor pattern.
- CycloneDX closed its Agent BOM proposals and Sigma has no AI log source, so there is no standard agent or MCP inventory or detection taxonomy to adopt.

In stream mode at batch 10 it is still 1.03x-2.79x smaller than OTLP+zstd; the 0.27x figure is uncompressed (compressed unary range is 0.41x-0.95x). ## 24-platform-architecture: Server architecture: single binary to multi-tenant SaaS and MSP

Full brief: [24-platform-architecture.md](24-platform-architecture.md)

Web search quota was exhausted early, so this rests on about 45 direct fetches of vendor docs, specs and GitHub; no 2026 survey of cell-architecture write-ups was possible. Recommendation: one Rust binary with exactly two shapes, `--target=all` and one target per process. Grafana abandoned a middle shape twice (Loki SSD removed in 4.0, Mimir read-write removed in 3.0). OpenObserve is the closest prior art: SQLite plus local disk on one node; Postgres, NATS and Parquet on object storage in HA. Stacks needing Kafka, ClickHouse, Postgres and Redis proved unsupportable for self-hosters (PostHog dropped Kubernetes; Sentry self-hosted is ~15 services with a 16 GB floor and no HA). No studied project has hard tenant isolation plus an MSP hierarchy: Wazuh's tenancy is dashboard saved objects, Velociraptor calls its orgs "soft separation" under one CA. Make the Organisation the hard boundary (keys, object prefix, region, quotas), with Provider above it for inherited default/locked policy and audited delegated access; cross-tenant views are federated queries. Fleet control planes are cheap at 100k endpoints (Fleet: 25 small tasks plus Aurora 2xlarge); the telemetry store is the cost (Elastic: 512 GB RAM hot tier). Use OpAMP semantics for sensor management; Wazuh 5.0 (rc2) is replacing its bespoke protocol with HTTPS and JWT enrolment tokens. Policy and detection content must ride the same signed, health-gated rings as binaries (CrowdStrike RCA finding 6; Microsoft MVI 3.0); Teleport still halts rollouts manually and ships unsigned binaries. MCP went stateless on 2026-07-28, so it is just another API surface. Accept OTLP: Microsoft deprecated the Agent 365 Observability SDK for an OpenTelemetry distro that dual-exports. My sizing is assumption-based: ~100k events and ~60 MB raw per heavy workstation per day, ~150 MB/month compressed, under $0.01 storage; 100k endpoints is ~6 TB/day raw. Validate with a pilot.

**Design implications**

- Build one Rust binary with `--target=all` and per-target processes only; no intermediate mode. Named targets: router, gateway, ingest, log, detect, store, query, control, rollout, content, keys, notify, api.
- Single-node mode must need zero external services: SQLite metadata, embedded WAL, local Parquet. Scaled mode swaps in Postgres, a partitioned log broker and object storage behind the same traits.
- Make Organisation the hard isolation unit (per-org DEK, object prefix, region pin, quotas, audit log); derive org_id from the device credential, never from payloads; enforce via framework-injected tenant context plus Postgres RLS.
- Model MSPs as Provider > Organisation > Group > Device > Agent with default/locked inheritance, per-setting provenance, time-boxed audited role bindings, and cross-tenant views as federated queries returning org_id.
- Adopt OpAMP-style sensor management: config hash, APPLIED/FAILED status, capability negotiation, package offers. Enrol with short-lived use-capped JWT tokens and hardware-backed device keys with request signing, all in the open build.
- Ship binaries, policy and detection content through one signed (TUF) ring pipeline with canaries, bake time, automatic health-gated halt, sensor-side last-known-good revert, and customer-selectable N/N-1 content rings.
- Offer four key modes: operator KMS, customer-managed KEK, endpoint-sealed sensitive fields (HPKE to a customer-held key with blind-index search), and customer co-signed policy so the operator cannot push policy alone.
- Go proto-first (gRPC plus generated REST/SDKs), accept OTLP and emit OCSF, expose a stateless MCP endpoint on the same authz path, and use SQL over OCSF tables with a KQL-style front end and Sigma import.

- Wazuh 5.0 (rc2, 2026-10-30) replaces its agent protocol end to end with HTTPS and JWT enrolment tokens, makes clustering the default, and relicenses the engine under AGPLv3.
- MCP dropped sessions and the initialize handshake on 2026-07-28, and deprecated Roots, Sampling, Logging and Dynamic Client Registration.

## 28-oss-sustainability: Open-source sustainability: licences, governance, contribution model, business model

Full brief: [28-oss-sustainability.md](28-oss-sustainability.md)

Web search was unavailable (shared budget exhausted), so findings rest on directly fetched primary documents and the GitHub API; post-mid-2026 news may be missing. Core recommendation: Apache-2.0 for every code component with DCO and no CLA. It is the only combination that is OSI-approved, embeddable by proprietary EDR vendors, and admissible to a Linux Foundation home: CNCF mandates Apache-2.0, OpenSSF Apache-2.0 or MIT, and AAIF an OSI-approved permissive licence. AGPL on the server would close all three. A permissive licence cannot itself stop the steward closing future versions; credibility comes from who owns the trademark, domain and GitHub organisation, as the 2025 NATS/Synadia dispute showed. Forks of relicensed projects are thriving (OpenTofu, OpenBao, Valkey each have 350+ contributors), Redis re-added AGPL and admitted community damage, and MinIO's AGPL repository is archived. Rules content must be Apache-2.0 or MIT: Sigma's DRL and Elastic's ELv2 are not OSI-approved and burden embedders. SPDX also flags CC-BY-4.0, CDLA and OpenMDW as not OSI-approved, so docs need dual licensing and weights Apache-2.0. Under the CRA the steward is a manufacturer for anything monetised; Article 14 reporting has applied since 11 September 2026. Intrusion detection and prevention is Annex III Class II, but Article 32(5) lets fully open-source products self-assess if technical documentation is public. AI-contribution policies agree on human accountability, disclosure, and agents never signing the DCO, but conflict on trailers (LLVM and OpenTelemetry want Assisted-by; Kubernetes forbids it). Open PR queues and cash bounties have failed: curl ended its bounty in January 2026, Ghostty gates PRs behind a vouch list, tldraw disabled PRs. Revenue without withheld features is narrow: hosting, CrowdSec-style reciprocal intelligence feeds, OEM services and support; donations are negligible.

- Publish a day-one covenant: OSI licences forever, binaries under the same licence as source, and a dated trigger to transfer trademark, domain and GitHub organisation to a neutral foundation.
- Target AAIF Sandbox first (join its Security, Identity and Observability working groups now); keep CNCF or OpenSSF as alternatives. Design governance to hit two unaffiliated adopters and two committing organisations.
- Split contribution into two lanes: open declarative content (rules, fingerprints, policy packs) verified by fixture-based CI, and code that requires an accepted specification plus a vouch-list entry.
- Keep content in a separate signed, indexed repository with Falco-style maturity tiers, benign and regression corpora, a known-false-positives file and automatic promotion.
- Fund through hosting, a CrowdSec-style reciprocity-tiered intelligence feed with a published rule, and an OEM programme (signed LTS builds, embargoed notices, CRA documentation pack, conformance mark).
- Publish CRA technical documentation and a cybersecurity policy in-repo to use Article 32(5) self-assessment; use GitHub as CNA and private reporting, with no cash bug bounty.

## 29-rune: Rune UI framework deep-dive for the desktop app

Full brief: [29-rune.md](29-rune.md)

Rune is feasible for the console UI but not as a trust boundary, and it is weak without a GPU. It is 19 days old (v0.0.1, MIT, no tags, not on crates.io, about 1,805 commits, 84% one author); apps pin a git rev of a fast-forward-only `dev`. The model is Elm-like (`view(&State) -> El`, handlers mutate state, `poll`, `AppHandle::update`), which fits a view-model boundary well. Accessibility is real (AccessKit adapters for UIA, NSAccessibility, AT-SPI, default feature). rune-kit has virtualised Table and Tree, Diff, streaming Markdown, forms, toasts, dialogs and an app shell; no charts, slider, date picker or gutter code editor. Headless mode is excellent: same renderer, virtual clock, PNG, element plus accessibility tree JSON, scripted input, and an in-process runtime for cargo test.

Three findings should shape the architecture. First, an AccessKit Click runs a button's `on_press` with no pointer event, Rune has no input provenance, and every release binary accepts `--script` on argv, so a same-user agent can press an approval button three ways. Second, rendering needs DX12 or Vulkan (Vulkan only on Linux, no GL, no CPU renderer); on WARP a full-window frame costs 0.67 to 0.82 CPU-seconds, about 2 fps on 2 vCPUs, so VDI and RDP users need another path. Third, long uptime is at risk: open reports of 100% idle core on Windows DX12 and covered Wayland windows, a per-cycle surface leak on macOS, and a 180 MB private-memory floor on Windows.

Platform gaps: tray is Windows and Linux only, notifications macOS and Windows only, no start-at-login, packaging, signing or updater. Governance: issues only, 198 of 211 open, 5 with a maintainer reply, upstream CI is macOS only, and the documented test command failed 16 tests on dev.

Web search was unavailable, so there is no third-party commentary; everything is from the repo and vendor docs.

**Design implications**

- Split the UI into an always-on session agent (tray, notifications, autostart, IPC, no GPU device) and a Rune console process spawned on demand that exits on close, to avoid leak and idle-spin reports.
- Never treat a click in a same-privilege Rune window as approval. On Windows launch the prompt above the agent's integrity level and restrict the answer pipe; elsewhere use OS authentication or out-of-band approval for high-risk actions.
- Ship every Rune binary with `.args(Vec::new())` so headless flags such as `--script` are not read from process argv, and add a negative test proving accessibility clicks and scripts cannot approve.
- Put view-models, intents, reducers, IPC client and token data in a crate with no Rune dependency; keep Rune views as thin dispatchers. Plan a second front-end for no-GPU fleets.
- Wrap tray, notifications, single instance, deep links and autostart behind our own shell trait; fill macOS tray and Linux notifications with other crates, and write autostart ourselves.
- Mirror the repo, pin a rev, bump on a schedule through our own Windows, macOS and Linux CI plus a 48-hour real-window soak with memory and idle-CPU assertions; keep a small patch queue.
- Use tree and accessibility JSON goldens on all three OSes and PNG goldens on one reference renderer (Linux lavapipe); drive flows with `--script` and in-process `headless_runtime` tests.
- Detect software adapters or remote sessions at start and switch to a lite mode: small windows, no shadows or blur, instant transitions, cached subtrees.

**Surprises**

- Accessibility is not a stub: AccessKit adapters ship by default. The same README's 'Differences from PLAN.md' section still says there is no AccessKit, so the docs contradict themselves.
- The 'agents turn issues around fast' claim is not visible in the tracker: 198 of 211 issues are open and only 5 have a maintainer reply, while the team merged 205 of its own PRs.
- Every release binary is scriptable from argv (`--script`, `--tree`), which makes any Rune app drivable without a window unless the app opts out.
- Upstream CI runs tests on macOS only, despite Windows and Linux being called first-class; the precompiled Windows shader went unused because of a CRLF hash mismatch.
- The docs site is behind Cloudflare Access for the maintainers' accounts only; the READMEs are the only public documentation.

**Verifier's corrections**

Eight of ten claims held against source. Three things to get right. (1) Windows prompt isolation: a high-integrity prompt is not closed to everything. An admin-launched UIAccess process or any elevated agent can still drive it; only system-integrity UI is out of reach of all documented scenarios. (2) The 92% CPU / 2.1 fps WARP figure is from a 1642x1091 window on Windows 11 with WARP forced and 2 cores pinned, not the 380x1080 panel on the VM. (3) macOS does gate accessibility control behind a per-app user grant, so "no boundary" is overstated. Also: App::args does not cover is_headless() or environment switches, and 189 (not 160) issues arrived since 2026-11-06. Web search was unavailable; all checks used directly fetched primary sources.

## 31-agentdev-operating-model: Operating model for a product built entirely by AI agents

Full brief: [31-agentdev-operating-model.md](31-agentdev-operating-model.md)

Web search was unavailable (shared budget exhausted), so this rests on direct reads of primary pages and the GitHub API; vendor numbers are self-reported. Public evidence supports two topologies: a hierarchy of non-coding planners over isolated workers (Cursor, after flat lock-coordinated peers collapsed to the throughput of 2-3 agents), and single-writer-per-change with extra agents only reviewing or advising (Cognition, April 2026). Anthropic's 16 flat peers with git lock files worked only because the compiler task had thousands of independent tests and a GCC oracle; a security product has few such oracles. OpenAI's zero-human-code product (about 1M lines, 1,500 PRs, five months) shows the durable pattern: a 100-line AGENTS.md as a map into a linted docs tree, execution plans and decision logs in the repo, a rigid layered architecture enforced by custom linters whose error messages carry the fix, and scheduled cleanup agents. Self-evaluation fails; a separate, clean-context, calibrated evaluator that drives the real artefact is the main quality lever, but Anthropic removed parts of its harness within one model generation, so every component must be re-justified per model release. Test gaming is documented (placeholders, forcing UI state by script, marking done after unit tests) and countered by immutable acceptance files, expected-before-action logs and oracles. Costs: about $20k for a 100k-line compiler; $125-200 per harnessed app build versus $9 solo; agent teams about 7x tokens. Unattended agents need an OS boundary: bypass mode only in a container or VM, credentials held by a proxy outside the sandbox, read-only agent jobs with scoped buffered writes (gh-aw). No public effort covers kernel drivers or system extensions, and hosted macOS arm64 runners cannot nest virtualisation, so the sensor work needs self-hosted VM farms. A niche UI framework runs against OpenAI's finding that agents do best on well-represented technology. The brief recommends roles, lifecycle, repository artefacts, escalation rules, tier policy and a failure-to-countermeasure table.

**Design implications**

- Adopt single writer per work item: non-coding chief planner, area planners per platform, isolated workers returning structured handoffs, independent evaluators, scheduled gardeners. Keep the merge queue deterministic software, not an agent.
- Make the repository the only memory: 100-line AGENTS.md map, per-crate AGENTS.md, ADRs, exec plans with decision logs, llms.txt references for unusual dependencies, CI checks for doc freshness and cross-links.
- Encode architecture as crate dependency-direction lints and structural tests from the first commit, with lint messages that state the remediation. Add lints for placeholders and TODO stubs.
- Put acceptance criteria and tests in paths workers cannot edit (hook deny plus CI check); only an evaluator with recorded evidence flips the pass flag. Name an oracle for every spec.
- Run every unattended agent in a container or VM with an egress allowlist and proxy-held tokens; give each agent role a single-purpose identity; keep signing keys and release steps unreachable by agents.
- Expose cross-OS testing as one tool that dispatches to remote runners and returns terse, greppable output. Plan self-hosted Mac hosts with disposable VMs and snapshot-revert Windows and Linux VM pools for driver work.
- Set model and effort per role, cap writers at 3-5 initially, enforce per-item token budgets, max turns and stall timeouts, and re-benchmark each harness component on every model release.
- Dogfood: run our own hooks, gateways and sensors on the development agent fleet and log every escalation and automated approval to an in-repo decision log sampled by risk tier.

**Surprises**

- Cursor removed both the judge and the integrator roles; a central quality gate became the bottleneck. They accept a small steady error rate and do a final green pass instead.
- Anthropic dropped sprint decomposition, context resets and per-sprint QA within one model generation. Harness components have a half-life of months.
- Cognition found a weak primary model escalating to a strong one failed; consultation only worked between frontier-level models, including Claude and GPT together.
- OpenAI lost 20% of human time to cleaning agent slop until cleanup itself was automated; it also reimplemented small libraries in-repo because agents handle opaque dependencies poorly.
- The GitHub API now resolves cirruslabs/tart to openai/tart, and the Gas Town and Beads repositories moved to a gastownhall organisation; Beads is now backed by Dolt, not JSONL in git.

All ten claims held; no refutations. Points the architect must not get wrong: (1) gh-aw threat detection defaults to warn mode, so flagged issues, comments and PRs still publish unless continue-on-error is false. (2) Tart is FSL-1.1-ALv2 (OpenAI), source-available, not open source. (3) Hosted x64 Linux runners have KVM, so kernel sweeps need no self-hosted pool. (4) The $9 solo baseline pairs with the $200 run, not $124.70. (5) Workflow 1,000-agent limit is a fixed cap; workflows run headless, agent teams do not. ## 35-data-secrets: Data control, secrets handling and information-flow control for agents

Full brief: [35-data-secrets.md](35-data-secrets.md)

The web-search budget was already spent, so this brief rests on primary pages fetched directly and the GitHub API; items from memory are flagged in the file.

No agent protects credential stores by default. Claude Code's sandbox lets commands read the whole machine, including ~/.ssh and ~/.aws/credentials, covers only shell commands, and does not exist on native Windows. That is the cheapest gap to close.

Keeping secrets away from the model has converged on one shape: the agent holds a per-session phantom token and a proxy outside the boundary swaps in the real value for named hosts. Claude Code (experimental, needs TLS termination), nono, Infisical Agent Vault and Fly tokenizer all do it. The standalone open-source Agent Vault now tells users to move to Infisical's platform.

Hooks can redact as well as block: Claude Code PreToolUse rewrites input and PostToolUse replaces tool output. Prompts can be blocked but not rewritten. Cursor hooks fail open unless failClosed is set.

Hostname allow-lists are weak. Anthropic's own docs warn about domain fronting and about allowing github.com. Real control needs method and path rules or TLS termination.

Deterministic information-flow control works in research (CaMeL 77% versus 84% utility at about 2.8x tokens; FIDES 163 injections down to 1) but the public code is dormant since mid-2025. The practical route is session labels with sink gating and human-approved declassification, which Meta's Rule of Two endorses.

Purview is integrable: a Graph v1.0 API returns block verdicts for text, and sensitivity labels are readable key-value metadata. Tenant-restriction headers exist for Anthropic, Microsoft and Google, all needing TLS inspection.

Undo is file-only everywhere and misses Bash and subagent changes. BeyondTrust and Microsoft Defender's endpoint agent protection do little on data or secrets.

Recommended order: protected paths and env scrubbing, then runtime secret redaction, session labels and sink gating, egress proxy, secrets broker, honeytokens, checkpoints, classification connectors, provider posture.

**Design implications**

- Ship a default protected-path list (deny-read credential stores, write-protect agent control files) as managed settings for each agent plus OS-sensor detections, because no agent denies credential reads by default.
- Build the secrets broker around per-session phantom tokens bound to host, method and path; a request carrying the phantom also proves the agent made it, solving shared-credential attribution.
- Prefer base-URL reverse-proxy routes for credential injection and make TLS termination a per-host opt-in, since termination breaks pinned tools and makes us an endpoint root CA.
- Have the broker speak existing helper protocols (AWS credential_process, git credential helper, SSH agent sign-only, Docker and kubectl plugins) over peer-authenticated sockets, never unauthenticated localhost ports.
- Model policy as sources that add labels, sink classes, flow rules and scoped human declassification; treat git push, package publish and LLM provider as first-class sinks.
- Add a quarantine primitive: untrusted reads run in a sink-less sub-session returning only typed low-capacity results, to limit taint creep and approval fatigue.
- Egress rules must support method and path and destination org or repo pinning on allowed hosts; drop UDP from agent processes and resolve DNS only at the proxy.
- Use Kingfisher (Apache-2.0, Rust) in-process for secret detection and reuse sandbox-runtime, nono and Microsoft MXC for isolation; avoid embedding AGPL TruffleHog.

**Surprises**

- Canarytokens now lists an 'MCP Configuration' token type, so honeytokens aimed at agents are already a recognised category.
- Microsoft states content created by Agent 365 agents does not inherit sensitivity labels from source items, and agents are unaware when DLP blocks them.
- Codex uses Microsoft's open-source MXC (MIT, Rust SDK) as its Windows sandbox; MXC also has a UI policy for clipboard and display.
- Microsoft Defender for Endpoint has a preview 'AI agent runtime protection' (Set-MpPreference -AiAgentProtection), Windows only and aimed at prompt injection rather than data.
- ProtectAI's llm-guard repository was archived in July 2026.

**Verifier's corrections**

All ten claims held against primary docs and independent sources (Claude Code CHANGELOG, sandbox-runtime README, Graph docs source, paper HTML, GitHub API). Three things the architect must not get wrong: (1) "Nobody ships IFC" is false: microsoft/agent-framework ships an experimental, maintained FIDES implementation (MIT, Python) worth reusing as a reference. (2) Claude Code is unsandboxed on native Windows, but anthropics/sandbox-runtime already has an alpha Windows backend (srt-win, WFP), so reuse rather than invent. (3) Agent Vault OSS is still maintained and MIT-licensed (ee/ carve-out); the risk is upstream direction, not licence. Minor: NODE_USE_ENV_PROXY also exists in Node 22.21+; BeyondTrust also supports Windows Server 2022+; mask without injectHosts injects on all allowed domains. ## 36-response-operations: Detection and response operations: actions, kill switch, approvals, incidents, hunting

Full brief: [36-response-operations.md](36-response-operations.md)

Web search was unavailable for this run (budget already exhausted), so the brief rests on directly fetched primary docs, specs, papers and GitHub metadata; managed-detection offerings and chat-based approval products were not researched.

Hooks in Claude Code, Cursor, Codex and Copilot CLI all fail open on timeout by default, and their verbs differ (Codex has no "ask"; Cursor honours it only for shell and MCP; Copilot denies it in autopilot). Hooks are good for steering and telemetry, but the enforcement boundary has to be the OS sensor and the gateways.

CrowdStrike's AI Kill Switch (2026-11-03) currently only directs AI gateways to block model access; endpoint termination, identity revocation, SaaS and browser containment are "coming soon". Microsoft's local-agent runtime protection is Windows-only preview, built on vendor hooks plus network inspection, with a Disabled/Audit/Block rollout. BeyondTrust offers allow/audit/hold/block on Windows and macOS and can replay recorded activity against a policy before saving it.

Approvals rendered in the agent's own UI are forgeable (Lies-in-the-Loop), and users accept 93% of prompts. The usable building blocks are CIBA with a binding message, MCP URL-mode elicitation, and platform-authenticator confirmation bound to an action digest. AWS's Dogwood (Apache-2.0, Rust, Cedar superset) shows approvals expressed as session-history policy.

LLM reviewers are measurably weak (best SHADE-Arena monitor AUC 0.87; auto mode misses 17% of real overeager actions) and can be injected through the agent's output. Anthropic's classifier therefore sees only user messages and tool calls.

For the data model, OCSF 1.9.0 Incident Finding, CAEP 1.0 revocation events and CACAO playbooks are ready to reuse. Sigma, Splunk contentctl and attack_range, and Atomic Red Team are reusable for the detection lifecycle; Elastic's rules are ELv2.

The Windows and macOS actuator mechanisms in the action matrix are from prior knowledge, not re-verified today, and each needs a spike.

**Design implications**

- Treat in-agent hooks as steering and telemetry; put hard enforcement in the OS sensor and gateways. Ship hooks fail-closed where supported, decide locally over a socket, and alert when a configured hook did not fire for an observed tool execution.
- Define one signed ResponseAction contract with per-control-point actuators that declare capabilities, so verbs like ask, redact or pause degrade predictably per agent (for example Codex: deny with hint and hold at the gateway).
- Build the kill switch as multi-point and scoped (session to tenant or provider), delivered over our own push channel with signed, counter-protected commands; fleet-wide scopes need two approver signatures verified on the endpoint.
- Render approval prompts from the canonical tool call in a privileged helper, never from agent text; confirm via platform authenticator or CIBA push bound to an action digest; issue signed, expiring, use-limited grants evaluated by policy.
- Model data as Event, Finding, session-centred Incident, Case using OCSF Incident Finding fields; keep blocked attempts as findings; make suppressions and exceptions objects with mandatory expiry; hash-chain and sign evidence bundles.
- Make simulate, audit, block a per-rule, per-ring rollout with replay over stored history before enablement, and publish precision and recall per rule on an open benchmark corpus.
- Add post-denial evasion analytics from a per-session denial ledger, plus first-seen and rarity baselines per agent, tool, MCP server and egress domain, with a learning window and a parallel early-life rule set.
- Keep LLM reviewers asynchronous and escalate-only, fed structured actions with tool output omitted or quoted; deterministic tripwires on sensor config, transcripts, approval IPC and honey credentials carry the guarantees.

**Surprises**

- CrowdStrike's AI Kill Switch as shipped does not kill anything on the endpoint; it blocks model access at AI gateways, with process termination still on the roadmap.
- MCP's current spec is 2026-07-28 and stateless: elicitation now arrives inside InputRequiredResult with requestState, and the 2025-11-25 -32042 error and elicitationId are gone.
- AWS open-sourced Dogwood (Apache-2.0, Rust), a Cedar superset with temporal operators, so approval-before-action and per-session budgets are expressible as policy.
- Microsoft Defender stops generating near-real-time alerts for an agent once a blocking rule covers it, and Entra's agent risk detections are all offline.
- Claude Code server-managed settings refresh only hourly and fail open on a first failed fetch unless forceRemoteSettingsRefresh is set, so vendor policy channels cannot serve as a kill switch.

**Verifier's corrections**

Defender has two settings: -AiAgentProtection (hooks) and -AiAgentNetworkInspection (network); only the first deploys via Intune template. Claude Code auto mode does not terminate at 3/20 denials: it falls back to prompting, and headless runs keep going; the classifier also reads CLAUDE.md. Windows has no documented job-wide suspend, WFP filters by app path and user rather than process tree, and macOS Endpoint Security AUTH deadlines rule out holding for human approval. SSF 1.0 does not itself mandate signed SETs; enforce it ourselves. Elastic License v2 allows redistribution but not relicensing or hosted offerings. CrowdStrike's press release claims more present-tense endpoint capability than its blog. Web search was unavailable; checks used direct fetches and gh.

## 37-sensor-engineering: Endpoint sensor engineering: architecture, self-protection, updates, threat model

Full brief: [37-sensor-engineering.md](37-sensor-engineering.md)

Web search budget was exhausted before I started, so this brief rests on directly fetched primary docs and GitHub; items from prior knowledge are tagged [PK] in the file. The adversary is new: a user-privileged agent that reasons around controls. Ona (March 2026) documents Claude Code defeating a path denylist via /proc/self/root, disabling its sandbox, then beating an in-kernel exec hash gate by invoking ld-linux. Path identity and exec-only gates are insufficient. Agent hooks fail open: in Claude Code only exit 2 blocks, and HTTP hook failures are non-blocking unless onFailure is "block". Managed hooks live in admin-owned paths and cannot be disabled by user settings, but Anthropic states a local admin can edit them. So hooks hold against a user-level agent, not an administrator. CrowdStrike's 2024 outage was a validator/interpreter mismatch (21 fields defined, 20 supplied), a missing bounds check, wildcard-only tests and unstaged content. Defender's 2018 split (privileged service plus sandboxed content process) is the model to copy. Windows antimalware PPL requires an ELAM driver, so an open-source build cannot stop an administrator; even PPL products fall to EDR-Freeze and EDR-Redir (both 2025, admin, no driver). Elastic has no Linux self-protection and Defender's Linux tamper protection is audit-only. Design for prevention against user-level agents and detection against admins. Microsoft Defender now ships local agent discovery (GA, named-agent list) and runtime protection (preview, Windows only) via vendor hooks plus network inspection, which fails on certificate pinning and HTTP/3. Bespoke agents, Linux endpoints, Windows on Arm, broker-based lineage escape and unforgeable approvals are open ground. Recommended: minimal privileged core, sandboxed analyzer, single network process, tiny updater, untrusted hook shim and UI; a pure policy/detection library with C and WASM bindings; TUF-style signed A/B updates with rings and a crash-loop ladder. Not verified: current status of the Windows user-mode endpoint security platform.

**Design implications**

- Split the sensor: minimal privileged core handling fixed-layout events only; a sandboxed low-privilege analyzer parses all untrusted content; one unprivileged process owns network egress; a tiny on-demand updater verifies signatures.
- Ship a hook shim that exits 2 when the sensor is unreachable in enforce mode, referenced by absolute root-owned path from managed settings, because agent hook failures otherwise fail open.
- Cross-validate layers: raise a hook-bypass detection when the OS sensor sees tool-like activity from an agent tree with no matching hook event in a short window.
- Enforce on content hash and code loading (mmap-exec, interpreters, dynamic loader), not paths or execve alone; deny agent trees access to broker sockets such as Docker, systemd user and Task Scheduler by default.
- Treat rules and policy as code: one generated schema, the production interpreter run in CI on every artifact, on-device trial load in the sandbox, staged rings, customer pinning, and a crash-loop ladder that disables content before rolling back binaries.
- Target prevention against user-privileged agents and detection against administrators: server-side heartbeat gaps, uninstall tokens, hash-chained spool, suspension and bind-link monitoring; offer PPL only through an embedding MVI vendor.
- Make the policy and detection core a pure deterministic library (no I/O, injected clock) with C ABI and WASM builds so EDR vendors can embed it and so policy replay against recorded activity is possible.
- Keep the UI non-load-bearing and default-deny when absent; require approvals an agent cannot forge (secure desktop or higher integrity on Windows, Touch ID on macOS, polkit on Linux, or out-of-band).

**Surprises**

- Microsoft Defender already uses Claude Code and Copilot vendor hooks for inline blocking on Windows (preview), and inventories about fifty named local agents on Windows and macOS as GA.
- Anthropic's own docs concede a local administrator can edit managed settings; hook enforcement is only a boundary against non-admin agents.
- Two 2025 techniques disable PPL-protected EDRs from user mode with admin rights and no vulnerable driver, so PPL is not the end state for self-protection.
- Tetragon's docs warn SIGKILL does not always stop the triggering operation; Santa blocks execve only and ignores scripts, dlopen and DYLD_INSERT_LIBRARIES.
- BeyondTrust's agent product skips Windows on Arm and Linux endpoints and needs a tenant root CA for HTTPS inspection.

**Verifier's corrections**

Hooks: exit 0 plus JSON deny also blocks; onFailure:block needs Claude Code v2.1.295+ and does not cover async hooks. Managed settings: only the highest-ranked source applies by default, so install hooks via managed-settings.d and detect shadowing by server-managed or MDM policy; HKCU and WSL /etc/claude-code are user-writable. Ona case: the operator told the agent to find a way and approved the unsandboxed run, so it evidences approval fatigue, not autonomous sandbox escape. osquery's 10% CPU is of all cores. Windows drivers: attestation signing is testing-only and Server 2016+ requires HLK/WHCP. Defender lists about 60 agents, not 50. Web search was unavailable; checks used direct fetches and gh.

## 38-network-gateways: Network control: endpoint proxy, AI gateway, MCP broker, egress control, browser extension

Full brief: [38-network-gateways.md](38-network-gateways.md)

No web searches were possible (shared quota exhausted); findings come from directly fetched primary docs and the GitHub API, and are tagged verified/knowledge/inference in the brief. Market leaders ship both placements: CrowdStrike Falcon Guardian (renamed AIDR) has agent hooks and an AI gateway GA, but endpoint network inspection is still pre-beta (2026-11-03); BeyondTrust is endpoint-only with a tenant root CA, Windows and macOS only. Recommend an endpoint proxy plus a central gateway sharing one Rust parser and policy core. Steering needs three tiers: per-tool config (Claude Code can be pinned to a gateway with allowedProviders and trusts the OS cert store by default), sandboxing that removes other routes (Anthropic srt: bubblewrap without netns, Seatbelt, Windows WFP filters keyed on a sandbox user SID, no driver), and transparent redirection (WFP connect-redirect driver, macOS NETransparentProxyProvider, Linux cgroup eBPF). Runtime trust stores are inconsistent: Node needs NODE_USE_SYSTEM_CA or NODE_EXTRA_CA_CERTS and NODE_USE_ENV_PROXY; Deno defaults to Mozilla roots. MCP 2026-07-28 is stateless with mandatory Mcp-Method and Mcp-Name headers, server/discover and deterministic tools/list, which suits gateways and tool pinning; no gateway documents description hash-pinning. For the central gateway reuse agentgateway (Rust, Apache-2.0, v1.7.0, AAIF). Avoid LiteLLM: 18 advisories in 2026, five critical, plus a PyPI compromise. TensorZero is archived; envoyproxy/ai-gateway now redirects to theagentrouter/agent-router. Every MCP gateway shipped authorization bypasses in 2026 (fail-open CEL, cross-route sessions, canonicalisation gaps), so a fail-closed core with a conformance suite is a differentiator. Codex's Apache-2.0 Rust network proxy (MITM hooks, credential substitution, limited mode) is the best reference for the endpoint proxy. MV3 extensions cannot read response bodies or WebSocket frames via webRequest; page-context instrumentation is needed. Honest limits: server-side connectors, SigV4 bodies, pinned apps, QUIC/ECH in transparent mode, local admins.

**Design implications**

- Build one Rust core crate (provider, MCP and A2A parsers, normalised events, policy, redaction) compiled into endpoint proxy, gateway extension, MCP shim and WASM for the browser; this is also the embeddable artefact for EDR vendors.
- Use agentgateway as the central data plane and attach our policy through its remote guardrail (ExtMCP) and authorization hooks; ship thin collectors for LiteLLM, Kong and Portkey instead of building on them.
- Phase steering: first managed settings, env injection and user-mode WFP/Seatbelt/bubblewrap route removal; later a signed WFP connect-redirect driver, macOS transparent-proxy system extension and Linux cgroup eBPF for unregistered agents.
- Endpoint agent must inject CA and proxy variables per process tree (NODE_EXTRA_CA_CERTS, NODE_USE_SYSTEM_CA, NODE_USE_ENV_PROXY, DENO_TLS_CA_STORE, SSL_CERT_FILE), not only install a root; keep the CA key memory-only or non-exportable and MITM selectively.
- Ship the stdio MCP wrapper as a static Rust binary with no runtime fetch (unlike npx-based shims); evaluate Cedar policies with nested-argument support and pin canonical tool-definition hashes per server identity.
- Make policy fail closed everywhere: canonicalise names, URIs and numbers, bind session state to route and principal, bound upstream-controlled stream indexes, reject duplicate JSON keys, verify Mcp-Name header against body, dial the vetted IP.
- Parse first: Anthropic Messages, OpenAI Responses then Chat Completions, MCP 2025-06-18/2025-11-25/2026-07-28, Gemini, Bedrock Converse event streams; then A2A 1.0 and Realtime WebSocket.
- Browser extension must be force-installed MV3 with page-context wrappers for fetch, XHR, WebSocket and EventSource plus declarativeNetRequest blocking and native messaging to the endpoint agent; treat Chrome's Content Analysis Connector as optional.

**Surprises**

- CrowdStrike AIDR is now branded Falcon Guardian, and its endpoint network inspection was still pre-beta on 2026-11-03; only hooks and the gateway are available.
- TensorZero's GitHub repository is archived, and envoyproxy/ai-gateway redirects to a project called Agent Router under a different organisation.
- MCP 2026-07-28 dropped sessions, the initialize handshake, SSE resumability, and deprecated sampling, roots, logging and Dynamic Client Registration.
- Amazon Bedrock accepts bearer API keys, so SigV4 body signing is no longer the only path and bodies can be altered when keys are used.
- OpenAI Codex ships an Apache-2.0 Rust local proxy with HTTPS MITM hooks, credential substitution and a read-only network mode.

**Verifier's corrections**

Web-search quota was exhausted; verdicts rest on direct reads of primary docs, GitHub, OSV, PyPI and npm. Four corrections. (1) MCP 2026-07-28: deterministic tools/list order is only SHOULD, and Mcp-Name applies only to tools/call, resources/read, prompts/get, so pinning cannot assume stable order. (2) sandbox-runtime on Linux uses bwrap --unshare-net (a new empty network namespace), not "no namespace"; its Windows mode is alpha and breaks Schannel clients. (3) The webRequest limits are Chromium-only; Firefox exposes response bodies via filterResponseData. (4) NODE_USE_ENV_PROXY dates from Node v24.0.0, not v24.5.0. Also: LiteLLM's 18 advisories is a floor, and Agent Router is an AAIF project.

## 39-ai-ml-strategy: AI and ML inside the product: trace review, baselines, agent classifier, assistants

Full brief: [39-ai-ml-strategy.md](39-ai-ml-strategy.md)

Web search was unavailable (shared budget exhausted before I started), so this rests on direct fetches of primary sources, GitHub and Hugging Face APIs, local source captures and sibling briefs. LLM trace review is now a shipped pattern with a two-pass shape: Origin 1.12.5 (30 Sep 2026) reviews traces against policies, norms and inferred intents, then a Triage pass re-verifies each finding with quoted evidence; Origin runs its own inference. Uber's open ADR is the only source of production numbers: LLM triage then a reasoning agent with MCP context tools, USD 0.024 and 18.5 s per session, and 49% false positives in production despite zero on its benchmark (about USD 1 per host per month at Uber's volume, my calculation). Frontier monitors are weak under attack: Anthropic reports Auto Mode and Codex Guardian fail to block over 55% of red-team attacks, with cheap structural fixes (keyed record framing, monitoring workspace edits, framed tool results) recovering over 50 points; multi-agent and compaction attacks stay open. Heterogeneous ensembles beat single judges (AISI: about 33% worst-case miss to 5.7% at 1% FPR); resampling amplifies monitor injection. Most volume is overeager agents, not attackers (43 to 61% scope drift with no adversary). Recommended: five tiers (rules, small CPU models, LLM finder, LLM verifier with mechanically checked evidence spans, read-only investigator), post hoc by default, with a suspicion-ordered queue under a per-tenant budget. My estimate is USD 0.20 to 0.35 per heavy endpoint per month at today's Anthropic list prices; inline per-action gating should be bring-your-own-model. Ship first: an open agent-process classifier, a tool-output injection encoder, a session risk ranker, stock embeddings and prompt packs, all Apache-2.0. Natural-language policy should copy AWS's validate-and-prove loop and add generated tests plus replay against history. No blocking decision may depend on a model. CPU latency, local-judge throughput and CrowdSec's anti-poisoning internals are unverified.

**Design implications**

- Build review as five tiers: deterministic rules, small CPU models, LLM finder, LLM verifier, read-only investigator. Each tier has a version, a token budget and a published coverage metric.
- A deterministic hit is never cleared by a model. Models may only raise risk, explain, or clear another model's flag; Cedar and OS sensors make every blocking decision.
- Give the judge a strict input contract: trusted policy, user messages and tool calls; untrusted tool results and agent prose wrapped in per-record HMAC-keyed tags and JSON-L escaped.
- Require every finding to carry span offsets into the trace and verify them by string match in code; drop and count findings whose evidence does not match.
- Use a heterogeneous monitor ensemble (action-only plus reasoning-aware) aggregated by a small tree model; never resample one judge until it passes.
- Key review units on workspace and process lineage, including sub-agent handoffs, compaction summaries and agent memory or config writes, not on session IDs.
- Make inline LLM gating bring-your-own-model behind one JudgeBackend trait with a conformance suite; SaaS default is batched post hoc review under a per-tenant budget and suspicion-ordered queue.
- Ship models, prompts and thresholds as signed packs through the same rings as rules, with shadow mode, seeded canary sessions for live recall, and automatic rollback.

**Surprises**

- Uber's detector had zero false positives on its own benchmark and 49% false positives in production; benchmark precision does not transfer.
- Adding untrusted tool results to the monitor's context improved detection and did not raise injection success once records were key-framed, reversing the March 2026 auto-mode design choice.
- Haiku 5.5 lists at USD 0.10 / 0.50 per MTok, so reviewing a 15K-token session costs under 0.2 cents; the constraint is false positives, not judge cost.
- LLM and agent traffic is classifiable from encrypted packet metadata alone (97.7% model, up to 90.7% agent task), so unknown agents can be flagged without TLS interception.
- CrowdSec counts only signals from unmodified official scenarios (hash-compared) toward consensus, and demotes suspected cheaters to a 3,000-IP list.

**Verifier's corrections**

Eight of ten claims held; two need care. (1) The over-50-point attack-success drop is for Auto Mode ++ as a whole, which includes a tool-calling investigator stage on Opus 4.8; framing, edit monitoring and tool results alone are not shown to deliver it. (2) Authorization Drift's 0.43-0.61 is share of runs for six high-performing models (mostly Qwen), not share of tasks for all frontier models; the full range is 0.029-0.605. Also: ADR's published scores are on 302 tasks (42 malicious), not 304/43; ADR cost is per benchmark task, not measured in production; SWE-chat is gated, so CI needs a token; Authorization Drift code is released (MIT). Web search budget was exhausted; all checks used direct primary fetches and APIs.

## g02-edr-class-rivals-docs: Technical-docs teardown of the remaining EDR-class and SASE agent-security products

Full brief: [g02-edr-class-rivals-docs.md](g02-edr-class-rivals-docs.md)

Web search was unavailable (shared budget exhausted), so this brief rests on directly fetched vendor docs and GitHub; about a dozen vendors could not be read and are marked not verified. Among those I could read, agent-native hooks are the convergent enforcement point: Microsoft Defender, BeyondTrust, Cisco DefenseClaw, Noma, Lasso and 1Password all install into Claude Code, Codex, Cursor and Copilot hooks, and nobody documents coexistence. Native Linux endpoints are the clearest hole: Microsoft discovery is Windows and macOS with WSL in preview, and BeyondTrust is Windows x64 and macOS only. Microsoft's runtime protection is preview, Windows only, and detects prompt injection only; its network method fails on certificate pinning and HTTP/3, and Cursor has no runtime row. Cisco ships an Apache-2.0 rival, DefenseClaw, with version-pinned hook contracts for 12 agents, a published fail-mode matrix (closed by default, open under Secure Client) and documented bypasses such as hooks that fail to start. First-party controls are file-based and strong: Claude Code's allowManagedHooksOnly means our hooks must arrive through managed settings; Codex uses requirements.toml. SaaS posture tools from Palo Alto and Check Point are connector lists bounded by platform APIs.

- Adopt version-ranged connector contracts with a published per-connector fail-mode table and a doctor check for hooks that fail to start, then cross-check hooks against OS sensor events.
- Discover agents by behaviour (LLM API connections, tool and MCP spawning, config files) instead of process-name lists, which Elastic, Sysdig and Microsoft all rely on.
- Write detection content against a normalised schema with adapters for SentinelOne Cloud Funnel, Defender XDR, Sysmon and Falco; this is the embed path for EDR vendors.
- Reimplement rather than copy Elastic's GenAI rules (Elastic License v2); Falco and Cisco's Quarry DSL are Apache-2.0 and reusable.
- Decide policy locally, default to fail-closed, avoid mandatory TLS interception, and offer free OTLP and OCSF export plus ingestion of GitHub, Anthropic, Cloudflare and Docker logs.

**Surprises**

- Cisco already ships an Apache-2.0 hook-and-gateway product (DefenseClaw) covering 12 coding agents, with a public fail-mode matrix and bypass list.
- Microsoft's endpoint runtime protection only detects prompt injection; it is not a general action policy engine, and is Windows-only preview.
- Elastic's agent detection content is designed to run over SentinelOne and Microsoft Defender telemetry, not just Elastic Defend.
- Cisco's enterprise distribution (Secure Client) defaults hooks to fail-open, the opposite of its standalone default.
- Lakera's docs site is now branded as the Check Point AI Defense Plane, with device agents handled by a separate Workforce AI Security product.

**Verifier's corrections**

Linux/Arm hook enforcement is not whitespace: falcosecurity/prempti (Apache-2.0, Sysdig-originated) does allow/deny/ask on Linux, macOS and Windows including arm64, and DefenseClaw runs on Linux. The open gap is kernel-level Linux enforcement. DefenseClaw is not uniformly fail-closed: per-user installs on the default rule pack let calls run with a warning when the gateway is down; latest release is 1.0.8, not 1.0.4. BeyondTrust needs the root certificate on macOS too, and Windows support is "Server 2022 or later". Codex requirements arrive via MDM key requirements_toml_base64, not config_toml_base64, and Codex has its own allow_managed_hooks_only. Windows agent workspace is real but still opt-in preview: agents run under separate local agent accounts (names end in $) in their own session, so attribution there is a token/session check. It only covers Copilot-style agents and MSIX-packaged MCP servers reached through the on-device registry (ODR); Claude Code, Cursor, Codex and bespoke agents still run as the user, so lineage heuristics remain necessary. Windows now has agent-connector policies (AgentConnectorAccessPolicy host-to-server allowlist, ConfigureAgentConnectors, AgentConsentDuration, OnDeviceRegistryLoggingLevel) but Enterprise/Education only and still flagged Insider Preview. 26H2 ships readable event channels (Microsoft-Windows-AgentConnector-*, Microsoft-Windows-AI-ModelContextProtocol) with free-text payloads. ACP (Agent Client Protocol) is the best single shim: JSON-RPC over stdio, v1.30.0, Apache-2.0, about 50 agents and clients including Zed, JetBrains, Neovim and Xcode 27; an upstream proxy-chains RFD defines a conductor pattern. It observes everything but enforces only what agents delegate (fs/*, terminal/*) or choose to ask about. WebMCP is a W3C CG draft in origin trial (Chrome 149, Edge 150) using document.modelContext, with no observer API or enterprise policy. Browser agents are governed by vendor policies (Chrome Gemini*, Edge CopilotBrowserUse*). macOS 27 adds no agent identity and removes direct TCC database access. Microsoft Defender already discovers local agents and MCP servers on Windows and macOS and has preview runtime protection; BeyondTrust does kernel plus network enforcement with TLS interception. Neither covers Linux. Web Bot Auth is now an IETF WG draft; AP2 is v0.2 under FIDO.

**Design implications**

- Add a declared-inventory layer to discovery: ODR listings, MCP AppExtension registrations, ACP registry JSON, editor ACP configs, browser managed-policy state. Diff against observed processes to produce the shadow-agent report.
- Make attribution carry its basis (os_agent_account, sandbox_principal, protocol_asserted, lineage_inferred, traffic_inferred) so policy can require a minimum evidence strength rather than trusting one heuristic.
- Build an ACP conductor in Rust on the official crate: transparent stdio proxy that logs tool_call updates, mediates session/request_permission, and enforces on fs/* and terminal/*. Publish it as a registry wrapper.
- Do not rely on ACP or Windows agent workspace for enforcement of third-party agents; keep in-agent hooks and OS sensors as the primary pre-action control, with ACP as observation plus partial veto.
- Ship a Windows event collector for AgentConnector and ModelContextProtocol channels behind a capability probe, storing raw events because payloads are unstructured and the feature is still preview.
- Compile our policy model down to native controls where they exist: AgentConnectorAccessPolicy JSON, Chrome GeminiActOnWeb URL lists, Edge CopilotBrowserUse lists, macOS PPPC profiles; our sensors cover Pro editions and gaps.
- Build a browser extension sensor that wraps document.modelContext.registerTool in the main world, listens for toolactivated, and reports CDP attachment, since WebMCP has no audit hook.
- Treat synthetic-input signals as evidence only: injected-input flags, CGEvent source PID, uinput opens and remote-debugging switches miss UI Automation and accessibility-pattern automation. On macOS use Endpoint Security, never TCC.db.

**Surprises**

- Windows 11 26H2 (10.0.26300) already ships AgentConnector and ModelContextProtocol event channels and ETW providers inbox on Pro, even with agentic features disabled and odr.exe absent.
- Xcode 27 added Agent Client Protocol support, agent plug-ins and a filesystem security layer for coding agents, so ACP now spans Zed, JetBrains, Neovim and Apple's IDE.
- WebMCP moved from navigator.modelContext to document.modelContext, and the declarative form API (toolname, agentInvoked) was dropped from the spec into a separate explainer.
- AP2 renamed its mandates to Checkout and Payment Mandates with Open/Closed stages and was donated to the FIDO Alliance; Web Bot Auth became an IETF working-group document in October 2026.
- Microsoft Defender's runtime protection uses vendor hook interfaces first and network inspection as fallback, and Chrome's own GeminiSparkSettings text warns existing security controls might not be respected.

**Verifier's corrections**

Web search budget was exhausted; verdicts rest on direct primary fetches and GitHub API reads. Three things must not be carried forward. (1) WebMCP is not awaiting Safari/Firefox positions: WebKit formally opposes it and Mozilla is neutral, so design for Chromium only. (2) Do not build ACP enforcement on fs/* and terminal/*: ACP v2 removes them (and the tool_call notification), and v1 adoption was low. (3) The official Rust SDK crate is agent-client-protocol 5.1.0, not 1.16.0 (that is the schema crate), and it already ships a conductor crate to reuse. Minor: the registry has 45 agents, schema-v1.30.0 belongs to the protocol repo, and the remote-transport RFD is in the Active stage. The verification table is appended to the brief.

## g10-saas-ops-day2-economics: Operating the hosted service and self-hosted day-2: SRE, metering, billing, support and unit economics

Full brief: [g10-saas-ops-day2-economics.md](g10-saas-ops-day2-economics.md)

Web search was unavailable (shared budget exhausted), so this brief rests on direct fetches of primary docs and GitHub; cost outputs are my arithmetic on stated assumptions, not measurements.

LLM review, not storage, drives cost. With agent-scoped edge filtering (~5,000 events/endpoint/day, 10x compression) storage is cents per endpoint-month on ClickHouse Cloud list prices ($25.30/TB-month, $0.298/CU-hour Scale). Modelled COGS is about $0.40-$0.90 per endpoint-month with platform model keys, of which 65-80% is LLM spend, at 10, 1,000 and 50,000 endpoints alike. Reviewing every tool call costs ~$2.50 (Haiku 5.5) to ~$47 (Sonnet 5.5) per heavy endpoint-month, so deterministic policy first, a 1-5% escalation slice, caching, batch, and customer-supplied keys are structural requirements. The free tier is only safe on customer keys.

For billing, only OpenMeter (Apache-2.0, still beta, needs Kafka+ClickHouse+Postgres, hosted arm now inside Kong) and Kill Bill (Apache-2.0, JVM) are permissive; Lago, Flexprice and Meteroid are AGPL-3.0 and unsuitable for an embeddable product. Recommend a native CloudEvents usage ledger with partner→MSP→customer roll-ups and signed statements, with rating/invoicing as adapters.

Published practice: Grafana Cloud contracts only 99.5% with a 300% volume exclusion; GitLab communicates incidents over 5 minutes within an hour and reviews all S1/S2. Skew rules converge: server newest, agents lag (Teleport one major, kubelet three minors), no skipped majors, mandatory upgrade stops. ClickHouse and NATS docs both state replication is not backup; ClickHouse has incremental S3 backups but no PITR. CrowdStrike's RCA and Datadog's 2023 outage argue for a separate ring-based content channel with customer control and no synchronized update windows.

Self-hosted support is whitespace: PostHog calls self-hosting officially unsupported and Sentry does not patch old versions. The file includes the cost-model sheet outline, metering design, draft SLOs and incident process, skew/upgrade policy, DR runbook requirements and an agent/human staffing table. Unverified: EDR vendor SLAs, AICPA criteria text, MSP billing practice, real telemetry volumes.

**Design implications**

- Make token payer a first-class tenant setting (customer key, capped platform key, local model) and meter tokens by key owner; restrict the free tier to customer keys or local models.
- Put a deterministic policy engine and verdict cache before any LLM review, with a per-tenant daily token budget and a defined fallback verdict when the budget is spent.
- Build an append-only CloudEvents usage ledger in core with partner, MSP, customer and site IDs on every row and signed monthly statements; keep rating and invoicing in external adapters (Stripe, Kill Bill, OpenMeter).
- Encode version skew in the sensor handshake: server newest, accepts current plus two prior minors and previous LTS; out-of-range sensors keep enforcing cached policy and raise a health finding.
- Ship three independent release channels (binaries, schema/policy, detection content), each with rings, canaries, pinning, customer-controlled timing and one-command rollback, and never a fleet-wide synchronized update window.
- Use expand/contract migrations across two releases with a machine-readable upgrade-path manifest and a preflight command that refuses unsafe jumps, so binary rollback never needs a database restore.
- At quota, degrade raw-event fidelity by sampling but never drop verdicts, detections or audit records; enforce limits with ingest token buckets, NATS stream byte limits and ClickHouse workloads.
- Provide backup, restore --verify and support-bundle --preview commands from the first self-hosted release; automate quarterly restore drills and capture their output as SOC 2 availability evidence.

**Surprises**

- Elastic Security Serverless dropped per-endpoint fees on 2026-03-23; endpoint protection is now included and billing is ingest ($0.09-0.11/GB) plus retention ($0.017-0.019/GB-month).
- Haiku 5.5 lists at $0.10/$0.50 per million tokens, ten times cheaper than Haiku 4.5, which moves always-on LLM review from impossible to marginal on the cheapest tier only.
- OpenMeter is still beta after 236 pre-releases, its cloud product was absorbed into Kong Konnect, and its repo documents a known under-billing bug in legacy invoicing.
- Microsoft Agent 365 (GA 2026-05-01) is licensed per user, not per agent, and needs only one licensed user to enable the tenant.
- Sentry self-hosted published seven 'versions to avoid' across 2025-2026 for broken migrations, showing how fragile monthly CalVer upgrades are without required-stop tooling.
