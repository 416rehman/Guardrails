# ADR-0044: A code registered before the token check exists gets its tokens from #1853, adopted by RFC 0010

- Status: accepted
- Date: 2026-11-23
- Decided by: chief architect
- Spine: D-61, D-69, P17

- RFC: 0010 ([`rfcs/0010-code-tokens-before-the-token-check.md`](../../rfcs/0010-code-tokens-before-the-token-check.md)), accepted on #1998 (amendment 1 of [RFC 0007](../../rfcs/0007-grdr-model-and-grdr-schema-slice-0-surface.md))

## Context
RFC 0007 section 4 ("Content, not surface", third bullet) lets an item that registers an error code leave its two source-locale tokens (`code.<area>_<nnnn>.message` and `code.<area>_<nnnn>.fix`) to an interfaces item, and then blocks the registering item by that interfaces item so the token check never fails on `main`. That token check is #1853 R2, which is not yet on `main`, and #1853 waits on #1613, #449, #1612 and the RFC on #448. Under [ADR-0041](ADR-0041-the-grdr-model-slice-0-surface-adopted-by-rfc-0009.md) (RFC 0009 constraint 5, from ruling D5 on #1850), #1853 writes the tokens of every `GRDR-MODEL` code registered when it is worked, and #383 (`priority:p0`), #1986, #1994 and #1995 register their codes and write none. Keeping RFC 0007 section 4's blocking active before #1853 R2 lands on `main` held those slice-0 `MODEL` items behind the interfaces chain even though nothing on `main` checks or renders code tokens before #1613 and #1853 land ([RFC 0010, Motivation](../../rfcs/0010-code-tokens-before-the-token-check.md#motivation)).

#1982 (RFC 0009 and ADR-0041) landed on `main` in commit `0fde8bc`. ## Decision
**Accepted.** RFC 0010 (amendment 1 of RFC 0007) is accepted on reviewed RFC file blob `74616992ad270de277a20272eeeffd5dc9858c91` (accepted file blob `43cbdb3c08933783ce089f4e768f55771f1e9607`) against spine pin `a80859235e7a2a4444648d6fa8d389d78dde6be9` ([RFC 0010, Design](../../rfcs/0010-code-tokens-before-the-token-check.md#design)). In outline:
- **R1 (amended RFC 0007 section 4 sentence).** Once the token check (#1853 R2) is on `main`, an item that registers a code and writes no tokens is blocked by the interfaces item that writes them; before then, #1853 R1 writes the tokens of every code registered when #1853 is worked, so the check never fails on `main`.
- **R2 and R4 (unchanged scope).** Everything else in RFC 0007 stands: self-authored tokens in `interface/strings/src/code.mf2.toml`, `eval-ux`, `impl-l10n` under D-69, token ids `code.<area>_<nnnn>.message` and `.fix`, `grdr-schema`'s `experimental` class, section 12's missing-token failure row, and design/34 F2 `/codes/<code>` pages through #1636.
- **R3 (slice-0 `MODEL` items, extended to #1986).** #383 (`0001` to `0005`), #1995 (`0006`), #1986 (`0007` to `0009`) and #1994 (`0010` and `0011`) are blocked by #1998 until #1998 closes on merge, and by neither #1614 nor #1853; #1853 writes their `code.<code>.message` and `code.<code>.fix` tokens with the text of RFC 0009 constraints 2a, 2b and 2h and RFC 0007 constraint 2f when worked.
- **R5 (window merge order).** While #1853's pull request is open, #1853's pull request and every open code-registering pull request merge only from a head that contains `main`'s tip (`git merge-base --is-ancestor origin/main <head>`), closing the race left by `main`'s non-strict ruleset (`strict_required_status_checks_policy: false`).

**No pin and no evidence.** RFC 0010 decides no pinned path, so its Decision section holds no decision line, `rfcs/pins.toml` is unchanged, nothing is added under `rfcs/evidence/`, and `rfcs/0007-grdr-model-and-grdr-schema-slice-0-surface.md` is not edited ([RFC 0001, "RFC states"](../../rfcs/0001-adopt-the-spine.md#design); [ADR-0036](ADR-0036-the-amended-spine-is-the-baseline-adopted-by-rfc-0001.md), "Evidence added in route"; [ADR-0038](ADR-0038-the-grdr-model-and-grdr-schema-slice-0-surface-adopted-by-rfc-0007.md)).

**Constraints.** The decision binds the eight constraints of [RFC 0010, Constraints](../../rfcs/0010-code-tokens-before-the-token-check.md#constraints):
1. **R3 covers all four `MODEL` registering items (`#1998` comment `7095847020`, `eval-architecture` minor 2, `eval-api` minor 1, `eval-adversarial` m2).** R3 binds `#383`, `#1986`, `#1994` and `#1995` explicitly, plus `#1853`. Unblocking of `#383`, `#1986`, `#1994` and `#1995` from `#1998` occurs only after `#1998`'s decision pull request merges.
2. **Failure mode row 3 exit when `#1853` lands first (`eval-api` minor 1, `eval-architecture` minor 1, `eval-adversarial` m2).** `#1853` is not linked as blocked by `#383`, `#1986`, `#1994` or `#1995` (which would hold `#1925` and `#427` behind `#1986`'s `#17`, `#394`, `#284` chain). Instead, if `#1853` R2 lands on `main` before any of those four items (or for any code registered after `#1853` lands without tokens), the lead of the first affected registering item to meet the landed check files an `interfaces` item (`squad:interfaces`, at the registering item's priority, `priority:p0` for slice-0 `MODEL` items) to write the missing tokens in `interface/strings/src/code.mf2.toml` (under RFC 0009 constraints 2a, 2b, 2h and RFC 0007 constraint 2f) and blocks the unlanded registering item(s) by it (or, with `lead-interfaces`'s acceptance, writes them in the registering pull request under RFC 0007 section 4's first clause). Binds `#1853`, `#383`, `#1986`, `#1994`, `#1995` and their leads.
3. **R5 path trigger, decision-time item list, and lapse (`eval-api` minor 3, `eval-architecture` minor 4, `eval-adversarial` m3, `eval-security` minor 1, `persona-simplicity` minor).** During the R5 window, a registering pull request is identified mechanically by `git diff --name-only origin/main...<head> -- schema/codes/` returning any path (covering every code area and future items). Open items touching `schema/codes/` or slice-0 code registration at decision time are `#383`, `#1986`, `#1994`, `#1995`, `#278`, `#279`, `#370`, `#667`, `#1028`, `#1742`, `#1829`, `#1968` and `#1978` (plus `#1925` and `#427` if touching `schema/codes/`). At `#1853`'s merge, the orchestrating session lists open pull requests touching `schema/codes/` (`gh pr list --state open --json number,files`) and posts R5 on any still open that lacks it. R5 lapses permanently once `#1853`'s pull request has merged and every pull request touching `schema/codes/` open during `#1853`'s open window has either merged (on a head containing `#1853`'s merge commit) or closed. Binds `#1853`, the open code-registering items and the orchestrating session.
4. **R5 serial merge execution, check order, post-merge verification and row 2 causes (`eval-api` minor 2, `eval-architecture` minor 3, `eval-adversarial` m1, `eval-security` minor 2).** While `#1853`'s pull request is open, `#1853` and every pull request matching Constraint 3's `schema/codes/` test merge strictly one at a time (never in parallel subagents or batches). Immediately before each `gh pr merge --squash --match-head-commit <sha>` (and after `gh pr checks <pr> --watch`), the orchestrating session runs `git fetch origin main` (exit 0), verifies `origin/main` matches `gh api repos/416rehman/Guardrails/git/ref/heads/main --jq .object.sha`, and verifies `git merge-base --is-ancestor origin/main <head>` (exit 0). Any rebased high-tier pull request re-runs both CI gates and its required evaluators on the new head. After each merge, the session checks the `verify` push run on `main` before starting the next merge in the set, opening Failure mode row 2's `priority:p0` interfaces exit if `main` fails. Interleaved parallel merges, unchecked stale fetches, and manual out-of-session merges are row 2's causes. Binds `#1853` and the orchestrating session.
5. **Temporary `CONTRIBUTING.md` window notice (`persona-contributor` seat 7, change 1).** When `#1853`'s pull request opens, `lead-security` adds one line to `CONTRIBUTING.md` (naming `RFC: 0010` if `rfc-required` is active) noting that open pull requests changing `schema/codes/` may be asked to rebase onto `main` under R5 while `#1853` is open, and removes it when R5 lapses under Constraint 3. Binds `lead-security`.
6. **Check diagnostic naming both contributor paths (`persona-contributor` seat 7, change 2).** `#1853` R2's missing-token error names the code, the locale, and both contributor options: writing the two source-locale tokens in `interface/strings/src/code.mf2.toml` (with `eval-ux` review) or opening/linking an `interfaces` work item (`squad:interfaces`). Binds `#1853`.
7. **Token length budgets and safety risk (`persona-intl` seat 9 condition).** `#1853` R1 preserves `max` and `risk` (`risk = safety`, beside `desc` per RFC 0007 constraint 2f and RFC 0009 constraint 2h) on all `code.<area>_<nnnn>.message` and `.fix` tokens so `en-XA`, `ar-XB` and `ja-XC` checks hold from day one. Binds `#1853`.
8. **R5 scope outside Summary and Surfaces changed (`eval-architecture` minor 5).** Summary and Surfaces changed stay byte-identical to `7461699` and omit R5 because R5 is a bounded orchestrator merge rule rather than an edit to RFC 0007 or `grdr-schema`.

**What this acceptance binds.** RFC 0007 section 4's amended blocking rule and R1 to R4 change only by a new RFC naming both RFC 0007 and RFC 0010 ([RFC 0007 section 11](../../rfcs/0007-grdr-model-and-grdr-schema-slice-0-surface.md#11-stability); [ADR-0038](ADR-0038-the-grdr-model-and-grdr-schema-slice-0-surface-adopted-by-rfc-0007.md)). R5 binds the orchestrating session for `#1853`'s open-PR window only and lapses per Constraint 3.

## Enforced by
- **Before `#1853` lands:** no token check runs on `main`, and no surface reads or renders code tokens before `#1613` and `#1853` land.
- **On `#1853`'s pull request:** `#1853` R2 and R3 (`grdr-interface-gen` checking every active code in `grdr_schema::codes::ALL` on the merge with base), with Constraints 6 and 7 checked on `#1853`'s pull request.
- **During `#1853`'s open-PR window (R5):** the orchestrating session holding Constraint 3's `schema/codes/` diff test (`git diff --name-only origin/main...<head> -- schema/codes/`), Constraint 4's serial merge order, live-tip `is-ancestor` check after `gh pr checks --watch`, and post-merge `verify` inspection on `main`, plus `lead-security`'s temporary notice in `CONTRIBUTING.md` (Constraint 5). Until automated in `grdr-work-issue`, R5 holds by review and session execution.
- **After `#1853` lands:** RFC 0007 section 4's amended blocking rule, the CI `grdr-interface-gen` token check, and the Failure modes row 2 and row 3 exits (`priority:p0` interfaces item / registering-lead exit under Constraint 2).

## Consequences
- Closing `#1998` upon merge unblocks `#383`, `#1986`, `#1994` and `#1995` from `#1998` (each remains blocked by its own non-token prerequisites such as `#1984`, `#278`, `#284`, `#394` and `#17`) without waiting on `#1614` or `#1853`.
- Any code registered on `main` before `#1853` lands lacks source-locale tokens until `#1853` lands; no surface renders them before `#1613` and `#1853`.
- Keeping `#1853` unblocked by `#1986` leaves `#1925` and `#427` off `#1986`'s dependency chain; if `#1853` lands before any of `#383`, `#1986`, `#1994` or `#1995`, Constraint 2 supplies the `priority:p0` interfaces-item exit.
- During the R5 window, pull requests touching `schema/codes/` and `#1853` merge serially rather than in parallel batches, and any rebased high-tier registering pull request re-runs both CI gates and its required evaluators. Once the window closes, R5 lapses permanently.

## Alternatives rejected
- Those of [RFC 0010, Alternatives](../../rfcs/0010-code-tokens-before-the-token-check.md#alternatives).
- A pin record or evidence files: RFC 0010 decides no pinned path, so adding either is out of route ([RFC 0001](../../rfcs/0001-adopt-the-spine.md#design); [ADR-0036](ADR-0036-the-amended-spine-is-the-baseline-adopted-by-rfc-0001.md)).
- Editing RFC 0007 directly, or altering RFC 0010's reviewed `Summary`, `Design` or `Surfaces changed`: RFC 0001 ("Review binds the decision", "RFC states") and RFC 0008 constraint 4d forbid editing an accepted RFC or changing reviewed body lines after review (`eval-architecture` minor 5).
- Linking `#1853` as blocked by `#383`, `#1986`, `#1994` and `#1995` (`eval-adversarial` m2 option (a), `eval-architecture` minor 1 first option): rejected because it places `#1925` and `priority:p0` `#427` behind `#1986`'s `#17`, `#394` and `#284` chain.
- Pre-writing tokens in `#1853` for unregistered `MODEL` codes (`eval-adversarial` m2 option (b)): rejected because `#1853` R2 validates `codes::ALL` and `#1853` has no acceptance criterion permitting orphan tokens; Constraint 2 handles the `#1853`-first order without weakening the check.
- Editing `CONTRIBUTING.md` inside `#1998`: outside `#1998`'s write set and premature while `#1853` remains blocked by `#1613`; delegated to `lead-security` for `#1853`'s open window (Constraint 5).

## Revisit when
- A verdict by an evaluator of RFC 0010's review fails `7461699`, or a later comment shows a defect in RFC 0010; either opens a new RFC (`docs/design/30` section 3).
- `#1853` has merged and every pull request touching `schema/codes/` open during its window has merged or closed, at which point R5 lapses and `lead-security` removes the temporary `CONTRIBUTING.md` notice.
- RFC 0007 section 4's token-writing or blocking rules are changed again by a later amendment naming RFC 0007 and RFC 0010.
