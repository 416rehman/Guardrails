# ADR-0045: Every OS call needing unsafe and every raw OS binding crate lives in a layer 3 OS adapter crate

- Status: proposed
- Date: 2026-11-23
- Decided by: chief architect
- Spine: D-20, D-63, P5, P17; R-50
- Requires: #1749 (`grdr-os-service` and `grdr-peer-os` scaffold, `architecture.toml`, `.claude/owners.toml`, `security/trust-core.paths`), #1750 (`windows-sys` and `libc` admission), #419 (`rustix` admission for Linux and macOS kqueue), #1751 (`ARCH-027` and `ARCH-004` privileged-program coverage check), #1757 (accepted as RFC 0003, [ADR-0051](ADR-0051-the-grdr-wire-slice-0-surface-adopted-by-rfc-0003.md)), #1671 (`docs/design/03` sections 2, 10 and 11 update, synced by `#2011`), #2061 (`grdr-ipc-os` scaffold, `architecture.toml`, `.claude/owners.toml`, `security/trust-core.paths`), #2065 (`grdr-ipc-os` local `Link`, `Connector` and `Acceptor`), #2066 (`ARCH-028` `wire-seams`)
- RFC: not required for the `#1743`/`#1671` ruling itself (preserves `docs/design/03` section 10 without exception and adds only internal layer 3 OS adapter crates with no same-layer edge); public layer 2 seams (`Link`, `Connector`, `Acceptor`, `PeerReader`) and section 15 refinements (`grdr-ipc-os`, link-free `grdr-os-service`, `grdr-wire::peer_auth`) are adopted by RFC 0003 ([`rfcs/0003-grdr-wire-surface.md`](../../rfcs/0003-grdr-wire-surface.md), [ADR-0051](ADR-0051-the-grdr-wire-slice-0-surface-adopted-by-rfc-0003.md))
- Work items: #1743, #1671, #2068; follow-ups #1749, #1750, #1751, #1752, #1757, #2061, #2065, #2066; endpoint items #1724, #1725, #1745, #683, #684, #680, #689, #427, #430; security and adapter items #375, #1549, #555, #516, #374, #1606

## Context

[`docs/design/03-system-architecture-and-modularity.md`](../design/03-system-architecture-and-modularity.md) section 10 forbids `unsafe_code` across workspace crates except in layer 3 OS adapter crates (the optional Windows driver included) and the FFI crates `grdr-ffi` and `grdr-fastpath-ffi`. [`Cargo.toml`](../../Cargo.toml) enforces that rule through `[workspace.lints.rust] unsafe_code = "forbid"`, inherited by `grdr-daemon`, `grdr-hook`, `grdr`, `grdr-wire` and every non-adapter crate via `[lints] workspace = true`.

Endpoint slice-0 items require raw OS and FFI calls that the standard library does not expose safely:

- Service-manager integration and socket activation for `grdr-daemon` on Windows (`StartServiceCtrlDispatcherW`, `RegisterServiceCtrlHandlerExW`, `SetServiceStatus`, `#1724`), Linux (`LISTEN_FDS` descriptor adoption via `OwnedFd::from_raw_fd`, `sd_notify`, signals, `#1745`) and macOS (`launch_activate_socket`, signals, `#1725`, `#683`).
- Named-pipe listener creation with explicit DACLs (`CreateNamedPipeW`, `FILE_FLAG_FIRST_PIPE_INSTANCE`, `PIPE_REJECT_REMOTE_CLIENTS`, `#684`) and child-process handle supervision and exit watching (`pidfd`, kqueue `EVFILT_PROC`, Windows job completion ports and `TerminateProcess`, `#680`, `#427`).
- Bidirectional IPC peer authentication in `grdr-wire` (`peer_auth`) and `grdr-hook` on Linux (`SO_PEERCRED`, `SO_PEERPIDFD`, `pidfd_open`, `#375`), macOS (`LOCAL_PEERTOKEN` and `libbsm` audit-token readers, `#1549`, `#516`) and Windows (`GetNamedPipeClientProcessId`, `GetNamedPipeServerProcessId`, `OpenProcess`, `OpenProcessToken`, `GetTokenInformation`, `QueryFullProcessImageNameW`, `#555`, `#516`), raised in `#1671`.
- Engine sandboxing on Windows (`AppContainer`, job objects, `#689`).
- A requested systemd D-Bus client for Linux per-session transient cgroup-v2 scopes ([`docs/design/10-sensor-linux-containers-ci.md`](../design/10-sensor-linux-containers-ci.md) section 8, `#419`, `#430`).

`docs/design/03` section 2 (`ARCH-002`) forbids dependency edges between layer 3 crates, `R-50` assigns IPC peer authentication to the `security` squad while endpoint hosting belongs to `endpoint`, and `D-63` ([`docs/design/02-threat-model.md`](../design/02-threat-model.md) Interfaces) keeps the privileged core and IPC peer-authentication OS adapters inside [`security/trust-core.paths`](../../security/trust-core.paths). Spine section 5 splits a unit into a crate when it gains a second consumer (`grdr-os-service` serves `grdr-daemon` and user-session services; `grdr-peer-os` serves `grdr-daemon`, `grdr-hook`, `grdr` and `grdr-tray`). Accepted RFC 0003 ([ADR-0051](ADR-0051-the-grdr-wire-slice-0-surface-adopted-by-rfc-0003.md), `#1757`, section 15 applied in `#2068`) refines this boundary by placing local stream `Link`, `Connector` and `Acceptor` implementations in a dedicated layer 3 OS adapter crate (`grdr-ipc-os`) so client programs remain uncoupled from `grdr-os-service`, and by naming the `grdr-wire::peer_auth` seam and entry points (`PeerReader`, `open`, `accept`, `PendingPeer::first_frame`, `check_path`, `resolve`).

## Decision

### 1. Layer 3 OS adapter crates and `unsafe_code` scope

`docs/design/03` section 10 stands with no exception. Every OS call needing `unsafe` and every raw OS binding crate lives in a layer 3 OS adapter crate carrying the OS-adapter lints table (`unsafe_code = "deny"`, a reasoned `#[allow(unsafe_code)]` on each unsafe item, a `// SAFETY:` comment on every `unsafe` block, and `#![deny(clippy::arithmetic_side_effects)]` where `privilege = "privileged"`). Layer 4 programs (`grdr-daemon`, `grdr-hook`, `grdr`, `grdr-tray`) and layer 2 crates (`grdr-wire`) keep `[lints] workspace = true` (`unsafe_code = "forbid"`).

Three internal (`surface = "internal"`, `renders = "none"`) layer 3 crates join `grdr-sandbox-engine`:

| Crate | Layer | Squad | `privilege` | Trust core (`security/trust-core.paths`) | Holds |
|---|---|---|---|---|---|
| `grdr-os-service` | 3 | `endpoint` | `privileged` | Yes, privileged core (beside `grdr-sandbox-engine`) | Service-manager seam (Windows SCM dispatcher, control handler and `SetServiceStatus`; Linux `LISTEN_FDS` adoption and `sd_notify`; macOS `launch_activate_socket`); shared Unix signals; endpoint listener adoption and Windows named-pipe instance creation (owner set to service SID, `FILE_FLAG_FIRST_PIPE_INSTANCE`, `PIPE_REJECT_REMOTE_CLIENTS`, explicit DACL granting only `FILE_READ_DATA \| FILE_WRITE_DATA \| FILE_READ_ATTRIBUTES \| READ_CONTROL \| SYNCHRONIZE`), handing `UnixListener`, `OwnedFd` and `OwnedHandle` out without holding links or being linked by `grdr-hook`, `grdr` or `grdr-tray`; child process handles and exit watching |
| `grdr-ipc-os` | 3 | `endpoint` | `privileged` | Yes, IPC peer authentication (beside `grdr-peer-os`; [ADR-0051](ADR-0051-the-grdr-wire-slice-0-surface-adopted-by-rfc-0003.md)) | Local `Link`, `Connector` and `Acceptor` implementations of `grdr_wire::local` for Unix sockets (`SO_SNDTIMEO`, `poll(2)` with wake pipe) and Windows named pipes (overlapped I/O with `CancelIoEx`, `WaitNamedPipeW`, connect-completion `FileTime` stamp `connected_at`, `SECURITY_SQOS_PRESENT \| SECURITY_IDENTIFICATION` and exact five-right client open mask); wraps adopted `UnixListener` or pipe `OwnedHandle` instances via `grdr-daemon` without creating pipe instances or linking `grdr-os-service` |
| `grdr-peer-os` | 3 | `security` (`R-50`) | `privileged` | Yes, OS adapters of IPC peer authentication | `PeerReader` implementations (`SO_PEERCRED`, `SO_PEERPIDFD`, `pidfd_open`, `fdinfo`; `LOCAL_PEERTOKEN` and audit-token readers; `GetNamedPipeClientProcessId`, `GetNamedPipeServerProcessId`, `OpenProcess`, `OpenProcessToken`, `GetTokenInformation`, `GetProcessTimes`, `GetSecurityInfo`, SCM `QueryServiceStatusEx`, `ImpersonateNamedPipeClient` and `OpenThreadToken(..., OpenAsSelf = TRUE)` inside an RAII `RevertToSelf` guard, `lstat` path walk) plus hold-based lookups (`QueryFullProcessImageNameW`, peer executable path, start time and parent chain) |
| `grdr-sandbox-engine` (exists) | 3 | `endpoint` | `privileged` | Yes, privileged core | Unchanged: engine launch and sandbox confinement on Linux, macOS and Windows |

`grdr-os-clock` (layer 3, `privilege = "none"`, squad `core`, outside `security/trust-core.paths`) remains separate for system clock reads under the one-crate-per-seam rule (`#1927`, `#1933`), with RFC 0003's single recorded exception in `docs/design/03` section 10 for the Windows pipe `connected_at` wall-clock stamp compared solely with `GetProcessTimes` creation time.

The layer 3 adapter crates have no dependency edge to each other (`ARCH-002`). They exchange standard-library listener, descriptor and handle types (`UnixListener`, `OwnedFd`, `BorrowedFd`, `OwnedHandle`, `BorrowedHandle`) and stream types, joined in layer 4 programs: `grdr-daemon` hands adopted `UnixListener`s and Windows pipe instance-source closures (`impl FnMut() -> io::Result<OwnedHandle> + Send` calling `grdr-os-service`) into `grdr-ipc-os` acceptors, while `grdr-hook`, `grdr` and `grdr-tray` link `grdr-ipc-os` and `grdr-peer-os` and never `grdr-os-service`. `grdr-ipc-os` and `grdr-peer-os` each depend on `grdr-wire` (layer 3 to layer 2) to implement `grdr-wire`'s `Link`/`Connector`/`Acceptor` and `PeerReader` seams respectively, and depend on no other workspace crate.

### 2. Placement per call group (R1)

- **Windows service entry (`#1724`):** SCM dispatcher, control handler, `SetServiceStatus` and User-profile session-end sources live in `crates/grdr-os-service/src/windows/service*` over `windows-sys`. `ServiceHost` implementations, status/control state mappings and reporting `RUNNING` before serving the pipe stay in `programs/grdr-daemon/src/platform/windows/service*`.
- **Linux service entry (`#1745`):** `LISTEN_FDS` descriptor adoption (`OwnedFd::from_raw_fd` and socket checks over `rustix`) lives in `crates/grdr-os-service/src/linux/activation.rs`; `sd_notify` writes datagrams over std's `UnixDatagram` in `crates/grdr-os-service/src/linux/notify.rs`; shared Unix signal handling lives in `crates/grdr-os-service/src/unix/signal.rs`. Directory ownership checks (`#148`), configuration name matching and the `Systemd` `ServiceHost` stay in `programs/grdr-daemon/src/platform/linux/service*`.
- **macOS service entry (`#1725`, `#683`):** `launch_activate_socket` is declared in `crates/grdr-os-service/src/macos/activation.rs` inside the crate's own `extern "C"` block (no Rust binding crate exposes it), freeing the returned array with `libc::free`; signal handling reuses `crates/grdr-os-service/src/unix/signal.rs`. Foreground entry, directory checks and the launchd `ServiceHost` stay in `programs/grdr-daemon/src/platform/macos/`.
- **Endpoint listeners and local IPC links (`#683`, `#684`, `#2065`):** `grdr-os-service` adopts (`launch_activate_socket`, `LISTEN_FDS`) or creates (`CreateNamedPipeW` in `crates/grdr-os-service/src/windows/pipe*` with owner set to the service SID, `FILE_FLAG_FIRST_PIPE_INSTANCE`, `PIPE_REJECT_REMOTE_CLIENTS` and the explicit five-right DACL of RFC 0003 section 15) listeners and returns std `UnixListener`, `OwnedFd` or `OwnedHandle`. `grdr-ipc-os` implements every `Link`, `Connector` and `Acceptor` (`#2065`): `grdr-daemon` passes adopted `UnixListener`s or an instance-source closure (`impl FnMut() -> io::Result<OwnedHandle> + Send` calling `grdr-os-service`) into `grdr-ipc-os` acceptors, while `grdr-hook`, `grdr` and `grdr-tray` link `grdr-ipc-os` connectors and never `grdr-os-service`. `grdr-wire` holds pure `frame`, `local` seams and `peer_auth` (`#374`, `#1606`). Endpoint wiring, profile DACL choice and instance pool management stay in `grdr-daemon`.
- **Child supervision (`#680`, `#427`):** `socketpair` and pidfd helpers (Linux), kqueue `EVFILT_PROC` watch, reap and kill (macOS), and process-handle wait, `TerminateProcess`, job completion-port notifications and SCM service-pid query (Windows) live in `crates/grdr-os-service/src/{linux,macos,windows}/child*`. `EngineSupervision`, `ChildHandle` mapping and deadline logic stay in `grdr-daemon`.
- **Engine sandbox (`#689`, `#421`, `#688`):** Unchanged in `crates/grdr-sandbox-engine`. `#689` keeps its existing write set and uses `windows-sys` admitted on `crates/grdr-sandbox-engine/Cargo.toml` by `#1750`.
- **IPC peer authentication (`#375`, `#1549`, `#555`, `#516`):** `PeerReader` implementations and hold-based lookups in both directions live in `crates/grdr-peer-os/src/{linux,macos,windows}/**` (`rustix` on Linux; `libc` for `LOCAL_PEERTOKEN` and crate-local `extern "C"` blocks for `libbsm` audit-token calls on macOS; `windows-sys` on Windows, including `ImpersonateNamedPipeClient` and `OpenThreadToken(..., TOKEN_QUERY, OpenAsSelf = TRUE)` inside an RAII `RevertToSelf` guard). Platform-neutral verification (`peer_auth/model*`, `Refusal`, `PeerReader`, `open`, `accept`, `PendingPeer::first_frame`, `check_path` and `resolve` instead of `PeerVerifier` and `EndpointVerifier`) stays in `crates/grdr-wire/src/peer_auth/**` with `#![forbid(unsafe_code)]`, adopted by RFC 0003 ([ADR-0051](ADR-0051-the-grdr-wire-slice-0-surface-adopted-by-rfc-0003.md)). `grdr-hook` (`#516`), `grdr`, `grdr-tray` and `grdr-daemon` stay `unsafe`-free and authenticate peers through `grdr_wire::peer_auth` passed `grdr-peer-os` and `grdr-ipc-os` adapters.

### 3. Raw OS dependencies and licences (R1)

No service-manager wrapper crate (`windows-service`, `sd-notify`, `listenfd`, `libsystemd`) is admitted. OS adapter crates link raw bindings only:

- `#1750` admits `windows-sys` (Windows-only target dependency on `grdr-os-service`, `grdr-peer-os` and `grdr-sandbox-engine`, restricted to needed API features) and `libc` (target dependency on the same crates for calls `rustix` lacks, such as `LOCAL_PEERTOKEN` and `free`). RFC 0003 (`#2061`, `#2065`) adds `windows-sys` and `rustix` on `grdr-ipc-os` under the same `ARCH-027` policy. Both `windows-sys` and `libc` are dual-licensed `MIT OR Apache-2.0`, in the `permissive` class of [`supply-chain/licences.toml`](../../supply-chain/licences.toml) and allowed in [`deny.toml`](../../deny.toml).
- `#419` decides `rustix` (Linux and macOS kqueue/process calls) and the Linux seccomp builder on OS adapter crates only.
- Unbound C entry points (`launch_activate_socket`, `libbsm` audit-token readers) are declared directly in the owning adapter crate's `extern "C"` block with `// SAFETY:` comments rather than adding extra wrapper crates.

### 4. No D-Bus client in `grdr-daemon` (R3)

A D-Bus client decodes messages sent by other bus peers, so it is a content parser under [ADR-0010](ADR-0010-no-content-parser-in-a-privileged-closure.md) (`ARCH-004`) and remains excluded from `grdr-daemon` and every other `privilege = "privileged"` program. The transient cgroup-v2 scope request ([`docs/design/10-sensor-linux-containers-ci.md`](../design/10-sensor-linux-containers-ci.md) section 8, `#430`) moves to an unprivileged program running as the user on the user's bus (`grdr-run` is the first candidate, passing the root process by pidfd; `#419` and `docs/design/10` section 8 settle placement before a D-Bus crate is chosen). `grdr-daemon` keeps only the `Delegated` cgroupfs path (`mkdirat` through `grdr-os-service`) and scope state tracking. By contrast, `sd_notify` only writes datagrams over std's `UnixDatagram` and `LISTEN_FDS` reads integers set by the service manager, so neither is a content parser.

## Consequences

- `docs/design/03` section 10 requires no exception; `grdr-daemon`, `grdr-hook`, `grdr`, `grdr-tray` and `grdr-wire` keep `unsafe_code` forbidden and stay free of raw OS binding crates.
- Endpoint and peer-authentication OS `unsafe` is confined to four layer 3 trust-core crates split along squad boundaries (`endpoint` for `grdr-os-service`, `grdr-ipc-os` and `grdr-sandbox-engine`; `security` for `grdr-peer-os`).
- `grdr-wire` remains a portable, `unsafe`-free layer 2 public crate suitable for any embedding host (`P5`, `D-60`), exporting `PeerReader`, `open`, `accept`, `PendingPeer::first_frame`, `check_path` and `resolve` under [ADR-0051](ADR-0051-the-grdr-wire-slice-0-surface-adopted-by-rfc-0003.md).
- `grdr-daemon` stays free of D-Bus decoding (`ADR-0010`), placing systemd transient-scope requests (`#430`) in an unprivileged user program.
- Crates pass `UnixListener`, `OwnedFd`, `OwnedHandle` and stream types across layer 3 boundaries through `grdr-daemon` instead of calling raw bindings inside `grdr-daemon`, keeping `grdr-hook`, `grdr` and `grdr-tray` free of `grdr-os-service`, and endpoint/security issues sharing `src/lib.rs` and `src/<os>/mod.rs` sequence cleanly after `#1749`.

## Alternatives rejected

- **Allow `unsafe` in `grdr-daemon` or in `crates/grdr-wire/src/peer_auth/{macos,windows}` as a documented exception (`#1743` option 1 variant, `#1671` option A):** puts raw OS bindings and `unsafe` into a layer 4 program and a public layer 2 crate linked by every host (`P5`, `D-61`), and breaks `docs/design/03` section 10.
- **Vetted service-manager and peer-auth wrapper crates (`#1743` option 2, `#1671` option C):** no maintained crate offers a safe API for `launch_activate_socket`, `libbsm` audit-token inspection, or Windows named-pipe peer verification (`GetNamedPipeClientProcessId` and token inspection), leaving `unsafe` with us anyway; for systemd and SCM, wrapper crates pull third-party `unsafe` and extra dependencies into the privileged closure for small, fixed protocols.
- **Place service-manager calls in `grdr-wire`'s OS back ends (`#1743` option 3), or place local `Link`/`Connector`/`Acceptor` inside `grdr-os-service` (RFC 0003 `F6`):** either mixes `endpoint` service hosting into a layer 2 transport crate (`core` and `security`) or forces `grdr-hook`, `grdr` and `grdr-tray` to link `grdr-os-service`; keeping `grdr-ipc-os` separate avoids both ([ADR-0051](ADR-0051-the-grdr-wire-slice-0-surface-adopted-by-rfc-0003.md)).
- **Combine `grdr-os-service` and `grdr-peer-os` into one crate:** violates `R-50` (`security` owns IPC peer authentication; `endpoint` owns daemon service hosting) and forces `grdr-hook` and `grdr` to link service-manager code solely to verify an endpoint owner.
- **Admit a D-Bus client inside `grdr-daemon` (`#419`):** violates `ADR-0010` (`ARCH-004`) by adding a multi-peer message decoder to a privileged program's dependency closure.

## Revisit when

- A service-manager, local-link or peer-authentication operation requires direct access to daemon internals that cannot cross a `UnixListener`, `OwnedFd`, `OwnedHandle` or stream boundary within `limits.toml` latency or memory budgets.
- `rustix` or `libc` adds audited, parser-free safe or raw bindings for `launch_activate_socket` or macOS `libbsm` audit-token calls, letting `grdr-os-service` or `grdr-peer-os` drop its crate-local `extern "C"` block.
- `grdr-os-service`, `grdr-ipc-os` or `grdr-peer-os` requires an RFC-governed public API (`surface = "public"`), moving that surface to layer 2 through an RFC (`D-61`).
