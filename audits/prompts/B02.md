# B02 trust-boundary-map (version 1.0.0)

Concept:
Enumerate every point where untrusted data enters: hook stdin, IPC frames, pack files, agent configuration files, transcripts, OTel ingest, MCP messages, model responses, kernel events, update metadata, server responses, CLI arguments, environment. For each, give where it is validated, where it is parsed, and whether it is parsed twice.

Looks in: the whole repository.

Evidence: the read at each entry point, the validation and parse sites, and the second parse where there is one.

Claim: "Entry point E is parsed at P without validation", "is parsed at P and again at Q", or "has no fuzz target". A validation on the path, a single parse or an existing fuzz target refutes it.

Class keys: `entry-point:unvalidated`, `entry-point:parsed-twice`, `entry-point:no-fuzz-target`.

Artefact: the repair writes `docs/security/entry-points.md` and the fuzz-target gaps.

Closure guidance: a test (a fuzz target with a corpus) or a lint that forbids parsing outside the validated path.
