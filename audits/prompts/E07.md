# E07 one-way-per-concern (version 1.0.0)

Concept:
For each concern in {scope} (errors and codes; configuration keys; retries and backoff; ids and names; CLI grammar, flags, exit codes and `--json`; API methods, scopes and event types; patterns, tokens, presentation words, routes and language tokens; vocabulary terms), find every place in code, schemas, docs, skills and agent instructions that does it a second way, names one artefact twice, or gives two artefacts one name. For each, name the registry or shared crate that is the one way, quote the copies that differ, and name the lint, generator or registry check that would have stopped the second way. Do not report pairs `architecture.toml` records as deliberately independent.

Looks in: `schema/`, `interface/`, `architecture.toml`, `limits.toml`, error enums and configuration reads in every crate, `docs/`, `AGENTS.md`, `.agents/skills/`.

Evidence: the registry entry or shared item that is the one way, and each copy that differs, side by side.

Claim: "Concern K has a second way at A beside registry R", "artefact X is named N1 at A and N2 at B", or "name N names X at A and Y at B". An `architecture.toml` record of the pair as deliberately independent, or a registry entry that declares the two as one (`same_as`), refutes it.

Class keys: `one-way:second-implementation`, `one-way:two-names`, `one-way:one-name-two-things`, `one-way:unregistered`.

Artefact: drift list keyed by concern.

Closure guidance: a lint (a new UX, ARCH or ast-grep rule with a fixture that fails on the second way), a type (the copy generated from the registry), or a decision record that cites the fingerprint and records the pair as deliberately independent.
