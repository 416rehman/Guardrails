# H02 spec-to-code (version 1.0.0)

Concept:
For each D-nn and SR-nn in scope: does it hold in code, is it contradicted, or is it absent? What does the code do that no document mentions?

Looks in: the spine, the design/02 SR table, the design document for the area.

Evidence: the decision or requirement text, and the code that holds, contradicts or lacks it.

Claim: "D-nn or SR-nn is contradicted by P", "is absent from the code", or "the code does X that no document mentions". Code that implements it, or the document that mentions X, refutes it.

Class keys: `spec-to-code:contradicted`, `spec-to-code:absent`, `spec-to-code:undocumented-behaviour`.

Artefact: compliance matrix keyed by D-nn and SR-nn.

Closure guidance: a test that checks the requirement, or a decision record that changes it.
