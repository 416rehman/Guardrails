# M03 untrusted-parsing-in-privileged-code (version 1.0.0)

Concept:
List every parser, decoder, deserialiser, regex, decompressor, format sniffer and hand-rolled string split reachable in a privileged process, kernel-adjacent code or `grdr-hook`. For each, say why it is there, what bounds it, whether an agent can influence its input, and whether it should move to `grdr-engine`.

Looks in: closures of privileged programs and `grdr-hook` beyond what ARCH-004 can see: hand-written splitting of IPC payloads, path parsing, repeated protobuf fields with no bound, the TUF metadata parser in `grdr-updater`, the `grdr-fastpath` field scanner, macOS and Windows service shells.

Evidence: the parser call or hand-rolled split, the input source, and the bound or its absence.

Claim: "Parser K in privileged process P takes agent-influenced input I with bound B, or none, and belongs in `grdr-engine`." A bound from `limits.toml` and an input no agent can influence refute it.

Class keys: `privileged-parser:parser`, `privileged-parser:decoder`, `privileged-parser:deserialiser`, `privileged-parser:regex`, `privileged-parser:decompressor`, `privileged-parser:sniffer`, `privileged-parser:string-split`.

Artefact: parser inventory with bound and owner.

Closure guidance: a lint (an ARCH-004 extension) or a test (a differential fuzz against a full parser).
