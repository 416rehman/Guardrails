# M04 toctou-windows (version 1.0.0)

Concept:
Find every place where something is checked and later used: a path checked then opened, an executable hashed then run or mapped, a grant digest computed then the command executed, a PID looked up then signalled, a file validated then read again, a peer verified then the connection reused, a label read then the decision applied. Give the window, what can change in it, who can change it (an agent at user privilege, or an administrator), and whether the use re-checks or binds to a handle.

Looks in: grant re-check at execution (SR-19); loader-based exec that bypasses `execve` gates and `/proc/self/root` path tricks (research/37); symlink and junction swaps; fanotify decisions against the opened file; the approval display versus the executed action (SR-18); the shim digest check against the journal; label snapshot versus `state_seq`.

Evidence: the check, the use, and the code between them.

Claim: "Between check C at P and use U at Q, principal X can change Y, and U neither re-checks nor binds to the handle C checked." A re-check at U, or a handle-bound use, refutes it.

Class keys: `toctou:path-check-vs-open`, `toctou:hash-vs-exec`, `toctou:grant-digest-vs-exec`, `toctou:pid-lookup-vs-signal`, `toctou:validate-vs-reread`, `toctou:peer-verify-vs-reuse`, `toctou:label-read-vs-decision`, `toctou:approval-display-vs-exec`.

Artefact: window list.

Closure guidance: a test (a race test with an injected delay, Loom or Shuttle) or a type (a handle-bound API, so the use cannot take a path or PID again).
