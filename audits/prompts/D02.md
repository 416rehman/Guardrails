# D02 delivery-assumptions (version 1.0.0)

Concept:
Find code that assumes in-order, exactly-once or on-time delivery. State what happens on a duplicate, a late event and a reordered event.

Looks in: late labels and the `label.late` finding (D-09), the lateness window (D-33), spool replay, OS events arriving after hook decisions.

Evidence: the consumer, and the assumption it makes about order, count or time.

Claim: "Consumer C at P mishandles a duplicate, late or reordered event E and produces outcome O." Dedup, a window or a sequence check on that path refutes it.

Class keys: `delivery:duplicate`, `delivery:late`, `delivery:reordered`.

Artefact: deterministic-simulation scenarios.

Closure guidance: a test: a deterministic-simulation scenario that delivers the event that way.
