# D06 flaky-explainers (version 1.0.0)

Concept:
For each test quarantined or retried as flaky in the last 14 days, find the timing, ordering or shared-state cause in production code or test code.

Looks in: the CI flake log, `grdr-ports-testkit`, lab matrix jobs. Until CI exists the flake log is empty: return "not applicable" with that reason.

Evidence: the flaky test, and the code whose timing, ordering or shared state causes it.

Claim: "Test T is flaky because of cause C at P." A deterministic run that shows C absent refutes it.

Class keys: `flake:timing`, `flake:ordering`, `flake:shared-state`.

Artefact: cause per test.

Closure guidance: a test: the deterministic version of T (an injected clock, a fixed order, isolated state) that fails on the cause and passes after the fix.
