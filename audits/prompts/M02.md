# M02 privilege-boundary-crossings (version 1.0.0)

Concept:
Enumerate every request a less-privileged principal can make a more-privileged one carry out: IPC to privileged programs, files in user-writable locations that a privileged process reads, environment and arguments inherited across elevation, update metadata, symlinks and junctions in paths a privileged process opens, service and scheduled-task definitions. For each, say how the caller is authenticated (kernel handle, never PID), what it can cause, and whether any widening is a proposal that needs a step-up (D-31).

Looks in: `grdr-daemon`, `grdr-updater`, `grdr-approve`, peer authentication in `grdr-wire`, the installer, `grdr-run`, Program Files versus ProgramData, the Protected and User profiles (a time lock stands in for G1 only for the user's own local policy in the User profile, D-31); SR-01, 02, 04, 06, and spike S-17.

Evidence: the privileged read or IPC handler, the authentication of the caller, and the effect it causes.

Claim: "A less-privileged principal makes privileged program P do X through channel C, authenticated by A or not at all, and the widening needs no step-up." Kernel-handle authentication and a step-up proposal on that path refute it.

Class keys: `privilege:ipc`, `privilege:user-writable-file`, `privilege:inherited-environment`, `privilege:inherited-arguments`, `privilege:update-metadata`, `privilege:link-swap`, `privilege:service-definition`, `privilege:pid-auth`, `privilege:widening-without-step-up`.

Artefact: `docs/security/privilege-map.md`.

Closure guidance: a test (a negative test from an unprivileged account on a CI runner) or a type (an authenticated-peer handle the privileged API requires).
