# A01 implicit-state-machines (version 1.0.0)

Concept:
Find every lifecycle in {scope} whose state, transitions and ownership are spread across flags, `Option` fields, timestamps, counters, callbacks or async tasks. For each, give the states, the events, the transition table, the owner of each transition, the field combinations the types permit that no transition should produce, and every non-terminal state with no guaranteed exit through success, failure, cancel, timeout or restart. List the lifecycles that are already one enum with one transition function, so coverage is visible. Do not flag a single boolean with two obvious states.

Looks in: `grdr-core::session` (labels, counters, decay); the shim's invocation steps in `grdr-hook` (ack, verdict, table path, watchdog); `grdr-agents` install states (probe, write, canary, `effective`, "configured, not effective"); grants (minted, consumed, voided); the `grdr-update` last-known-good and crash-loop ladder; join and leave; the finding lifecycle and rollout rings once the server exists. The shapes: mutually exclusive booleans; a `state`, `status`, `phase`, `stage` or `mode` field held as a string, integer or `bool`; `Option` fields valid only in some phases; checks like `started && !finished`.

Evidence: the field declarations that hold the state, each site that writes them, and the check that reads a combination.

Claim: "Lifecycle L in item I is held in fields F; the types permit combination C that no transition produces", or "non-terminal state S of L has no exit". One quoted enum, transition function or exit refutes it.

Class keys: `implicit-state:exclusive-bools`, `implicit-state:stringly-status`, `implicit-state:phase-option`, `implicit-state:compound-check`, `implicit-state:timestamp-phase`, `implicit-state:counter-phase`, `implicit-state:task-owned-state`, `implicit-state:no-exit`.

Artefact: the repair writes `docs/state-machines/<name>.md` with the transition table and the machine's `paths` in its front matter; a trust-core machine also gets a Quint stub under `specs/`.

Closure guidance: a type only. The repair is an explicit state type: an enum whose variants own the data each state needs, with transitions as functions that consume one state and return the next (typestate where it is cheap), so the illegal combination cannot be built and every non-terminal state has an exit. A transition test and a `trybuild` compile-fail case come with it. A test, comment, extra flag, guard or assertion alone never closes it. On a pull request a surviving result is a blocking `major` review finding.
