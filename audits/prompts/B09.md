# B09 unsafe-invariants (version 1.0.0)

Concept:
For each `unsafe` block and FFI call in {scope}, state the invariant it relies on, who upholds it, whether its safety comment states that invariant, and which test runs it under Miri or AddressSanitizer. Find blocks whose invariant a caller with untrusted input can break.

Looks in: `grdr-ffi`, layer 3 OS adapter crates, `grdr-sensor-linux-bpf` loader code (SD-01; design/03 conventions).

Evidence: the `unsafe` block, its `// SAFETY:` comment, and the caller that passes untrusted input.

Claim: "The `unsafe` block at P relies on invariant V, and its safety comment does not state V", "caller C with untrusted input can break V", or "no Miri or ASan test runs it". A stated invariant upheld by a check or type on every path refutes it.

Class keys: `unsafe:invariant-unstated`, `unsafe:caller-can-break`, `unsafe:untested`.

Artefact: unsafe register.

Closure guidance: a test (a Miri or AddressSanitizer case) or the safety-comment lint.
