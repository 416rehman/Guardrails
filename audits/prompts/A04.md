# A04 unenforced-invariants (version 1.0.0)

Concept:
List invariants the code relies on that nothing enforces: comments saying must, always or never; `debug_assert!` only; checks that exist only in tests; statements in `design/` that no code or test checks.

Looks in: any-deny-wins across layers; list ceilings by set containment (D-11); operator artefacts narrow only (SR-26); labels inherit to children (SR-11); byte-exact replay of receipts; 64 enforcing labels and 32 counters per session (design/12 section 9).

Evidence: the statement of the invariant (comment, `debug_assert!`, test-only check or design line) and the code that relies on it without a check.

Claim: "Invariant V, stated at P, is relied on by Q and enforced by nothing in a release build." A release-build check, a type or a test that enforces V refutes it.

Class keys: `unenforced-invariant:comment-only`, `unenforced-invariant:debug-assert-only`, `unenforced-invariant:test-only-check`, `unenforced-invariant:design-only`.

Artefact: the repair records the invariant and its enforcing test in `docs/invariants.toml`.

Closure guidance: a test (proptest or a Kani proof) that fails when V breaks, or a type that makes V hold by construction.
