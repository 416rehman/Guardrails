# C02 error-taxonomy (version 1.0.0)

Concept:
Check that each crate has one error enum with registered `GRDR-<AREA>-NNNN` codes and a class (`input`, `policy`, `retryable`, `fatal`, `internal`), and that every evaluator error maps to an outcome through its rule class's failure policy. Find user-facing errors that leak internals.

Looks in: the `grdr-schema` error registry, every layer 0 to 3 crate.

Evidence: the error type or variant, its code and class or their absence, and the registry entry.

Claim: "Crate K's error E has no registered code or class", "evaluator error E reaches no outcome", or "user-facing message M exposes internal detail D". The registry entry or the mapping refutes it.

Class keys: `error-taxonomy:no-crate-enum`, `error-taxonomy:unregistered-code`, `error-taxonomy:missing-class`, `error-taxonomy:unmapped-outcome`, `error-taxonomy:leaks-internals`.

Artefact: error catalogue diff.

Closure guidance: a lint that checks codes against the registry, or a type that makes the code and class required.
