# B04 tenant-scoping (version 1.0.0)

Concept:
For every query, cache key, bus subject, lake prefix, log field, metric label, file path and background job, check that the organisation is part of the key and comes from the injected tenant context, never from the request.

Looks in: `grdr-server` targets, `grdr-rel-postgres`, `grdr-lake`, `grdr-bus-*`, `grdr-blob`; in standalone, `grdr-store-local` and the org-id alias after `grdr join`.

Evidence: the key construction, and where its organisation value comes from.

Claim: "Key K at P omits the organisation" or "takes it from request field R instead of `TenantCtx`". A `TenantCtx` source on every path, or row-level security that rejects the mix, refutes it.

Class keys: `tenant-scope:missing-org`, `tenant-scope:org-from-request`.

Artefact: tenant-isolation matrix.

Closure guidance: a test (an isolation test across two organisations) or a lint that requires `TenantCtx` in the key builder.
