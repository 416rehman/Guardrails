### Findings

**minor** `rfcs/0001-adopt-the-spine.md:91` against `:108` (with `:35`). The delta gives evidence files a lifecycle that the rules do not hold in one place, and two sentences contradict each other on it.
- Proof. Rule 1 (line 91) says an in-route commit "edits or removes no line that was added in route and no evidence file". As written, "no evidence file" is not limited to files added in route. Line 108 says the revert "removes any line or evidence file that was not added in route, which meets rule 1". Nothing defines when an evidence file is "added in route". Line 35 makes the decision commit add the files ("The commit that adds a decision line also adds"), but no rule limits additions to that commit. So under rule 1, a commit that adds only a file under `rfcs/evidence/` is in route.
- Scenario. Take an out-of-route commit that adds a decision line and its evidence files. Under rule 1, the chief architect's revert pull request that removes them is out of route, so `rfc-required` fails it, and line 108's "which meets rule 1" is false. The revert can only leave the file in place. Second case: a commit that adds nothing but a file holding a fail by an evaluator of the set, on some RFC's blobs. It is in route, it can never be removed, and by line 36 it blocks a decision on those blobs. The exit is a new text with new blobs, so nothing wedges and no unreviewed text reaches a pinned path. The checker of #1741 still has to pick a reading the RFC does not give.
- Fix, two clauses. Rule 1 reads "it edits or removes no line and no evidence file that was added in route". "The evidence is committed with the decision" adds: an evidence file is added in route only in the commit that adds a decision line it covers, and any other addition under `rfcs/evidence/` is out of route. Since the session's decision sends findings after the decision to #1741, this can go into #1741's scope note and fixtures instead of a revision 7.
