## Summary
Each FFI crate generates its C header from a descriptor in its own integration test, `tests/header_drift.rs`. It commits the header, and a C source of layout asserts beside it, under `include/`.

The descriptor names every export, struct, enum, typedef and constant, and each field's data class and byte encoding. Macros make the compiler hold it to the Rust items: a changed signature, a missing field, a changed field type or a missing enum variant stops the test from compiling.

A tool crate, `grdr-cabi-testkit`, owns the rest of the drift test behind an `Env` trait. It renders both files, compares them byte for byte with the committed ones, and runs five checks, `HDR-1` to `HDR-5`:
- types and layout against rustc;
- the committed text;
- every declaration and stated offset against the header's contract section;
- status codes and version constants against the registry and the library;
- every `#[unsafe(no_mangle)]` export against the descriptor.

Every failure names its next step. A new CI job, `c-headers`, compiles every committed header and layout source as C and as C++, with warnings as errors. It runs on the systems `verify.yml`'s `plan` job selects: gcc and clang on Linux for every pull request, and MSVC and Apple clang as well on the dispatched run on the head, on pushes to `main` and nightly.

No dependency is added. cbindgen is not used, the licence policy does not change, and `Cargo.lock` gains no third-party package. `grdr.h` and `grdr_macos.h` use the same method: what differs between headers is content in each descriptor, including the status block, the version scheme, the SPDX identifier and the contract document.

A runnable sketch on #474 shows the check passing on two stand-in crates and failing on each of 27 seeded changes. Those include the five that round 1 found undetected and the three that round 2 did. It passes on the two changes it should accept. It also runs 20 seeded unit tests of the testkit, and gcc and MSVC build the generated files cleanly.

## Motivation
EM-2 (#418) cannot be readied until this is decided. Its R5 asks for a test that fails when `grdr_fastpath.h` differs from the exported functions and `#[repr(C)]` types. Design/26 EM-2 says the "header [is] generated and diffed in CI". Design/03 section 7 gates the C ABI on "Generated header diffed". `c-abi.md` (#246) says the generated headers of EM-2 and EM-4 "are diffed against this text". #388 R12 asks the same for `grdr.h`, and #247 R7 for `grdr_macos.h`. Three headers need one answer.

The constraints:
- **Closure.** `libgrdr_fastpath` may resolve `grdr-fastpath` and `grdr-fastpath-ffi` only, as normal and build dependencies (design/26 section 2; #418 AC-6). A build-dependency is out.
- **Licence.** cbindgen 0.29.4 is MPL-2.0 (https://raw.githubusercontent.com/mozilla/cbindgen/main/Cargo.toml, read 2026-11-20; release dated 2026-06-10). `supply-chain/licences.toml` lists MPL-2.0 in its weak-copyleft class, which reads "never in layers 0 to 2, `grdr-ffi`, `grdr-wasm` or the embedded closure". As a dependency of either FFI crate, cbindgen would need a licence-policy RFC. Installed as a pinned tool it would need none (`supply-chain/build-tools.toml`).
- **No `xtask`.** ADR-0029 removed the `xtask` crate ("No `xtask` crate returns"), so #474 R1 (b)'s `xtask` route is gone.
- **Types in another crate.** #405 R1 may put the `#[repr(C)]` input and verdict in `grdr-fastpath` and have the FFI crate mirror them. A check that reads the FFI crate's source text would not see their fields; one that asks the compiler does.

## Design

### 1. Answers to #474
- **R1.** Neither (a) nor (b) as written. The header is generated, as design/26 and design/03 say. The generator is `grdr-cabi-testkit`, run by the crate's own drift test, over a descriptor the compiler holds to the Rust items. The committed header and layout source are the generated ones, byte for byte, and the `c-headers` job compiles both.
- **R2.** Not applicable: no cbindgen, no third-party dependency, no MPL-2.0 admission. The alternatives that would have needed one are under Alternatives.
- **R3.** The same method for `grdr.h` (#378 R5 (b), #388 R12) and `grdr_macos.h` (#247 R7). The status block of `grdr_fastpath.h` and `grdr.h` is one piece of default content in the testkit, `content::grdr_status`. Both descriptors use it, so the two blocks cannot differ. `grdr_macos.h` uses its own `i32` status enum and no status block. The sketch shows that header too.

### 2. Terms
- The **descriptor** is the list of a header's content, written in the crate's `tests/header_drift.rs` with the testkit's macros. Its parts are the status block, version, typedefs, enums, constants, opaque types, structs, functions, SPDX identifier and contract.
- To **render** is to produce the header and its layout source from the descriptor and, where the header has a status block, `status-codes.toml`. Rendering depends on nothing else, and in particular not on the host: the files are byte-identical on Windows and Linux in the sketch.
- To **bless** is to run the drift test with `GRDR_BLESS_HEADERS=1`. It writes both rendered files to `include/`, creating the directory when it is missing (round 2 finding 5), and then fails the run, so a bless never passes CI. It writes nothing if any comment text would break the C.
- The **contract section** of a header is the `## ` section, in the document the descriptor names, whose heading names the header file in backticks: section 2 of `c-abi.md` for `grdr_fastpath.h`, section 3 for `grdr.h`.
- A **check id** (`HDR-1` to `HDR-5`) names one kind of failure. Like the `TV-n` rules of `tables.md`, it appears only in test output, never at run time and never in output an administrator sees. It takes no `GRDR-<AREA>-<NNNN>` code and no `/codes` page.

### 4. The descriptor
```rust
c_struct!(Here, ffi::grdr_fp_input, "<doc>", {
    struct_size: u32 => [Structural] "<doc>",
    path: *const c_void => [ContentArgument, InField("path_encoding")] "<doc>",
    /* every field */
});
c_fn!(Here, ffi::grdr_fp_load, "<doc>",
      ("blob": *const u8, "len": usize, "arena": *mut c_void, "arena_len": usize,
       "out": *mut *const ffi::grdr_fp_tables) -> ffi::grdr_status as "grdr_status");
c_const!(ffi::GRDR_FP_PASS, "<doc>");
c_enum!(ffi::grdr_macos_status as i32, "<doc>", { GRDR_MACOS_OK => "<doc>", /* every variant */ });
```
What the compiler holds:
- **D1. Signatures.** `c_fn!` coerces the export to `unsafe extern "C" fn(<the listed types>) -> <return>`. A changed parameter type, a parameter added or removed, or a changed return type fails with E0308. The error points at the descriptor line and prints the expected and found pointer types; the sketch's seed s1 shows it.
- **D2. Fields.** `c_struct!` destructures the struct with every listed field and no `..`. A field added in Rust fails to compile ("pattern requires `..`"), and one removed from Rust fails with E0026 and E0609.
- **D3. Field types.** Each field is read through `fn(&S) -> &T` with the listed `T`. A changed type fails with E0308.
- **D4. Enum variants.** `c_enum!` matches every listed variant with no wildcard, so a variant added in Rust fails with E0004. It records each value both as the descriptor's C integer type and as `i128`; `HDR-1` compares the two, which catches a `u32` description of an `i32` enum with a negative value.
- **D5. Data class and encoding.** Every field carries a `DataClass` (`Identifier`, `Structural`, `Derived`, `ContentArgument`, `ContentBody`; design/04 section 2). The macro syntax requires it, and the header prints it beside the field. A byte field (a pointer to a byte or `void`, or an array of bytes) must carry an `Encoding`: `Utf8`, `InField("<field>")`, `NetworkOrder`, `Binary` or `Opaque`. Any other field must carry none; `HDR-1` checks both ways. No encoding implies a terminator.

What `HDR-1` holds, because the compiler cannot:
- **D6. Spellings.** `CType` maps the Rust primitives to the `<stdint.h>` names, `usize` to `size_t`, `c_void` and `()` to `void`, and `Option<unsafe extern "C" fn(..)>` to a C function pointer, with rustc's sizes and alignments. `as "<name>"` spells a type by a typedef, and the name must be in the header's closed typedef table: the descriptor's typedefs, the status block's typedef and the enums' typedefs. The typedef's underlying type must equal the Rust type's `CType`. The only other name allowed is the builtin `char`, over a one-byte Rust type. On a pointer to a one-byte type it names the pointee, so `*const c_char as "char"` is `const char *` (round 2 finding 3; `c_char` alone renders as `int8_t`, because Rust's `c_char` is an alias). So the round 1 seed `u32 as "size_t"` fails (seed A), and `as "char"` over a pointer to a wider type fails too.
- **D7. Array parameters and function-pointer fields.** `"entropy": *const u8 [32]` renders the C array parameter `const uint8_t entropy[32]`, which C reads as a pointer. `[n]` is allowed only after a pointer parameter, with n above 0. The length is not in the Rust type, so `HDR-3` holds it against the contract. A function-pointer field lists its parameter names, `("ctx", "size", "align")`, one per parameter.
- **D8. Names.** A struct, enum, function or constant takes its C name from the last segment of a two-segment Rust path, `ffi::<name>`, so every described item is at the crate root. If #405 defines the input and verdict in `grdr-fastpath`, the FFI crate re-exports them under the C names. Parameter names are C names, written as strings, because `in` is a Rust keyword. Status constants are listed with `c_status!(ffi::GRDR_OK)`, which takes the name from the item as `c_const!` does, so a name cannot be paired with another constant's value (round 2 seed X2).
- **D9. Enums cross only as return values.** C may pass any value of an integer typedef, and a Rust enum holding an undeclared value is undefined behaviour. So `HDR-1` refuses a Rust enum type, at any depth, in a parameter or a struct field, and allows it only as a function's return value by value (round 2 seed X4). Where C writes the value, the export takes the integer type, spelled by the enum's typedef (`"prior": i32 as "grdr_macos_status"`), and converts it with a checked `match` that returns an error status for an undeclared value.

What differs between headers is content, not code (P14): the file name, guard, SPDX identifier, summary, contract document and section, an optional status block, and an optional version. A version is `{ major, minor, packed macro, minor_bits, runtime }`, so the `major << 16 | minor` scheme of `c-abi.md` is data. A Rust constant left out of the descriptor is not part of the C surface; that is allowed, and seed s9 shows it.

### 5. The checks
`grdr_cabi_testkit::run(&descriptor, &paths, &mut StdEnv)` is the whole test. It reads the two committed files, the contract and, where there is a status block, the registry. It lists `src/` recursively and fails on any entry it cannot read. Then it runs the checks below, writes the rendered copies to `CARGO_TARGET_TMPDIR`, and blesses if asked. It returns one line per failure: the id, the detail, and `next:` with the one step that fixes it. A missing or unreadable input is a failure of the check that reads it, never a separate kind.

| Id | Fails when | Example detail, and its next step |
|---|---|---|
| `HDR-1` types and layout | A struct's offsets, size or alignment from rustc differ from the C layout of its listed fields, computed with rustc's sizes and alignments on the host. Also: a by-value use before declaration, or of an opaque type or `void`; a spelling outside the typedef table or over another type (D6); `[n]` misplaced, or wrong function-pointer names (D7); a missing or extra encoding (D5); an enum value that differs as described (D4); a Rust enum in a parameter or field (D9) | `grdr_fp_input.dest_kind: rustc offset 64, C layout 68`; next: list the fields in the struct's order with their Rust types, and keep `#[repr(C)]` on the struct |
| `HDR-2` text | A committed file is missing, has CR line endings, or differs from its rendering. Also: comment text in the descriptor or a registry `meaning` contains `*/` or `/*` (round 1's seed B). Bless then refuses to write | `include/grdr_fastpath.h: line 116: committed ..., rendered ...`; next: run the bless command (section 8), then run it again without the variable, and never edit the file by hand |
| `HDR-3` contract | A rendered declaration (`#define`, typedef, opaque type, struct, prototype) is missing from the contract section's `c` code blocks, or one stated there is missing from the header. Comparison is by C token sequence, comments stripped. Also: an offset or size the contract states in a field's comment differs from the 64-bit layout, or the contract or its section is missing | `in the header, not in ../../spec/host-contract/c-abi.md: #define GRDR_FP_DEST_UNIX 4u`; next: that section is protected (D-60), so open an issue asking for the change and stop, or undo the Rust and descriptor change |
| `HDR-4` constants | The registry uses a form outside the reader's subset, repeats a key, a name or a value, or its rows that are not retired differ from the Rust status constants the descriptor lists. Also: the crate's `grdr_status_str`, where the descriptor passes it, returns other than each row's name and the registry's `unknown_name`; or the version function returns other than the packed version constants | `Rust GRDR_E_STATE = 8 has no such row`; next: make `status-codes.toml` and the Rust constants agree, and remember that a new code needs an RFC (c-abi.md section 6) |
| `HDR-5` exports | The crate has a `build.rs`; a source line contains `include!`, `#[path`, `global_asm!`, `export_name` or `rustfmt::skip`; a top-level `pub extern "C" fn` in `src/lib.rs` has no `#[unsafe(no_mangle)]` among the attributes above it; an export carries an attribute other than `#[unsafe(no_mangle)]`, `#[allow(..)]`, `#[inline(..)]` or a `///` doc line, so `#[cfg(..)]` and `#[cfg_attr(..)]` fail; a `no_mangle` appears anywhere but a line of `src/lib.rs` that is exactly `#[unsafe(no_mangle)]` at the top level, followed by a top-level `pub extern "C" fn` or `pub unsafe extern "C" fn`; an export is not described; or a described function is not exported there | `src/private.rs:1: an export outside the top level of src/lib.rs`; next: write each export at the top level of `src/lib.rs` and describe it with `c_fn!` |

Rules the checks rest on:
- **Two layout models.** `HDR-1` uses rustc's own sizes and alignments on the host, so it is right on any target, including one where `uint64_t` aligns to 4 inside a struct. `HDR-3` and the layout source use the 64-bit model: natural alignment and 8-byte pointers, which every 64-bit target this repository builds shares. On a 64-bit host the two agree, so an offset the contract states is checked against rustc. `LP64_POINTER_BYTES` and the 100-column `WIDTH` are part of the rendered form (section 6), not `limits.toml` entries.
- **Exports.** Only crates that allow `unsafe` can export a symbol, because `unsafe_code` covers `no_mangle`, `export_name` and `global_asm!`; rustc 1.99.1 reports "usage of the unsafe `no_mangle` attribute" under `forbid(unsafe_code)`. Those crates are the FFI crates and the OS adapters. Requiring every export to be written out at the top level of `src/lib.rs`, and refusing `include!`, `#[path]` and `build.rs`, closes round 1's seeds D1, D2 and G. rustfmt indents every nested item, and `cargo fmt --check` is a gate, so a line at column 0 is a top-level line; `rustfmt::skip` is refused because it removes that guarantee. A top-level `extern "C" fn` with no export attribute is refused because it can only be a decoy for the descriptor's coercion. Together these close round 2's seed X1. An attribute is read whole: it starts at a line that begins with `#[` and ends at its bracket-balanced `]`, so rustfmt's wrapping of a long `#[allow(unsafe_code, reason = "...")]` over several lines is one attribute (round 3 seed Y1a, which must pass). Refusing `#[cfg]` on an export closes round 3 seed E1, where a compiled-out export and a `pub use` decoy let the header name a symbol the library does not export. The scan is textual and relies on rustfmt's form. It is the first check to remove if it ever gives a false failure, rather than loosen. #473's check of the archive's defined symbols stays, independent of it.
- **Registry reader.** It accepts comments, blank lines, top-level keys (`unknown_name`), `[[status]]`, and `key = value` where the value is a decimal integer, `true`, `false`, or a double-quoted string with no escape and no inner quote. Any other line, or a repeated key, is `HDR-4` with its line number. `handle_after` is behaviour, so #388's handle-state tests check it, not the header.
- **Contract reader.** It is a tokeniser and stays one: identifiers and numbers (with suffixes such as `1u`) are one token each, and each other non-space character is one token. Each `#define` line is one declaration, and every other declaration ends at a `;` outside braces. Other preprocessor lines are skipped. A stated offset is the first number in a field's comment inside a `typedef struct ... {` block, and a stated size is the first number after its closing brace. No expression is evaluated.
- **No waits, no skips.** The test reads and writes files and makes no process, network or clock call, so nothing in it waits. It has no skip path on any host.

### 6. The rendered files
The header, in this order:
1. `/* SPDX-License-Identifier: <spdx> */`, from the descriptor.
2. A banner: the file, its summary, "Generated by the header_drift test of `<crate>`; do not edit", and the exact command, `GRDR_BLESS_HEADERS=1 cargo test --locked -p <crate> --test header_drift`.
3. The include guard, `<stddef.h>` and `<stdint.h>`, and `extern "C"` under `__cplusplus`.
4. The status block, where the descriptor has one. For `grdr_status` headers this is `#ifndef GRDR_STATUS_DEFINED`, then `typedef uint32_t grdr_status;`, then one `#define <name> ((grdr_status)<value>u)` per row with its `meaning` as a comment. A retired row stays, marked "Retired.".
5. The version macros, then constants, enums (a typedef and one `#define` per variant), typedefs, opaque types, structs and prototypes. Each field is commented with `[<data class>; <encoding>]` and its doc, and prototypes are wrapped at 100 columns.

The header carries no offsets or sizes, because they differ between targets. The layout source, `<file>_layout.c`, carries them. It includes the header and, under `#if UINTPTR_MAX == 0xFFFFFFFFFFFFFFFFu`, asserts every typedef size and every struct size and field offset of the 64-bit model with `_Static_assert`, or `static_assert` in C++. It is committed beside the header and ships beside it in the embedded kit, so an embedder can compile it without Rust.

Every line ends in LF. The product name never appears; the `grdr` namespace stays fixed under a rebrand (ADR-0003). Person-facing status text is not in the header: `grdr_status_str` returns identifiers (c-abi.md section 3; D-69).

### 7. The C compiler step
The `c-headers` job of `verify.yml` takes its systems from the workflow's `plan` job, as the `rust` job does: `needs: plan`, with the matrix `fromJSON(needs.plan.outputs.systems)`. It adds no system list of its own. `plan` gives pull requests Linux only (owner instruction 28, runner minutes). It gives every system to a dispatched run, a push to `main` and the nightly run of the public repository, and Linux only to a private copy. So:
- **On every pull request**, ubuntu-26.04 compiles with gcc and with clang.
- **On the dispatched run on the head commit**, macos-26 adds Apple clang and windows-2025 adds MSVC, found through `vswhere` and `vcvars64.bat`. The same holds on pushes to `main` and nightly. An item reads those two results the way #418's AC-8 reads the `rust` jobs. It finds the `workflow_dispatch` run of `verify.yml` on `issue/<n>` whose `headSha` equals the branch head, and expects the jobs `c-headers (macos-26)` and `c-headers (windows-2025)` to have conclusion `success`. The dispatch rules are those #454 put on `main`.
- **In a private copy**, only gcc and clang run. MSVC and Apple clang never compile its headers. That is the copy's choice of runner minutes, and the release that ships a header comes from the public repository.

On each system it runs, for each `crates/*/include/*.h`, the job:
1. Fails if `<stem>_layout.c` or the crate's `tests/header_drift.rs` is missing. That catches a header whose drift test was deleted.
2. Compiles the header alone: as C99 and as C++11 with `-fsyntax-only` under gcc and clang, and as `/std:c11` and `/std:c++14` through a one-line translation unit under MSVC, whose lowest modes those are (it has no C99 or C++11 mode).
3. Compiles the layout source as C11 and as C++11 under gcc and clang, and as `/std:c11` and `/std:c++14` under MSVC.
4. Compiles one translation unit that includes every header twice, which checks the shared `GRDR_STATUS_DEFINED` guard.

The flags are `-Wall -Wextra -Wpedantic -Werror` under gcc and clang, and `/W4 /WX` under MSVC. On a system the plan gives it, a missing compiler fails the job; nothing is skipped there. The job is gate configuration, so lead-agent-kit builds it, and it blocks #418.

The sketch ran the same compiles by hand. gcc 14.2.0 built C99, C11, C17, C++11, C++17 and C++20 under `-Wpedantic -Werror`, and MSVC (Visual Studio 18) built each header alone, both layout sources and the combined unit as `/std:c11`, `/std:c++14` and `/std:c++17` under `/W4 /WX`, 15 compiles; all exited 0. A 32-bit leg (`-m32`) was not checked, because the image has no 32-bit libc headers. Section 11 makes that leg a condition of any 32-bit pilot.

### 8. Changing a header
A change to a C ABI is a public-surface change: D-60 for any function, field or code beyond design/26, and RFC 0004 for the header's form. So a header change opens with an issue, not a pull request. In order:
1. The contract section of `c-abi.md` (and `status-codes.toml`, for a code) gains the declaration, through its RFC or protected-change item. A contributor who reaches `HDR-3` opens an issue asking for that change and stops there; only the chief architect's item edits the file.
2. The Rust items change.
3. The descriptor changes. Until it does, D1 to D4 stop the build.
4. Bless with `GRDR_BLESS_HEADERS=1 cargo test --locked -p <crate> --test header_drift`, which fails by design, then run `cargo test --locked -p <crate> --test header_drift` again, which passes only if steps 1 to 3 agree. In PowerShell the variable is set with `$env:GRDR_BLESS_HEADERS = "1"` and in cmd with `set GRDR_BLESS_HEADERS=1`; clear it afterwards.

The descriptor of `grdr_fastpath.h` and of `grdr.h` is on a trust-core path. Every change to those headers therefore takes `eval-security`, `eval-adversarial` and two passing evaluators on different models (D-63).

This section, the check table of section 5 and the bless command in its three shells become `crates/grdr-cabi-testkit/AGENTS.md`. The testkit item's acceptance includes a check that the `AGENTS.md` check table equals section 5's table word for word, so the two cannot drift (seat 7, round 2). Each FFI crate's `AGENTS.md` points to it from "How to test", and `docs/product/embed/` gains one page for embedders: vendoring the header and layout source, the version rule of section 9, and what may be stripped (section 11). An agent reads the crate `AGENTS.md` at the start of every run that touches the crate.

### 9. Proposed section 2.4 of `c-abi.md`
`HDR-3` needs the constants in a `c` block. Section 2 states the values only in comments. This RFC adds the names, a packed version macro and the load rule. The text to insert before section 3:

````markdown
### 2.4 Constants

The header defines the fast-path ABI version it describes and a name for every value section 2
gives a field. A host that compiled against major `M` and minor `m` loads the library only when
`grdr_fp_abi_version() >> 16 == M` and `(grdr_fp_abi_version() & 0xFFFF) >= m`; the same major
and an equal or later minor. `GRDR_FP_ABI_VERSION` is the packed value the host compiled with.
````

Section 3 gains the matching block for `grdr.h` (`GRDR_ABI_MAJOR`, `GRDR_ABI_MINOR`, `GRDR_ABI_VERSION`) when #378 fixes the minor of each function. Growth within a major is already `c-abi.md` section 1's: trailing input fields behind `struct_size`, and output structs that never change.

### 10. What the check does not cover
- **Behaviour.** Which status a function returns, and when, is #418's differential and argument tests, and #388's handle-state tests.
- **Compatibility across releases.** Within a major, declarations are only added and input structs only grow trailing fields (D-71; design/03 section 7). #1771 builds that check; section 11 makes it a gate.
- **A run-time version mismatch.** No product program loads a library through these headers. The daemon links `grdr-fastpath` from Rust (design/26 section 2), and the sidecar is a Rust binary. A partner's host applies section 9's rule. If a product program ever loads one, it reports a mismatch as a health condition with a registered code, a runbook and a `grdr doctor` line naming both versions and the component to upgrade, never as a tamper finding. That program's item adds the code.
- **Signedness of an enum whose values are all non-negative.** D4 catches a wrong signedness only through a negative value. Every value is the same in either type, so C reads it the same.

Data classes (P8): the check reads source, interface text and registry files, all `structural`. It logs nothing at run time and adds no field to any message. The headers now state each field's class; that is documentation of classes the wire types already carry, not a new class. Assurance effect (P1): none. No action class changes `visibility`, `control`, `on_failure` or `tamper`.

### 11. Stability
- The headers share the class of their C ABI: experimental until one external embed pilot completes (D-60). A change to the renderer that changes any header's text is an amendment that names RFC 0004 and regenerates every header in one change.
- A header leaves experimental only once #1771 runs as a release gate. #1771 is also a gate of the first release that ships any header, even though that release has no earlier one to compare with, so the check exists before a second release can break it.
- Before a pilot on a 32-bit target, the `c-headers` job gains that target's compiler leg, and the layout source gains its asserts.
- A vendor that ships a header under its own brand may strip the banner and every comment. The declarations are the ABI, and the version constants are the only compatibility signal.
- `grdr-cabi-testkit` is internal. It changes by ordinary items, except where a change alters a rendered header, which is an amendment as above.

## Alternatives
Each alternative below was checked against what shipping projects do:
- rustls-ffi installs cbindgen as a tool pinned to 0.29.4 in its `ensure-header-updated` job, regenerates the header and runs `git diff --exit-code`. Its workflow says the pin exists because point releases can change the output (https://raw.githubusercontent.com/rustls/rustls-ffi/main/.github/workflows/test.yaml, read 2026-11-20).
- safer_ffi generates headers from a registry inside the library, behind a `headers` feature and a dedicated binary (https://raw.githubusercontent.com/getditto/safer_ffi/master/README.md, read 2026-11-20).
- `offset_of!` has been stable since Rust 1.77 (https://doc.rust-lang.org/core/mem/macro.offset_of.html, read 2026-11-20).

The options:
- **(a) A hand-written header, and a test that parses it and the crate's `extern "C"` items.** It needs two parsers: a C subset, and Rust source, which takes `syn` (a new dependency) or a hand-written one. A source parser does not see through `pub use`, type aliases or types defined in `grdr-fastpath` (#405), and it checks no layout. Rejected.
- **(b1) cbindgen as a dev-dependency.** The licence class forbids MPL-2.0 in layers 0 to 2 and `grdr-ffi`, and its ten required direct dependencies would enter the dev graph of a trust-core crate. Rejected.
- **(b2) cbindgen in `build.rs`.** It breaks the fast-path closure. Rejected.
- **(b3) cbindgen as a pinned tool in `build-tools.toml`, run by a CI step, as rustls-ffi does.** Allowed by the licence and the closure, but:
  - the check leaves `cargo test --workspace`;
  - each session needs cbindgen to regenerate;
  - the types in `grdr-fastpath` need `parse_deps`;
  - it checks neither rustc's layout nor `c-abi.md`;
  - each bump can churn three headers.

  It is the fallback if the testkit proves too costly to keep. No header needs it today.
- **(b4) An `xtask` tool.** ADR-0029 removed `xtask`. Rejected.
- **(d) The header as the source, with Rust generated from it by bindgen.** It needs libclang on every host and makes the Rust side generated code inside the trust core. Rejected.
- **(e) A registry in the library, as safer_ffi has.** It ships the descriptor in the artefact or needs a Cargo feature. Rejected.
- **(f) A proc-macro attribute on each export.** It needs `syn` and `quote`. Rejected.
- **(g) A hand-written header with only C static asserts.** It checks layout, but not signatures, because linking checks names only. Kept as the `c-headers` job beside the drift test, not instead of it.
- **(h) A copy of the renderer in each crate's test.** Three copies, and the shared status block could drift. Rejected for one testkit.
- **(i) The testkit as a public layer 1 crate (revision 1).** That adds a published, semver-checked crate, two same-layer edges and a list, where design/03's `tool` layer already covers a dev-only crate. Rejected for `layer = "tool"`.
- **(j) A C compile inside `cargo test`, driven by `CC`.** Every contributor's `cargo test --workspace` would then need a configured C compiler, and on Windows that means finding MSVC without the `cc` crate. Rejected for the `c-headers` job, which runs where the compilers are known.
- **(k) Explicit padding fields, so no offset depends on the target (seat 5).** Section 2.1 of #246 leaves implicit padding after `dest_port`, and pointers differ between 32- and 64-bit targets in any case. Declined: alignment comes from rustc (section 5), and a 32-bit target gets its own compiler leg before a pilot.
- **(l) Fewer per-field docs, taken from `c-abi.md` (seat 8).** The header must state each field's data class and encoding, which `c-abi.md` does not carry, so the descriptor keeps one doc per field. Offsets left the header instead.
- **(m) A system list of the `c-headers` job's own (revision 2).** It would be a second planner beside `plan`, overriding owner instruction 28 for one job, or it would promise three systems that a pull request and a private copy never get. Rejected for `plan`'s systems and the dispatched run (section 7).
- **(n) A Rust enum in a parameter, read with a validity check.** A Rust enum holding an undeclared value is undefined behaviour before any check can run. Rejected for D9.

## Drawbacks
- The descriptor is a third statement of each signature beside the Rust and the header. The compiler holds it to the Rust, but each change edits it. Changing one exported function takes three hand edits (contract, Rust, descriptor) and a bless.
- `HDR-3` ties the test to the form of the contract document: a heading that names the header in backticks, `c` code blocks, and offsets as the first number of a field comment. A reshuffle fails closed, and the cost lands on the chief architect's protected file.
- The export scan is textual. It depends on rustfmt's form and requires every export at the top level of `src/lib.rs`, so #418's modules hold implementations and `lib.rs` holds the exports.
- One more crate, one more CI job, and a C compiler on each hosted runner.
- The drift test reads files outside its crate (`spec/`). A crate that is ever published lists `tests/header_drift.rs` in `package.exclude`.
- The status block carries each code's English `meaning` as a comment. A reword regenerates both C ABI headers.

## Decision
Accepted by the chief architect under D-61, after three review rounds with the persona council and `eval-architecture`. The last round passed with no major finding.

Reasons:
1. **It answers #474 inside the spine.** The header is generated and diffed in CI, as design/26 EM-2 and design/03 section 7 say. No dependency, licence change, public crate or same-layer edge is added (D-02, D-61), and the fast-path closure stays `grdr-fastpath` and `grdr-fastpath-ffi` (design/26 section 2).
2. **Every statement of the C surface is held by something independent of the one who writes it.**
   - The compiler holds the descriptor to the Rust (D1 to D4).
   - The testkit holds the header to the descriptor, the protected contract and the registry (`HDR-1` to `HDR-5`).
   - A C compiler on the systems `plan` selects holds the header to C and C++ (section 7).
   - #473 holds the archive's symbols.
   Each of the 27 seeded drifts of the sketch fails one of them, including every gap rounds 1 and 2 found. Round 3's E1 is caught by #473's symbol check today and refused by #1778's export-attribute rule. Round 3's Y1a, a false failure, is fixed by #1778's whole-attribute rule.
3. **What differs between headers is content (P14).** Status block, version scheme, SPDX identifier and contract are descriptor fields. A second header with a different status type passes the same code.
4. **It fails closed.** Missing inputs, unreadable directories, comment text that would break C, unknown spellings, hidden exports and enums where C writes the value all fail, each with its next step. Nothing is skipped on a system the plan gives the job.
5. **The costs are stated and accepted.** They are a third statement of each signature, a textual export scan, one more CI job, and a contract format the test reads (Drawbacks). cbindgen as a pinned tool, Alternative (b3), stays the fallback.

The three round 3 minors are folded in as wording changes of sections 5 and 7, without a further round, because each narrows a rule the RFC already states:
- complete attributes in the scan;
- only `no_mangle`, `allow`, `inline` and doc attributes on an export;
- MSVC's `/std:c11` and `/std:c++14` modes.

The MSVC claim was re-run at those modes, with 15 compiles exiting 0. #1778 and #1779 carry them with seeded tests.

ADR-0034 (#1776) records this decision. A comment after this decision that shows a defect opens a new RFC; there is no waiting period (owner instruction 7).
