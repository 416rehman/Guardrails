## Summary
Each FFI crate generates its C header from a descriptor in its own integration test, `tests/header_drift.rs`, and commits the header under `include/`. The descriptor names every export, struct and constant. Macros make the compiler check it against the Rust items, so a changed signature, a missing field or a changed field type stops the test from compiling. A std-only crate with no I/O, `grdr-cabi-testkit`, then:
- renders the header from the descriptor and the status registry, and requires the committed header to match it byte for byte;
- checks every struct's layout against rustc's;
- checks every declaration against the header's section of `c-abi.md`;
- checks every `#[unsafe(no_mangle)]` export against the descriptor;
- checks the library's version function against the header's version constants.

Each failure has a check id, `HDR-1` to `HDR-8`. `cargo test --workspace` runs the check on the three CI systems.

No dependency is added. cbindgen is not used, the licence policy does not change, and `Cargo.lock` gains no package. `grdr.h` and `grdr_macos.h` use the same method and the same status-block renderer, so the block both C ABI headers share is identical by construction. A runnable sketch on #474 shows the check passing on a clean tree and failing on each of 13 seeded changes.

## Motivation
EM-2 (#418) cannot be readied until this is decided. Its R5 asks for a test that fails when `grdr_fastpath.h` differs from the exported functions and `#[repr(C)]` types. Design/26 EM-2 says the "header [is] generated and diffed in CI". Design/03 section 7 gates the C ABI on "Generated header diffed". `c-abi.md` (#246) says the generated headers of EM-2 and EM-4 "are diffed against this text". #388 R12 asks the same for `grdr.h`, and #247 R7 for `grdr_macos.h`. Three headers need one answer.

The constraints:
- **Closure.** `libgrdr_fastpath` may resolve `grdr-fastpath` and `grdr-fastpath-ffi` only, as normal and build dependencies (design/26 section 2; #418 AC-6). A build-dependency is out.
- **Licence.** cbindgen 0.29.4 is MPL-2.0 (https://raw.githubusercontent.com/mozilla/cbindgen/main/Cargo.toml, read 2026-11-20; release dated 2026-06-10). #474 says `supply-chain/licences.toml` does not list MPL-2.0. It does, in the weak-copyleft class, which reads "never in layers 0 to 2, `grdr-ffi`, `grdr-wasm` or the embedded closure". So cbindgen as a dependency of either FFI crate needs a licence-policy change, which is itself an RFC (design/30 section 3). Installed as a pinned tool, it would need none (`supply-chain/build-tools.toml`).
- **No `xtask`.** ADR-0029 removed the `xtask` crate: "No `xtask` crate returns". #474 R1 (b) names an `xtask` tool, and that route is gone.
- **Types in another crate.** #405 R1 may put the `#[repr(C)]` input and verdict in `grdr-fastpath` and have the FFI crate mirror them. A check that reads source text of `grdr-fastpath-ffi` would not see their fields. One that asks the compiler does.

## Design

### 1. Answers to #474
- **R1.** Neither (a) nor (b) as written. The header is generated, as design/26 and design/03 say. The generator is an in-tree, std-only renderer that the crate's own drift test runs, over a descriptor the compiler holds to the Rust items. The committed header is the generated one, byte for byte.
- **R2.** Not applicable: no cbindgen, no dependency, no MPL-2.0 admission. Section 13 gives the alternatives that would have needed one.
- **R3.** The same method for `grdr.h` (#378 R5 (b), #388 R12) and `grdr_macos.h` (#247 R7). The status block of `grdr_fastpath.h` and `grdr.h` comes from one function over `status-codes.toml`, so the two blocks cannot differ.

### 2. Terms
- The **descriptor** is the list of a header's constants, opaque types, structs and functions, written in the crate's `tests/header_drift.rs` with the testkit's macros.
- To **render** is to produce the header text from the descriptor and `status-codes.toml`. Rendering depends on nothing else; in particular, not on the host.
- To **bless** is to run the drift test with `GRDR_BLESS_HEADERS=1`, which writes the rendered header to `include/` and then fails (`HDR-8`).
- The **contract section** of a header is the `## ` section of `spec/host-contract/c-abi.md` whose heading names the header file in backticks: section 2 for `grdr_fastpath.h`, section 3 for `grdr.h`.
- A **check id** (`HDR-1` to `HDR-8`) names one way the check fails. Like the `TV-n` rules of `tables.md`, it appears only in test output and never at run time, so it takes no `GRDR-<AREA>-<NNNN>` code and no `/codes` page.

### 3. What lives where
| Concern | Path | Squad, lane |
|---|---|---|
| `CType`, the macros `c_struct!`, `c_fn!` and `c_const!`, the layout model, the renderer, the contract tokeniser, the registry reader, the export scanner, the layout-assert source | `crates/grdr-cabi-testkit/src/**`: layer 1, std only, no dependency, no I/O, no feature, `unsafe_code` forbidden, on the `test-support` list | core; high tier |
| The descriptor of one header, and the file reads and writes | `crates/grdr-fastpath-ffi/tests/header_drift.rs`; `crates/grdr-ffi/tests/header_drift.rs`; `crates/grdr-sensor-macos/tests/header_drift.rs` | the crate's squad; trust core where the crate is |
| The header | `crates/<crate>/include/<file>.h`, generated, LF only (`.gitattributes` already sets `eol=lf`) | as the crate |
| The interface text | `spec/host-contract/c-abi.md`, the contract section per header | ecosystem, through the chief architect |
| Status names and values | `spec/host-contract/status-codes.toml` | as above |

The testkit is test support, a dev-dependency only. It never enters a normal or build closure, and the archlint graph rule over the `test-support` list in `architecture.toml` holds that, the rule RFC 0002 Rule 1 gives `grdr-ports-testkit`. It is layer 1 so that layer 1 crates may dev-depend on it. It is pure, so layer 1's no-I/O rule holds. The drift test reads and writes the files, and test code may do I/O.

### 4. The descriptor
```rust
pub trait CType<R> { fn cty() -> CTy; }   // R: a key type local to the describing crate
c_struct!(Here, ffi::grdr_fp_verdict, "<doc>", { verdict: u32 => "<doc>", /* every field */ });
c_fn!(Here, ffi::grdr_fp_load, "<doc>",
      ("blob": *const u8, "len": usize, "arena": *mut c_void, "arena_len": usize,
       "out": *mut *const ffi::grdr_fp_tables) -> ffi::grdr_status as "grdr_status");
c_const!(ffi::GRDR_FP_PASS, "<doc>");
```
What the compiler holds:
- **D1. Signatures.** `c_fn!` coerces the export to `unsafe extern "C" fn(<the listed types>) -> <return>`. A changed parameter type, a parameter added or removed, or a changed return type fails with E0308.
- **D2. Fields.** `c_struct!` destructures the struct with every listed field and no `..`. A field added in Rust fails to compile ("pattern requires `..`"), and one removed from Rust fails with E0026 and E0609.
- **D3. Field types.** Each field is read through `fn(&S) -> &T` with the listed `T`. A changed type fails with E0308.
- **D4. Offsets and sizes.** The descriptor records `offset_of!`, `size_of` and `align_of` from rustc. `HDR-1` compares them with the C layout (section 5).
- **D5. Spelling.** `CType` maps `u8`, `u16`, `u32`, `u64`, `i32`, `i64` to the `<stdint.h>` names, `usize` to `size_t`, `c_void` to `void`, `c_char` to `char`, and builds pointers and arrays from those. The describing crate implements `CType<Here>` for its own structs, naming each `Named` or `Opaque`. `as "<typedef>"` spells a type by its C typedef, as `grdr_status` is. A Rust type alias is transparent, so `grdr_status` would otherwise render as `uint32_t`.
- **D6. Names.** A struct, function or constant takes its C name from its Rust path's last segment. If #405 defines the input and verdict in `grdr-fastpath`, the FFI crate re-exports them under the C names and the descriptor names the re-export. Parameter names are C names, written as strings, because `in` is a Rust keyword.

Not held by the compiler, and so checked at run time: field order (`HDR-1`), the set of exports (`HDR-5`), and the version function's value (`HDR-6`). A Rust constant left out of the descriptor is not part of the C surface. That is allowed, and the sketch's seed s9 shows it.

### 5. The checks
The drift test reads the committed header, `c-abi.md`, `status-codes.toml` and every `.rs` file under `src/`. It calls `grdr_cabi_testkit::check`, which returns the rendered header and a list of failures. Then the test:
- writes the rendered copy to `CARGO_TARGET_TMPDIR`;
- writes a C source of layout asserts there (section 9);
- blesses, if asked;
- fails if the list is not empty, printing one line per failure: the check id and the detail.

| Id | Fails when | Detail printed |
|---|---|---|
| `HDR-1` layout | A struct's rustc offset, size or alignment differs from the C layout of its listed fields under natural alignment, computed with the host's pointer width. Also when a struct is used by value before it is declared, or an opaque type or `void` is used by value | `grdr_fp_input.dest_kind: rustc offset 64, C layout 68` |
| `HDR-2` text | The committed header is not byte-identical to the rendered one | The first differing line, committed and rendered, or "CR line endings" |
| `HDR-3` contract | A rendered declaration (constant, opaque typedef, struct, prototype) is missing from the contract section's `c` code blocks, or one stated there is missing from the header. Comparison is by C token sequence, with comments stripped. The status block is not compared here | `in the header, not in c-abi.md: #define GRDR_FP_DEST_UNIX 4u` |
| `HDR-4` registry | `status-codes.toml` uses a form outside the reader's subset, or repeats a name or value. Also when the Rust status constants the descriptor lists differ from the rows that are not retired | `Rust GRDR_E_STATE = 8 has no such row` |
| `HDR-5` exports | A source line names `no_mangle` or `export_name` in any form but a line that is exactly `#[unsafe(no_mangle)]`; that line is not followed by an `extern "C" fn` with a literal name; an export is not in the descriptor; or a described function has no export | `src/lib.rs:129: grdr_fp_extra is exported but not described` |
| `HDR-6` version | The library's version function returns a value other than `major << 16 \| minor` of the descriptor's version constants | `the library returns 0x2, the header declares 0.1 (0x1)` |
| `HDR-7` input | A file the check reads is missing, unreadable or not UTF-8 | The path and the OS error |
| `HDR-8` bless | `GRDR_BLESS_HEADERS` is set. The header is written and the run fails anyway, so a bless never passes CI | `include/grdr_fastpath.h written; run the test again without GRDR_BLESS_HEADERS` |

Rules the checks rest on:
- **Exports.** Only crates that allow `unsafe` code can export a symbol, because `unsafe_code` covers `no_mangle` and `export_name` (rustc 1.99.1 reports "usage of the unsafe `no_mangle` attribute" under `forbid(unsafe_code)`). Those crates are the FFI crates and the OS adapters. So scanning the FFI crate's own `src/` covers every `grdr_fp_*` symbol that `libgrdr_fastpath` can carry, since `grdr-fastpath` forbids `unsafe`. The scanner is textual and relies on rustfmt's form. It fails closed on anything it cannot read, including an export written by a macro. #473's check of the archive's defined symbols stays, and is independent of this one.
- **Registry reader.** It accepts comments, blank lines, `[[status]]`, and `key = value` where the value is a decimal integer, `true`, `false`, or a double-quoted string with no escape and no inner quote. Any other line is `HDR-4` with its line number. It never guesses.
- **Contract tokens.** Identifiers, numbers and suffixes such as `1u` are one token each, and each other non-space character is one token. Each `#define` line is one declaration. Every other declaration ends at a `;` outside braces. Other preprocessor lines are not declarations.
- **No waits.** The check reads files and makes no process, network or clock call, so nothing in it waits. It has no skip path. On a 32-bit host `HDR-1` uses that host's pointer width, and rendering still uses 8, so `HDR-2` is the same everywhere.

### 6. The rendered header
In this order:
1. `/* SPDX-License-Identifier: Apache-2.0 */`.
2. A banner: the file, what it is, its ABI version, "Generated by the header_drift test of this crate (RFC 0004); do not edit", and how to regenerate it.
3. The include guard. `<stddef.h>` and `<stdint.h>`. `extern "C"` under `__cplusplus`.
4. The status block: `#ifndef GRDR_STATUS_DEFINED`, `typedef uint32_t grdr_status;`, then one `#define <name> ((grdr_status)<value>u)` per row, with the row's `meaning` as its comment. A retired row stays, marked "Retired.".
5. `#define <PREFIX>_ABI_MAJOR` and `_MINOR`, then the descriptor's constants, each `#define <name> <value>u`.
6. Opaque typedefs, then structs in descriptor order, each field commented with its offset on 64-bit targets and its doc, then the size.
7. Prototypes, each with its doc comment, parameters wrapped at 100 columns under the opening parenthesis.

Every line ends in LF. The product name never appears; the `grdr` namespace stays fixed under a rebrand (ADR-0003). The person-facing text of a status is not in the header: `grdr_status_str` returns identifiers (c-abi.md section 3; D-69).

### 7. Changing a header
A change to a C ABI is a public-surface change: D-60 for any function, field or code beyond design/26, and RFC 0004 for the header's form. In order:
1. The contract section of `c-abi.md` (and `status-codes.toml`, for a code) gains the declaration, through its RFC or protected-change item.
2. The Rust items change.
3. The descriptor changes. Until it does, D1 to D3 stop the build.
4. Bless, which fails with `HDR-8`, then run again, which passes only if steps 1 to 3 agree.

The descriptor of `grdr_fastpath.h` is under `crates/grdr-fastpath-ffi/**`, a trust-core path. Every change to that header therefore takes `eval-security`, `eval-adversarial` and two passing evaluators on different models (D-63).

### 9. What the check does not cover
- **How a C compiler reads the header.** `#[repr(C)]` follows the platform's C layout, so `HDR-1`, checked against rustc, is the C layout as long as `CType`'s map is right. To check the map itself, the test writes `<file>_layout.c`, which includes the header and asserts every `sizeof` and `offsetof` rustc reported, as C11 and as C++. The sketch builds it with MSVC as C11 and C++17 under `/W4 /WX`, and both pass. A compiler step joins `cargo test` when #378 R5 (c) rules on how a test reaches the host compiler. #247 AC-1 already does it on macOS with the system compiler. A C program linked against the library checks symbol names, never signatures, so a C leg is an addition to D1 to D3, never a replacement for them.
- **Behaviour.** Which status a function returns, and when, is #418's differential and argument tests.
- **Compatibility across releases.** D-71 and design/03 section 7 also gate a header against its last release: within a major, declarations are only added, and structs only grow trailing fields. That diff is a separate check. It can reuse the contract tokeniser on the header at the release tag. No item built it, so #1771 now does (section 14).

Data classes (P8): the check reads source, interface text and registry files, all `structural`. It logs nothing at run time and adds no field to any message. Assurance effect (P1): none. No action class changes `visibility`, `control`, `on_failure` or `tamper`.

### 11. Stability
- The headers share the class of their C ABI: experimental until one external embed pilot completes (D-60). The rendered form is part of that surface. A change to the renderer that changes any header's text is an amendment that names RFC 0004 and regenerates every header in one change.
- `grdr-cabi-testkit` enters `surfaces.toml` as `experimental`. Its consumers are the workspace's own tests.
- No amendment is needed for a new header that uses the method as it stands: a crate adds its descriptor, its `include/` file and its contract section.

### 12. Mechanisms
| Decision | Mechanism | Built by |
|---|---|---|
| The header is the rendering of its descriptor and the registry | `HDR-2` in each crate's `header_drift` test, run by `cargo test --workspace` in `verify.yml` on the three systems | The testkit item; #418, #388, #247 |
| The descriptor matches the Rust items | D1 to D3 at compile time; `compile_fail` doctests in the testkit for each, and one in `grdr-fastpath-ffi` that describes `grdr_fp_arena_size` with a wrong parameter type (#418 AC-5's seeded change) | The testkit item; #418 |
| The C layout matches rustc's | `HDR-1` on every CI host; the layout-assert source for the C compiler step | The testkit item; the step once #378 R5 (c) is ruled |
| The header matches `c-abi.md` | `HDR-3`; section 2.4 in `c-abi.md` | The testkit item; the `c-abi.md` item filed on acceptance |
| One status block for both headers | `HDR-4` and one render function in the testkit | The testkit item |
| Every export is described | `HDR-5`; `unsafe_code` forbidden outside the FFI and OS adapter crates (workspace lints) | The testkit item |
| A bless never passes | `HDR-8` | The testkit item |
| No dependency, no closure change | `cargo tree --locked -p grdr-fastpath-ffi -e normal,build` (#418 AC-6); `cargo deny check`; the testkit's empty dependency list and its `test-support` entry in `architecture.toml` | #418; the scaffold part of the testkit item |
| Seeded failures stay caught | Unit tests in the testkit: one seeded input per `HDR` id over the pure `check` | The testkit item |

## Surfaces changed
- `grdr_fastpath.h` (C ABI, experimental): generated form. New constants `GRDR_FP_ABI_MAJOR` and `GRDR_FP_ABI_MINOR`, and names for the values section 2 already fixes. No function, field or status code changes.
- `grdr.h` and `grdr_macos.h`: the same generated form, when their items land.
- `grdr-cabi-testkit` (layer 1, public, `experimental`): new.
- New same-layer dev edges `grdr-fastpath-ffi` and `grdr-ffi` to `grdr-cabi-testkit`.
- As proposals: `c-abi.md` section 2.4; rows in `architecture.toml`, `surfaces.toml`, `owners.toml` and `.claude/risk-tiers.toml`.
- No spine text, protobuf package, licence policy or `Cargo.lock` package changes.

## Alternatives
Each alternative below was checked against what shipping projects do. rustls-ffi installs cbindgen as a tool pinned to 0.29.4 in its `ensure-header-updated` job, regenerates the header and runs `git diff --exit-code`. Its workflow says the pin exists because point releases can change the output (https://raw.githubusercontent.com/rustls/rustls-ffi/main/.github/workflows/test.yaml, read 2026-11-20). safer_ffi generates headers from a registry inside the library, behind a `headers` feature and a dedicated binary (https://raw.githubusercontent.com/getditto/safer_ffi/master/README.md, read 2026-11-20). `offset_of!` has been stable since Rust 1.77 (https://doc.rust-lang.org/core/mem/macro.offset_of.html, read 2026-11-20).
- **(a) A hand-written header, and a test that parses it and the crate's `extern "C"` items.** It needs two parsers: a C subset, and Rust source, which takes `syn` (a new dependency) or a hand-written one. A source parser does not see through `pub use`, type aliases or types defined in `grdr-fastpath` (#405), and it checks no layout. It also departs from "generated" in design/26 and design/03. Rejected.
- **(b1) cbindgen as a dev-dependency.** The licence class forbids MPL-2.0 in layers 0 to 2 and `grdr-ffi`, so it needs a licence-policy RFC and `cargo deny` exceptions. It also adds cbindgen's ten required direct dependencies, among them `syn`, `serde`, `toml` and `tempfile`, to the dev graph of a trust-core crate. Rejected.
- **(b2) cbindgen in `build.rs`.** It breaks the fast-path closure (#418 AC-6). Rejected.
- **(b3) cbindgen as a pinned tool in `build-tools.toml`, run by a CI step, as rustls-ffi does.** The licence and the closure both allow it. It loses for four reasons:
  - The check leaves `cargo test --workspace`, so a session's gates cannot see it, and each session would have to install cbindgen to regenerate the header.
  - cbindgen reads source, so the types in `grdr-fastpath` need `parse_deps`.
  - It checks neither rustc's layout nor `c-abi.md`, which `c-abi.md` itself asks for.
  - Each cbindgen bump can churn three headers, two of them on trust-core paths.

  This is the fallback if the testkit proves too costly to keep.
- **(b4) An `xtask` tool.** ADR-0029 removed `xtask`. Rejected.
- **(d) The header as the source, with Rust generated from it by bindgen (BSD-3-Clause).** It needs libclang on every host and a build step or a second committed artefact, and the Rust side would become generated code inside the trust core. Rejected.
- **(e) A registry in the library, as safer_ffi has.** It ships the descriptor in the artefact or needs a Cargo feature, which layers 0 to 2 do not have (design/03 section 8). Rejected.
- **(f) A proc-macro attribute on each export.** It needs `syn` and `quote` as dependencies of the FFI crate. Rejected.
- **(g) A hand-written header with only C static asserts.** A C compiler would have to be reachable on all three hosts; on Windows that needs `vcvars` or the `cc` crate. It checks layout but not signatures, because linking checks names only. Kept as the addition of section 9, not the mechanism.
- **(h) A copy of the renderer in each crate's test.** Three copies, and the shared status block could drift between `grdr.h` and `grdr_fastpath.h`. Rejected for one testkit.

## Drawbacks
- The descriptor is a third statement of each signature beside the Rust and the header. The compiler holds it to the Rust, but each change edits it.
- `HDR-3` ties the test to the form of `c-abi.md`: a heading that names the header in backticks, and `c` code blocks. A reshuffle of that document fails the test until the heading or the block is restored. That fails closed, and the cost lands on the chief architect's protected file.
- The export scanner is textual. It depends on rustfmt's form and refuses a macro-generated export.
- One more crate, two dev edges, and a `test-support` entry.
- The drift test reads `spec/` outside its crate. A published crate's package would carry a test that cannot run, so a crate that is published lists `tests/header_drift.rs` in `package.exclude`.
- The status block carries each code's `meaning` in English as a comment. That is developer text in a source file, not a product string, but a reword of a `meaning` regenerates both headers.
