## Summary
RFC 0005 was accepted in #1913 with four record-level gaps recorded in round 3 evaluator minors and deferred to #1940 before `#427`, `#1930` and `#1917` are readied:

1. **Error-code routing classes (R1):** under [RFC 0007](./0007-grdr-model-and-grdr-schema-slice-0-surface.md) sections 3 and 4, `Arg(Path)` and `Arg(Destination)` take `class = "input"` (replacing `retryable`), `State` stays `retryable`, `repeat` and `[retry.fastpath-reload]` giving up both take `retryable` (because `2b` follows both), `1d` bound elapsing and `2b` cycle ending take `fatal`, and `fatal` on a daemon state code means automatic recovery stops and external exits named in `fix` apply (never that the state has no exit). Re-adoption refusal codes take `policy` or `retryable` as specified in R1.
2. **Constraint `1d` endpoints and named exit (R2):** before first adoption and once the `1d` bound elapses with no tables adopted, `decide` and agent hooks (`1c`) stay down (`provider` does not serve action decisions), while `local` ([docs/design/11](../docs/design/11-endpoint-engineering.md) section 1) starts and stays up for status/health reads and standalone `2a`, and `grdr-uplink` runs on enrolled devices. Exits from `No tables since start` are explicitly named, including supplying and activating a valid bundle at or above the D-37 generation floor on a solo device whose persisted `1b` bundle fails a check.
3. **Constraint `2b` scope (R3):** yes, `2b`'s slow, bounded background re-adoption cycle follows `[retry.fastpath-reload]` giving up identically to a repeat `Changed`, replacing `Floor-missing, reloading ended` with explicit sub-states for cooldown, active background attempts, and cycle ended.
4. **Constraint `2a` authorisation, SR-04, state precondition, rate bounds and cooldown response (R4):** replaces the erroneous D-70 "operator" wording with the D-55 `Responder` (`Re`) or active delegated `Provider response technician` (`TR`) role ([docs/design/21](../docs/design/21-tenancy-keys-and-access.md) section 7) acting via a signed server `CommandEnvelope` ([docs/design/22](../docs/design/22-transport-fleet-and-updates.md) section 5), closing the `local` `2a` route on enrolled devices; reconciles SR-04 ([docs/design/02](../docs/design/02-threat-model.md) section 3.8); restricts `2a` acceptance to no-tables and floor-missing states (refusing `Serving`); counts only accepted requests against a `[bound.*]` pair of `BoundUnit::Count` and `BoundUnit::Ms` in `limits.toml`; aggregates refusal audits per peer and window; and gives requests arriving during `2b` cooldown a non-silent refusal code rather than a drop.

## Motivation
Round 3 reviews on #1913 identified four ambiguities in RFC 0005's Decision constraints that cannot wait for downstream implementation issues:

- **Classes become immutable once registered (`eval-architecture` M1, M3; `eval-acceptance` M4):** under RFC 0007 section 4, once `#427` registers `schema/codes/fastpath.toml` on `main`, an entry's `class` and `connect` keys cannot be altered without retiring the code number (`#278`). Assigning `retryable` to `Arg(Path)` / `Arg(Destination)` or diverging classes between `repeat` and `[retry.fastpath-reload]` giving up would freeze contradictions on `main`.
- **Cold-start reachability and broken solo bundles (`eval-architecture` M2; `eval-acceptance` M1; `eval-security` N3):** RFC 0005 constraint `1d` stated `"It enables nothing, neither hooks nor endpoints"`, leaving ambiguous whether `local` (needed to read `Degraded` status and run standalone `2a`) and `grdr-uplink` (needed for server activation) run at or past `1d`, and naming no exit when a solo device's persisted `1b` bundle fails a deterministic check or the D-37 generation floor.
- **Give-up vs repeat in `2b` (`eval-architecture` M3):** R2.19's table routed both `repeat Changed` and `[retry.fastpath-reload]` giving up into the same `Floor-missing, reloading ended` state while `2b` named only a repeat and `4d` split their `class` values.
- **Role confusion, SR-04 mismatch and DoS edges in `2a` (`eval-architecture` M4; `eval-security` N4; `eval-diff` M3):** RFC 0005 `2a` called a tenant device administrator an "operator" (a D-70 platform operator who has no command route to tenant devices), did not close the `local` `2a` route on enrolled devices, left SR-04's proposal rule unexplained for standalone `2a`, allowed `2a` while `Serving` (enabling probation-reset loops via R2.19), did not protect the rate budget from refused requests, used `"rate"` which is not a `BoundUnit` of RFC 0007 section 5, and left undefined what a request inside `2b` cooldown receives.

## Design

### R1. Error-code `class` values and `fatal` semantics for state codes (Item 1)
This rule amends RFC 0005 Decision constraint `4d` under RFC 0007 sections 3 and 4 (`ErrorClass`: `input`, `policy`, `retryable`, `fatal`, `internal`):

- **R1.1. `Arg(Path)` and `Arg(Destination)` take `class = "input"` (with `ConnectCode::InvalidArgument`).** In R2.17, the daemon handles `Arg(Path)` or `Arg(Destination)` by calling `eval` again with a different input (`Resolution::Unresolved` per R2.3b). Repeating the same `Resolved` input unchanged deterministically fails R2.3a or [spec/host-contract/tables.md](../spec/host-contract/tables.md) section 3.3 identically (`"the caller's request, data or configuration is wrong, and the same input fails the same way"`, RFC 0007 section 3). Calling them `retryable` would imply a retry policy over unchanged input. Their `fix` token states that the host caller inspects or resolves the invalid path/destination form (`eval-architecture` M1 on #1913).
- **R1.2. `State` keeps `class = "retryable"` (with `ConnectCode::Unavailable` or `FailedPrecondition` as `#427` picks).** Unlike `Arg(Path)` and `Arg(Destination)`, `State` reflects a transient bundle-tag lag while engine projections and adopted floor tables align (R2.17, MN14), so the same call may succeed once projections converge.
- **R1.3. Remaining `grdr_fastpath::Error` leaves keep RFC 0005 `4d`'s classes:**
  - `Arg(Arena)`, `Arg(ActionClass)`, `Arg(PrincipalKind)`, `Arg(Reason)`, `Abi`, `Bundle(Rule(n))` and `Bundle(EvalCap)` take **`internal`**: `grdr-daemon` loads only blobs produced by its own compile instance (R3.7), so any of these indicates a product defect.
  - `Changed` takes **`fatal`**: that retired handle never answers again (R2.12a); reloading opens a new handle.
- **R1.4. Daemon floor-state codes (`R4.3`, `1d`, `2b`) take these classes and `#427` registers all five beside `#1925`'s tokens:**
  - Entering `Floor-missing` on initial `Changed`: **`retryable`**, because `[retry.fastpath-reload]` starts at once (`R2.18`).
  - Repeat `Changed` in `PreBackground2b` probation ending immediate reload (`R2.19`, `2b`): **`retryable`**, because `2b`'s slow, bounded background re-adoption cycle follows after cooldown (R3).
  - Immediate reload policy (`[retry.fastpath-reload]`) giving up: **`retryable`**, because under R3 it takes the exact same `2b` cooldown and bounded background re-adoption transition as a `PreBackground2b` repeat `Changed` (`eval-architecture` M3).
  - Background re-adoption cycle (`2b`) ending (either `[retry.fastpath-reload-background]` gives up or `Changed` occurs in `PostRecovery2b` probation): **`fatal`**, a fifth `FASTPATH` state code registered by `#427` (with tokens in `#1925`), because automatic recovery has ended and external action is required.
  - Cold-start `1d` bound elapsing with no tables adopted: **`fatal`**, because no automatic background reload (`2b`) runs from `No tables since start`; recovery needs one of R2's named external exits.
- **R1.5. Meaning of `class = "fatal"` on daemon state codes (`#427`, `#278`, `#1925`):** For a daemon state code, `fatal` means **automatic reload does not run (or has stopped) and repeating the failed reload unchanged does not help**. It **never** means the state is terminal or has no exit ([docs/design/03](../docs/design/03-system-architecture-and-modularity.md) section 10, `P9`). Each `fatal` state code's `fix` token names the external exits available in that state: bundle activation or `DesiredState` delivery, a valid `2a` re-adoption request (outside cooldown), replacing/repairing a failing local persisted bundle (R2), or host restart.
- **R1.6. `2a` re-adoption request refusal codes (registered in area `FASTPATH` by `#1930` / `#427`, tokens by `#1925` / `#1930`):**
  - Request inside `2b` cooldown: **`retryable`**, Connect `unavailable` (repeating after the cooldown ends succeeds; non-silent refusal, `eval-diff` M3).
  - Rate bound `(fastpath.readopt-max, fastpath.readopt-window)` exceeded: **`policy`**, Connect `resource_exhausted` (RFC 0007 section 3: quota/bound reached by correct use).
  - Floor is currently `Serving` (`Serving, no episode` or `Serving, on probation`): **`policy`**, Connect `failed_precondition`.
  - Enrolled `local` route closed, wrong peer uid on standalone `local`, or caller inside agent session lineage (`SR-04`): **`policy`**, Connect `permission_denied` (reusing `#1930`'s or the daemon's shared SR-04 refusal code where already registered, or dedicated `FASTPATH` entry).
- **R1.7.** Constraint `4d`'s closing sentence `"no FASTPATH code is input or policy"` becomes `"Arg(Path) and Arg(Destination) are input; re-adoption request refusals are policy or retryable as RFC 0011 R1.6 specifies; no other grdr_fastpath::Error leaf is input or policy."`

| Code subject | Source | Class | Connect code | Reason / next step |
|---|---|---|---|---|

| Other `ArgFault`, `Abi`, `Bundle(*)` | R1.3 (`#427`) | `internal` | `internal` | Product or compiler defect; support bundle per RFC 0007 |

| Floor-missing entered on `Changed` | R1.4 (`#427`) | `retryable` | `unavailable` | `[retry.fastpath-reload]` runs immediately |
| Repeat `Changed` in `PreBackground2b` probation ending immediate reload | R1.4 (`#427`) | `retryable` | `unavailable` | Enters `2b` cooldown then `[retry.fastpath-reload-background]` |

| `2a` refused: enrolled `local` closed, wrong peer or SR-04 agent lineage | R1.6 (`#1930`) | `policy` | `permission_denied` | Enrolled devices require server `CommandEnvelope` from `Re`/`TR`; agent callers denied |

### R2. Constraint `1d`: endpoints at the bound and named exits from `No tables since start` (Item 2)
This rule amends RFC 0005 Decision constraint `1d` and aligns [docs/design/11](../docs/design/11-endpoint-engineering.md) section 1 and `#149` / `#1538` / `#427`:

- **R2.1. Endpoints that stay down vs up before first adoption and at the `1d` bound.** Constraint `1d`'s sentence `"It enables nothing, neither hooks nor endpoints, and changes no answer"` becomes:
  - **Stay down (not serving until first adoption succeeds):** `decide` ([docs/design/11](../docs/design/11-endpoint-engineering.md) section 1) stays down / closed, `provider` serves no action decisions, and agent hooks (`1c`) remain disabled in harnesses. Any hook request emitted by a harness with an already-registered hook is answered solely by the shim's fail-safe table (`D-14`, [docs/design/07](../docs/design/07-control-points-and-hook-broker.md) section 10), never by `grdr-daemon`.
  - **Start and stay up:** `local` ([docs/design/11](../docs/design/11-endpoint-engineering.md) section 1, start order phase 5) starts and stays up before first adoption and past the `1d` bound so users/operators can query `Status`, `Explain`, `Query` and `Subscribe` (seeing `Degraded` and the `1d` `FASTPATH` code with `D-44` rule/reason/route tokens) and, **on standalone devices only**, invoke `2a`. On **enrolled devices**, `grdr-uplink` ([docs/design/11](../docs/design/11-endpoint-engineering.md) section 1, start order phase 8) starts and stays running regardless of the `1d` bound so signed server activations (`DesiredState`) and `2a` `CommandEnvelope` commands ([docs/design/22](../docs/design/22-transport-fleet-and-updates.md) section 5) can arrive at any time.
  - **Reconciliation with `1a` and `1c`:** `No tables since start` (both before and after the `1d` bound elapses) retains `1a`'s floor behaviour inside `#427`'s `NoTablesSinceStart` variant: any non-hook floor lookup directed to the daemon denies actions of processes inside session containers, never denies a person's own shell or shared-host actions outside a container, and attaches `degraded_reason = floor-missing`. When `1d` elapses, only the `Degraded` flag and the `1d` `FASTPATH` state code are added; answers do not change and `decide` and hooks remain down.
- **R2.2. Named exits from `No tables since start` (both before and after `1d` elapses):**
  1. **Policy bundle activation or recompile on new device facts (`R2.19`, `#1538`):** arrival of a valid bundle activation (`DesiredState` / `PackageOffer` over `grdr-uplink` on an enrolled device, or a local verified bundle activation) or a `#1538` recompile on changed device facts whose compiled blob passes `load`, host ceilings (`R5.3`) and binding checks transitions `No tables since start -> Serving, no episode`, enables `decide`, `provider` and agent hooks, and clears the `1d` degraded state.
  2. **Authenticated `2a` re-adoption request (R4, `#1930`):** when the device's verified policy source can now compile and load (for example after an earlier transient helper or startup fault clears), an accepted `2a` request (`local` on standalone; server `CommandEnvelope` from `Re`/`TR` on enrolled) runs an immediate activation attempt from a freshly verified source.
  3. **Solo device whose persisted bundle fails a check (`1b`, `eval-security` N3):** if `grdr-daemon` entered `No tables since start` because `1b`'s startup verification of the persisted bundle failed (such as failing a TV rule, exceeding host ceilings, failing compile, or carrying a generation below the D-37 persisted generation floor), repeating bare `2a` (which names no bundle, path or table) or restarting the daemon reads the same persisted bundle and fails identically (`Refused { code }`). The named exit in this state is **replacing or repairing the local policy source with a valid bundle at or above the D-37 generation floor and activating it** (applying a valid newer local bundle through `#1538`'s policy activation flow or reinstalling/repairing the signed distribution bundle package, then activating or running `2a` / restarting `grdr-daemon`). **The daemon must never delete, zero or lower the D-37 generation floor automatically** to accept a lower-generation bundle (`D-37`). The `1d` code's `fix` token and runbook (`#1925`, `#427`) must name both the `2a` command (when the local source is valid) and the bundle replacement/repair step (when persisted checks or the D-37 generation floor failed).
  4. **Daemon or host restart (`R2.19`):** re-enters `No tables since start` with a fresh `1d` window, reading any repaired persisted bundle via `1b` or awaiting server activation.

### R3. Constraint `2b`: background re-adoption follows `[retry.fastpath-reload]` giving up (Item 3)
This rule amends RFC 0005 Decision constraint `2b` and replaces R2.19's state-transition table (`#427`, `#1917`):

- **R3.1. `2b` follows both a `PreBackground2b` repeat `Changed` and `[retry.fastpath-reload]` giving up, with explicit probation stages (`S4`).** R2.19 previously mapped both events to `Floor-missing, reloading ended`, while constraint `2b` mentioned only a repeat `Changed`. Unifying both on entry to `2b` ensures transient compile or helper hangs that exhaust `[retry.fastpath-reload]` still recover automatically after cooldown. To avoid any implicit provenance on `Serving, on probation` (`docs/design/03` section 10, `S4`), `Serving, on probation` carries an explicit typed `ProbationStage` field (`PreBackground2b` or `PostRecovery2b`):
  - **`PreBackground2b`** applies only to handles adopted out of `Floor-missing, reload pending` (via `[retry.fastpath-reload]`, activation, `#1538` recompile on new facts, or accepted `2a`), and further `Activation` or `#1538` adoptions during `PreBackground2b` remain in `PreBackground2b`.
  - **`PostRecovery2b`** applies once the open episode has entered `2b` (`Floor-missing, background cooldown`, `Floor-missing, background pending`, or `Floor-missing, auto-recovery ended`): every adoption out of those three states (whether by `[retry.fastpath-reload-background]`, `Activation`, `#1538` recompile on new device facts, or accepted `2a`), and any subsequent `Activation` or `#1538` adoption while already in `PostRecovery2b`, enters `Serving, on probation(PostRecovery2b)`. From `PostRecovery2b`, only passing `fastpath.reload-settle` closes the episode and refills `[retry.fastpath-reload]` and `[retry.fastpath-reload-background]`; a `Changed` before settle transitions directly to `Floor-missing, auto-recovery ended` (`fatal`), never re-arming `2b` cooldown or automatic retries.
- **R3.2. Complete explicit state-transition table (replacing R2.19's table):**

Failed or refused: unchanged (`No tables since start`; accepted `2a` consumes 1 rate unit) |

| `Floor-missing, background pending` | Accepted `2a` (within `(Count, Ms)` rate bound) | Tried at once from freshly verified source (consumes 1 rate unit): adopted -> `Serving, on probation(PostRecovery2b)` and cancel remaining `[retry.fastpath-reload-background]` attempts; failed/refused -> unchanged (`Floor-missing, background pending`) |
| `Floor-missing, auto-recovery ended` | Activation or `#1538` recompile on new device facts | Tried once immediately against freshly verified source: adopted -> `Serving, on probation(PostRecovery2b)`; failed/refused -> unchanged (`Floor-missing, auto-recovery ended`; no further auto-retries) |
| `Floor-missing, auto-recovery ended` | Accepted `2a` (within `(Count, Ms)` rate bound) | Tried once immediately against freshly verified source (consumes 1 rate unit): adopted -> `Serving, on probation(PostRecovery2b)`; failed/refused -> unchanged (`Floor-missing, auto-recovery ended`; no further auto-retries) |

| `Any` | Daemon or host restart (`R2.19`) | `No tables since start`, until `#1538` adopts tables (`1b` startup checks run) |

- **R3.3.** Every `2b` background attempt reads from a freshly verified source (never the retired/changed copy, never last-known-good tables that returned `Changed`) and raises a tamper/recovery finding (`R2.19`, `4d`, `6d`). In all four `Floor-missing` variants, `loss_closed_classes` stays a field on the variant (`eval-architecture` M2 on #1913) and actions fall back to R2.17 identically. Similarly, both `Serving, no episode` and `Serving, on probation(ProbationStage)` hold `loss_closed_classes` as variant fields.

### R4. Constraint `2a`: D-55 role, route, SR-04, rate accounting, floor-missing precondition, `BoundUnit` and cooldown response (Item 4)
This rule replaces the role, route, accounting and boundary rules of RFC 0005 Decision constraint `2a` (`#1930`, `#1917`, `#427`, `#1921`, `#1916`):

- **R4.1. Authorised D-55 role and route (removing "operator"):**
  - RFC 0005 `2a` used `"operator"` for a tenant device administrator; under Spine section 3 and `D-70`, *Operator* (`Op`) is the platform operator, who holds server metadata rights only under a `SupportGrant` and holds no `response.execute` authority over tenant devices ([docs/design/21](../docs/design/21-tenancy-keys-and-access.md) section 7). The word `"operator"` is removed from constraint `2a`.
  - **Enrolled device (Platform, self-hosted or hosted):**
    - **Principal:** a **D-55 organisation `Responder` (`Re`)**, or an active delegated **`Provider response technician` (`TR`)** holding `response.execute` ([docs/design/21](../docs/design/21-tenancy-keys-and-access.md) section 7). Neither `Op` nor policy-authoring roles (`Au`, `Ap`, `TP`) may send `2a`, preserving D-55 policy-vs-response separation.
    - **Route:** a **server-originated device-scope response command delivered over [docs/design/22](../docs/design/22-transport-fleet-and-updates.md) section 5 (`CommandEnvelope`)**, authorised on the server (`Grdr::Console` / `grdr.api`, Cedar `response.execute`), audited (`audit.admin`), signed with the deployment fleet key (per SR-30 device-scope non-destructive rules, trusted-time `not_after`, `(server_epoch, counter)` monotonic anti-replay, `target` device identity) and delivered to `grdr-uplink` via `FleetService` (`CheckIn`, `Wait`, `Subscribe` `COMMAND` nudge or `PendingCommands`).
    - **Enrolled `local` route closed:** while a device is enrolled, `grdr-daemon`'s `local` endpoint MUST **refuse** all `2a` re-adoption requests (`class = "policy"`, Connect `permission_denied`, CLI exit `4`). A local user on an enrolled device cannot trigger local re-adoption or bypass fleet authorisation and rate accounting.
  - **Standalone device (not enrolled):**
    - **Principal and route:** the **local human device owner** (outside any agent session lineage), invoking one unelevated CLI command (`#1930`, registered in `#1883`) over `grdr-daemon`'s `local` endpoint ([docs/design/11](../docs/design/11-endpoint-engineering.md) section 1).
    - **Authentication (`SR-01`):** `grdr-daemon` verifies peer OS identity via kernel peer handle, matching the local profile's device owner account and refusing any second unrelated uid or remote peer.
- **R4.2. SR-04 proposals clause and in-session refusal:**
  - **First clause (`"Mutating calls from any local surface or our MCP server are proposals"`):** on a standalone device, a `2a` re-adoption request is **not** a D-31 widening proposal, because it changes no policy, Mode, capture level, grant or exception, widens nothing, and names no bundle, path or table; it only requests verification and adoption of the daemon's own verified source (`R2.18`). Routing standalone `2a` through `grdr-approve` step-up (`Propose`) would deadlock local recovery whenever supervision or floor tables are degraded and would contradict `"one unelevated command"`. Accordingly, `#1916` and `#1930` record `2a` in [docs/design/11](../docs/design/11-endpoint-engineering.md) section 1 (`local` endpoint table) as a standalone-only, non-widening operational control trigger (`ReAdopt`), keeping `"Widening mutations: Proposals only (D-31)"` intact.
  - **Second clause (`"calls from inside an agent session are refused"`):** enforced unconditionally. Any `2a` call originating inside a session container or attributed to an agent session lineage is **refused** (`class = "policy"`, Connect `permission_denied`, CLI exit `4`, audited without bundle content). Our MCP server ([docs/design/23](../docs/design/23-api-policy-as-code-and-mcp-server.md) section 10, `D-38`) exposes no operational/response actions and offers no `2a` route.
- **R4.3. Accepted only while floor is missing (`eval-security` N4d):**
  - `2a` re-adoption requests are eligible **only when the floor has no serving tables and no active `2b` cooldown**: `No tables since start` (before and after `1d`), `Floor-missing, reload pending`, `Floor-missing, background pending`, and `Floor-missing, auto-recovery ended`.
  - In **`Floor-missing, background cooldown`**, `2a` requests are **refused** with the `2b`-cooldown code (`R1.6`, `retryable`, Connect `unavailable`, CLI exit `4`), leaving the cooldown timer and `(Count, Ms)` rate budget unchanged.
  - While the floor is **`Serving, no episode`** or **`Serving, on probation(ProbationStage)`**, `grdr-daemon` MUST **refuse** `2a` requests (`class = "policy"`, Connect `failed_precondition`, CLI exit `4`), leaving the serving handle, open episode, `ProbationStage` and probation timer (`fastpath.reload-settle`) untouched. Accepting `2a` during probation would let requests keep resetting probation under R2.19 so the reload policy never refills.
- **R4.4. Rate bound `BoundUnit` and scope across states (`#1917` R5a, RFC 0007 sections 5 and 6):**
  - RFC 0007 section 5 provides `BoundUnit::{Bytes, Count, Ms, Permille}` and has no `rate` unit.
  - `#1917` R5a defines the `2a` rate bound as **two `[bound.*]` rows** under `fastpath.*`, both `scope = "fixed"`, `effect = "none"` and `owner = "design/26"`:
    1. **`[bound.fastpath.readopt-max]`**, unit **`count`** (`BoundUnit::Count`): maximum accepted `2a` requests in one window;
    2. **`[bound.fastpath.readopt-window]`**, unit **`ms`** (`BoundUnit::Ms`): window length over which accepted requests are counted.
  - Neither row name uses a reserved unit word or reserved segment under RFC 0007 section 6. `docs/design/26` sets their values and `[min, max]` ranges in `#1917`.
  - This `(Count, Ms)` rate bound covers accepted `2a` requests in **every** eligible state (`No tables since start` and all `Floor-missing` states), because `2b` cooldown exists only while in `Floor-missing, background cooldown` (`eval-diff` M3). `2b`'s cooldown itself is expressed in **`ms`** under RFC 0007 section 6 (`#1917` R5).
- **R4.5. Order of checks, non-spending refusals, cooldown response and anti-amplification audit:**
  1. **Evaluation order:** (1) route and peer/envelope authentication (`enrolled local closed`, `SR-01` kernel uid match, `SR-04` non-session lineage, or `CommandEnvelope` signature/target/`not_after`/replay verification) -> (2) floor state eligibility (refuse `Serving, no episode` and `Serving, on probation(ProbationStage)`) -> (3) cooldown check (refuse `Floor-missing, background cooldown`) -> (4) `(fastpath.readopt-max, fastpath.readopt-window)` rate check (refuse if exhausted).
  2. **Only accepted requests spend the rate budget:** requests refused at steps (1), (2), (3) or (4) **never** decrement or consume capacity from `(fastpath.readopt-max, fastpath.readopt-window)`, and leave floor state, probation timers and cooldown timers untouched. Only a request that passes all four checks and triggers an adoption attempt spends one count in the current window.
  3. **What a request inside `2b` cooldown receives (`eval-diff` M3):** **never a silent drop**, and never an unbounded deferred queue. It receives an explicit refusal carrying the registered cooldown `FASTPATH` code (`R1.6`, `class = "retryable"`, Connect `unavailable`, CLI exit `4` under `design/23` section 11's refused exit code), spends no rate budget, and leaves the cooldown timer unaltered.
  4. **Anti-amplification audit:** accepted `2a` requests are audited individually without bundle content (peer uid or `CommandEnvelope` principal role, device id, floor state, outcome). Refused `2a` requests are audited without bundle content **aggregated per peer and rate window** (first refusal plus periodic or window-end summary count) so a caller looping invalid or rate-limited requests cannot amplify audit log or spool writes (`eval-security` N4c).

**Failure modes.**

| Failure | Declared outcome | Visible as |
|---|---|---|
| `eval` returns `Arg(Path)` or `Arg(Destination)` | R2.17 retries once with `Unresolved` on the same handle; coded `input` | Verdict from worst-case/matching rows and `GRDR-FASTPATH-*` (`input`) |

Data classes: audit records for accepted `2a` requests and per-peer aggregated refusals contain `structural` and `identifier` fields only (peer uid or `CommandEnvelope` role/issuer id, device id, floor state, refusal code, aggregate count), all `LogSafe` with no bundle or path bytes (`WI-0014`). ## Alternatives
- **Edit `rfcs/0005-fastpath-rust-surface.md` directly in place.** Prohibited by [RFC 0001](./0001-adopt-the-spine.md) ("RFC states" and "Review binds the decision") and contrary to the `rfcs/0010` amendment precedent. Rejected.
- **Keep `Arg(Path)` and `Arg(Destination)` as `retryable`.** R2.17 sends a modified call (`Resolution::Unresolved`), while the same `Resolved` input always fails identically. Misclassifies under RFC 0007 section 3. Rejected.
- **Exclude `[retry.fastpath-reload]` give-up from `2b`.** Splits `Floor-missing, reloading ended` into two hidden sub-states (`S4`) and strands transient compile/helper hangs without recovery while recovering repeated tamper faults. Rejected.
- **Exclude `[retry.fastpath-reload]` give-up from `retryable` while routing it to `2b`.** Gives identical transitions conflicting `class` values (`repeat` = `retryable` vs `gave up` = `fatal`, `eval-architecture` M3). Rejected; instead both take `retryable`, and `2b` cycle exhaustion receives an explicit `fatal` state code beside `1d`.
- **Name D-70 `Op` or allow `local` `2a` on enrolled devices.** `Op` has no tenant device command path (`D-70`, [docs/design/21](../docs/design/21-tenancy-keys-and-access.md)), and keeping `local` open on enrolled devices lets a local user bypass fleet authorisation and rate controls. Rejected.
- **Route standalone `2a` as a D-31 widening proposal through `grdr-approve`.** `2a` changes no policy, Mode or grant, and step-up approval can be unavailable when supervision/floor tables are degraded, violating `"one unelevated command"`. Rejected; kept non-widening on `local` while keeping SR-04's agent-lineage refusal strict.
- **Accept `2a` while `Serving` or charge refused requests to the rate row.** Enables probation-reset loops (keeping reload budgets un-refilled) and allows unprivileged callers to exhaust the owner's recovery quota. Rejected.
- **Add `BoundUnit::Rate` to RFC 0007 section 5.** Adds unnecessary schema/generator surface when RFC 0007's `Count` and `Ms` `[bound.*]` pair represents a bounded rate window natively. Rejected.
- **Reset or lower the D-37 generation floor on a solo device whose persisted bundle fails `1b`.** Weakens D-37 rollback protection. Rejected in favour of supplying/repairing a valid bundle at or above the floor.

## Drawbacks
- Adds one `fatal` `FASTPATH` state code (`2b` auto-recovery ended) and explicit `2a` refusal codes (`cooldown`, `rate limit`, `already serving`, `enrolled local closed`) to `#427` / `#1930` / `#1925`.
- Uses two fixed `[bound.*]` rows (`fastpath.readopt-max` in `count`, `fastpath.readopt-window` in `ms`) instead of a single conceptual rate row in `limits.toml`.
- On an enrolled device without server connectivity and past `1d`, a local user cannot invoke `2a` locally and must restore uplink connectivity or wait for a server `DesiredState` / `CommandEnvelope` from `Re`/`TR`.
- Solo recovery from a broken or down-level persisted bundle requires replacing or repairing the local bundle at or above the D-37 floor rather than bare `2a`.
- [rfcs/0005-fastpath-rust-surface.md](./0005-fastpath-rust-surface.md) remains unedited on `main`; readers discover these amendments via `#1940`, this RFC and its future ADR.
